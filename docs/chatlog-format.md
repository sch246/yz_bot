# chatlog 记录格式（协议）

`chatlog/` 是聊天历史的唯一写入权威，也是启动时重建近期消息、范围查询和 `.search` 的唯一数据来源。因此本篇是**协议而不是描述**：下面每一条形状都有解析侧依赖，改动其中任何一条都是破坏性变更，必须同时改解析侧并考虑既有文件。

写入侧全部在 `mods/chatlog.py`，解析侧是同一文件末尾的 `parse_log` 与 `_recognise_notice`。当前实现见[运行架构](architecture.md#唯一消息路由)，设计取舍见[统一消息模型](working/proposals/message-model.md)。

## 目录与文件

```
chatlog/group/{群号}/{YYYY-MM}/{DD}.log
chatlog/private/{QQ号}/{YYYY-MM}/{DD}.log
chatlog/bot/{YYYY-MM}/{DD}.log
```

窗口和日期**只由路径承载**，不在行内重复。`bot/` 是没有窗口的事件的堆放处：好友请求、`friend_add`、以及写入失败时的兜底 `repr`。

时间戳按**本地时区**渲染，解析时假定同一时区。设备换时区会平移历史时间——这是已知的推导假设，不用一个字段消灭它。

## 两种行

**记录头顶格，正文缩进 4 个空格。** 这条规则承担了全部的边界识别：正文里伪造的记录头也是缩进的，因此不会被误读成新记录。

- 一条真正的空行（`""`）表示空正文。
- 正文内部的空行写作 `"    "`（4 个空格）。
- **正文末尾的换行与空白一律清除。** 这是有意的：QQ 客户端本身也清，聊天消息末尾的空白几乎不存在有价值的情况。写入前 `rstrip()`，解析后 `rstrip()`，两者因此严格互逆。

### 消息形状

```
【{头衔}】{名字}({QQ号}) {HH:MM:SS} | {消息号}
    {正文}
{名字}({QQ号}) {HH:MM:SS} | {消息号}
    {正文}
```

第一行是群聊，第二行是私聊。除了 `【头衔】`，两者同形。

- **正文存 OneBot 原始串**，不做 unescape。unescape 会抹掉真实 CQ 码和用户字面输入 `[CQ:...]` 的区别，那是不可逆的。显示侧由 `chatlog.display()` 还原，终端回显和 `.search` 都经过它。
- `【头衔】` 和名字是**写入当时**的显示值，只作推导值填进 `sender`，**不能反查身份**。
- 名字取 QQ 侧的真实身份：群内是群名片（无名片则账号昵称），私聊是账号昵称。**不使用 `.setname` 的自定义名**——那是显示偏好，不该改写「发生过什么」的记录。模型看到的名字是另一回事：`mods/chat.py` 用 `identity.getname`，自定义名在那里生效，消息和戳一戳都一样。两条路刻意分开。

### 通知形状

```
: {文本} {HH:MM:SS}
```

一行，没有正文块。`{文本}` 的全部句式见下节。

## 解析规则

**从右往左。** 显示名可由用户自设，一个精心构造的名字能在头部里造出假的分隔符，因此：先取最右的 ` | `，再取它左边最右的 `(数字) HH:MM:SS`，剩下的整体是名字；`【头衔】名字` 按最右的 `】` 切分。同理，通知里的 id 一律从行尾锚定。

**版本自判。** 私聊消息行是否带 `({QQ号})` 就是 v0/v1 的分界；群聊行两版同形，因此靠 `storage` 里 `chatlog/format` 的 `v1_since` 时间戳判定，没有提示时按 v0 处理（少认保真度是安全方向）。

**不匹配就不猜。** 认不出的行原样留作不透明文本。措辞变化让一条记录**消失**，不会让它**出错**。

## 通知句式

每个人名一律渲染成 `{名字}({QQ号})`。带 ✅ 的目前已反解成事件字段，其余目前只作不透明文本——但形状同样是协议的一部分，任何一条将来出现消费者时都可以反解，**前提是先改这张表**。

| 事件 | 句式 |
|---|---|
| 戳一戳 ✅ | `{甲}({id})戳了戳{乙}({id})` |
| 群内撤回（自己） ✅ | `{甲}({id})撤回了一条消息({消息号})` |
| 群内撤回（他人） ✅ | `{操作者}({id})撤回了{甲}({id})的一条消息({消息号})` |
| 私聊撤回 ✅ | `{甲}({id})撤回了一条消息({消息号})` |
| 设为管理员 | `{甲}({id})被设为了管理员` |
| 移除管理员 | `{甲}({id})被移除了管理员` |
| 主动退群 | `{甲}({id})离开了群` |
| 被踢出群 | `{甲}({id})被{操作者}({id})踢出了群` |
| 加入群 | `{操作者}({id}){同意\|邀请}{甲}({id})加入了群` |
| 禁言 | `{甲}({id})被{操作者}({id})禁言{d}天{h}时{m}分{s}秒` |
| 解除禁言 | `{甲}({id})被{操作者}({id})解除禁言` |
| 加好友 | `添加了{甲}({id})为好友` |
| 运气王 | `{甲}({id})的红包，{乙}({id})是运气王` |
| 群荣誉 | `{甲}({id})获得荣誉：{荣誉名}` |
| 更新名片 | `{甲}({id})更新了ta的名片为"{名片}"` |
| 移除名片 | `{甲}({id})移除了ta的名片` |
| 精华消息 | `{操作者}({id}){设为\|取消了}{甲}({id})的精华消息({消息号})` |

反解成事件的两类只取行尾那个 id，不解释句子本身：

- **戳一戳**需要 `user_id`/`target_id`，因为 `chat.get_msgs` 拿到事件后又交回 `format_poke` 渲染——往返在本文件的格式化与解析之间闭合，用的还是当前身份，所以重建出来的戳一戳与实时事件逐字相同。
- **撤回**只需要被撤回的 `{消息号}`，用来让启动重建不把已撤回的消息放回内存。`read_range` 不做这个剔除：档案对「发生过什么」的回答本就包含后来被收回的东西。

## 借用消息形状的通知

文件上传写成消息形状，但 `| {消息号}` 一段缺失，正文是文件描述而不是消息正文：

```
【{头衔}】{名字}({QQ号}) {HH:MM:SS} | 
    【文件】{文件名} {大小}
    {下载地址}
{名字}({QQ号}) {HH:MM:SS}
    【文件】{文件名} {大小}
    {下载地址}
```

`bot/` 里还有两种非人名头：好友请求的头本身就是一整句 `{名字}({QQ号})请求添加你为好友`，正文是验证消息；写入失败的兜底头是 `其它消息` 或 `未捕获消息`，正文是 `repr(dict)`。

## v0：切换之前的行

`v1_since` 之前写下的行只读、尽力解析、**永不重写**，与 v1 的差别有三处：

| | v0 | v1 |
|---|---|---|
| 私聊消息行 | `{名字} {时间} \| {消息号}`，没有 QQ 号 | 补上 `({QQ号})` |
| 正文 | unescape 过的显示投影 | OneBot 原始串 |
| 私聊戳一戳、私聊撤回、私聊文件 | 只有名字 | 一律带 `({QQ号})` |

因此 v0 的私聊记录**无法确定发送者**：柚子自己说的话和对端说的话只靠一个可变昵称区分。

解析时尽力补齐，规则取决于 `storage` 里 `chatlog/format` 的 **`bot_names`**——一份从柚子历史显示名到账号号码的映射。**柚子换过 QQ 号**，所以「是不是柚子」不是一个号，「叫什么」也不是一个名字，两件事都无法从行内推出，只能在这里写下来。

**配置了它，本身就是在声明「柚子用过的名字都在这儿了」。** 完整性不是第二个开关：肯把这张表写下来，意味着有人真的看过存档里有哪些名字。于是排除法成立——私聊窗口只有两个参与者，路径已经给出对端，所以「不是柚子的名字」就是对端的名字，一条规则覆盖全部行。

没配置时退化成只认当前账号，那份映射**已知是不完整的**（换号之前的一概不在里面），此时排除法不是弱一点而是错的：柚子用旧账号名字写下的行匹配不上任何东西，会被悄悄记到对端头上。所以未声明完整时对端那一侧要自己的正面证据——该账号**当前的昵称**，那正是 v0 私聊行记下的东西——两边都对不上就**留空**，不猜。

补出来的身份标进 `_guessed`，不与诚实的推导值混在一起。**这是全篇风险最高的兼容做法**，它只服务于检索：启动重建只收 v1 记录，所以猜出来的发送者永远不会进入内存或模型上下文。

不做一次性转换脚本把历史文件改写成 v1：**unescape 不可逆**，转换能补上 QQ 号，却无法把正文还原成原始串——重新转义会把真实 CQ 码变成字面文本，不转义则等于给一份投影贴上 v1 的标签。转换因此只能是半截的，代价是把一个已标注的缺口变成一个没有标注的谎。

## 每条记录的三级标注

`parse_log` 的结果里每个字段属于三类之一，必须能区分：

- **事实**：直接读自行内容——时间、消息号、发送者 QQ 号、正文。
- **推导**（`_derived`）：由路径、`identity.bot_id()` 或正文算出，规则确定——`group_id`、`message_type`、`post_type`、`sender` 里的名字与头衔。
- **缺省**（`_missing`）：根本没写下来的东西，认不出的 v0 私聊 `sender` 是主要一例。
- **猜测**（`_guessed`）：在一条写明的假设下补出来的，假设本身可能是错的。目前只有 v0 私聊的 `sender`。它单独成一级而不是并进 `_derived`，因为推导是规则确定的，猜测不是。

另有 `_source` 标出这是重建结果而不是实时事件。消费者读的是原始 OneBot 字段，没有这些标注，字段缺失就是静默降级而不是明确失败。
