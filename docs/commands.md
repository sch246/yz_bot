# 功能与命令目录

本目录描述命令的用户角色和状态范围。精确参数以 `.help <命令>`、命令自身帮助和 [COMMANDS.md](../COMMANDS.md) 为准。

## 核心可编程能力

### `.py`

管理员可在聊天中执行 Python。多行代码的最后一行作为表达式返回；`print` 会发送到当前聊天，`input` 会等待同一用户在当前窗口的下一条消息。

命令体可以单行或多行：前面的行用 `exec`，最后一行用 `eval`，结果不是 `None` 时发送回当前窗口；最后一行以普通 `#` 开头时静默。异常 traceback 也会回传到聊天。`print()` 每次调用会发送消息，`input()` 会占用同一用户、同一窗口的下一条消息。

执行环境在进程内共享，所以后一次 `.py` 可以使用前一次留下的名称，link action 也借用这套环境。默认状态在重启后消失；最后一行以 `###` 开头时，本次完整代码会追加到 `data/pyload.py`，以后每次启动重新执行。例如：

```text
.py
def rd(n, sides):
    return sum(random.randint(1, sides) for _ in range(n))
###
```

这会持久化定义而不求值末行。持久化代码必须能够从干净启动环境运行，不能依赖只存在于本次进程的临时变量。

它既是 REPL，也是现场修复和扩展入口。`^C` 会通过共享 continuation 机制唤醒并取消 `.py input()`，与 yield 命令使用同一条逃生路径。

同一套环境也被模型工具 `exec_code` 复用：它的 `print` 会被捕获成返回值、不会发进聊天；捕获走 `ContextVar`，用户代码自己起的线程里的 `print` 也进同一份捕获；`timeout` 默认 15 秒，同步调用不允许 `0` 无限等，后台模式允许 `0` 且跑在独立线程、不排 `_tasks` 的单队列，长脚本用 `back="wake"`/`"quiet"` 放到后台。

`data/pyload.py` 是未受版本控制、通过 `exec` 注入的设备级输入。长期复用能力属于普通 `mods`，确有动态消费者的平铺名字由 `mods.py::DYNAMIC_EXPORTS` 显式维护。pyload 在候选环境中完整成功后才安装；失败不会留下半套名称。新增长期能力时不要继续堆进 pyload，详见[运行架构](architecture.md#pypyloadpy-与动态名称)。

### 其它语言环境

这些命令延续“在聊天里写一点程序并立即得到结果”的体验，但实现并不统一：

| 命令 | 环境 | 当前角色 |
|---|---|---|
| `.js` | JavaScript | 长驻 Node REPL，`:bye` 关闭 |
| `.cpp` | C++ | 写入临时源文件，用 g++ 编译后以可交互子进程运行 |
| `.hs` | Haskell | 长驻 GHCi REPL，`:quit` 关闭；解释器路径可由 `GHCI_PATH` 配置 |
| `.nim` | Nim | 写入临时源文件，每次 compile-and-run |
| `.nl` | newLISP | 借 screen 保持一个 newLISP 会话 |
| `.lua` | Lua | 写入临时文件，优先调用 PATH 中的解释器并设置执行超时 |
| `.mcf` | Minecraft function/datapack | 直接创建或修改数据包函数与标签；属于管理员能力 |

这些命令共享产品理念，不共享技术契约；维护时不必为了形式统一强行套一层抽象。

### `!<shell>`

管理员可直接执行 Linux shell 命令。它位于普通点命令之后、link 之前，主要用于宿主机维护和 `.py` 不方便表达的操作。

## 自修改、文件与生命周期

| 命令 | 功能 | 状态/权限 |
|---|---|---|
| `.file` | 读取、写入、删除、发送或接收文件与目录 | 管理员；直接影响宿主机文件 |
| `.edit` | 在聊天中分页查看、逐行或整块编辑文件 | 管理员；多步交互，可保存或放弃缓冲 |
| `.reboot` | 优雅退出并请求外层立即重启 | 管理员；保存发起消息与“是否续话”，重启后插件钩子向原聊天发送“重启完成”，发起者是 Bot 自己时再唤醒中心 reader |
| `.shutdown` | 有意停止 Bot | 管理员；留下只执行一次的启动钩子，下次启动向原聊天发送“醒了” |
| `.op` | 添加或移除管理员 | 仅管理员；首位 master 不可由普通删除流程移除 |
| `.post` | 为当前群/私聊或指定目标切换 OneBot API 出站端口 | 与 `5701` 事件注入及假 API 端组合成调试通道；当前窗口可自助设置，指定其它窗口或清空全部映射需要管理员 |
| `.log` | 查看并修改终端订阅的日志流 | 管理员；Bot 实例级配置，存 storage、重启不重置 |

典型维护流是 `.edit`/`.file`/`.py` 修改，确认磁盘状态，再 `.reboot`。这条路径比进程内热替换更可预测。

`.log` 管理终端看哪些流：`.log` 列出启动以来出现过的流和当前订阅集，`.log on/off <前缀>` 增删一条，`.log only <前缀>…` 整体替换（不给前缀即清空）。匹配按 logger 名的层级做前缀匹配，所以 `yz.llm` 含 `yz.llm.request`；订阅集里以 `-` 开头的条目是挖除，最长前缀胜出，因此默认的 `yz` 加上 `-yz.storage` 就是「除 storage 外全看」。

它只控制 INFO 级流量：WARNING 以上无论是否订阅都进终端，退订也不影响 `app.log`，所以可以放心大幅退订。它是 Bot 实例级配置而不是聊天窗口级——终端只有一个。

`.op [del] (<QQ号>|<@某人>)+` 支持空格或换行分隔多个目标。它不能通过自身删除首位 master，但任何 op 都能调用 `.py`、shell 和文件能力绕过这一限制；授予 op 等价于授予 Bot 进程和宿主机的完全控制。

`.file` 是直接文件工具：`read` 可列目录或按行读取文本，`write` 覆盖指定区间，`get/set/to` 收发文件，`del` 删除，`setdir/dirto` 处理压缩目录。它保留了一些历史兼容和已知 bug，危险路径有局部保护，但不能把它当成沙箱。

`.edit [路径]` 是有缓冲的持续会话。`w` 保存、`wq` 保存退出、`q` 在有未保存修改时要求再次确认、`q!` 放弃、`d` 挂起；`u/r` 撤销重做，`p/n` 翻页，数字跳行，复制页面修改后发回可整块编辑。session 按文件路径保存并有聊天 owner：同一文件不能被另一个聊天窗口同时接管；群内参与者共享该群的 owner 线。缓冲存在 storage 中，但磁盘只有在 `w/wq` 后改变。

## 命令插件

公开 Module 本身就是插件系统：在 `mods/` 新增一个模块，并用无参数 `@command` 装饰入口。`run(body)` 注册为 `.模块名`，其它函数注册为 `.模块名.函数名`。模块之间直接 import，loader 只负责生命周期和失败隔离。开发细节见 [COMMANDS.md](../COMMANDS.md)，边界见[运行架构](architecture.md)。

## 动态反应系统

### `.link`

管理员可以查看、捕获、创建、编辑、移动、删除、导入和导出 link 节点。

节点的两种类型不只有条件不同，action 返回语义也不同：

| 类型 | cond | action |
|---|---|---|
| `py` | 前几行 `exec`，末行 `eval`；truthy 时命中 | 整段 `exec`，末行表达式不会自动回复，必须显式调用 `sendmsg()` 等 |
| `re` | 展开结构化模板后用 `re.match` 做前缀匹配 | 将捕获值替换进 `{:name}`；前几行 `exec`、末行 `eval`，非 `None` 时自动回复 |

`re` 模板的 `{name:type}` 会把 `type` 在 `.py` 共享环境中求值：字符串作为正则，可迭代值组成候选；求值失败则按字面正则使用。省略 type 时，小写开头的 `{name}` 匹配非空白串，大写开头匹配可跨空白内容；省略 name 的 `{:type}` 只插入模式。重复捕获名会生成反向引用。捕获值只做 action 文本替换，不进入 `.py` locals。

例如先在 `.py` 中持久化 `rd()` 后，可以创建骰子反应：

```text
.link re 骰子
\.r{r:\d+}d{d:\d+}$
===
f'{getname()} 投了 {:r} 个 {:d} 面骰，总数为 {rd(int("{:r}"), int("{:d}"))}'
```

这是配置即代码：插值最终生成 Python 源码，引用和转义必须按执行语境检查。

节点按 `links.json` 数组顺序检查；首个命中节点执行 action 后结束。默认新节点插入列表头，`.link move` 显式调整位置。持久格式不再包含 `succ`、`fail` 或 `while`。源码中的通用 `@capture` 可以定位在某个持久节点之前，或作为列表后的兜底，但不会写入该文件。

`.link catch` 不执行 action，但会真实求值 cond。尤其 `py cond` 仍会运行其中的 Python 语句，所以它只是“抑制 action 的路径检查”，不是无副作用 dry-run。cond 约定上不应 send/recv、修改状态或主动调用 action，否则 catch 结果也不可信。

cond 或 action 报错会写应用日志并把 traceback 回传当前聊天。cond 报错按未命中处理，继续后续线性节点；action 报错结束这次已经命中的反应。重复报错节流和统一 incident 仍是[未实现提案](working/proposals/errors-and-logging.md)。

`.reply` 是当前 link 配置中的便捷反应：通过聊天内容生成一个静态回复节点，体现了“反应系统可以继续修改自己”。当前节点见 [link 快照](working/link-reactions.md)。

## 聊天历史与检索

### `.search`

`.search <正则表达式>` 在当前聊天窗口的全部日志里逐行匹配，命中的**整条记录**一并显示，每页 5 条交互式翻页。搜索是纯 Python 的，不调用 shell。

记录 = 顶格的记录头加它缩进的正文。命中正文行会把上面的记录头（谁、几点、消息号）一并带出，命中记录头会把正文带出——两种用法都是常态，所以结果按记录而不是按行给。通知没有正文，本身就是一条单行记录。每条结果前附 `文件路径:行号` 定位头，行号指向记录的起始行。

匹配和显示都用 `chatlog.display()` 还原后的文本，也就是你在聊天窗口里看到的样子，而不是文件里存的 OneBot 原始串。正则非法时直接返回错误说明，不进入翻页；没有命中时返回空提示。

它读的是 `chatlog/` 下当前窗口的目录，那里的行格式是协议，见 [chatlog 记录格式](chatlog-format.md)。

## 群体记忆与娱乐

### `.cave`

回声洞是全局漂流瓶池。用户可以：

- 随机或按编号取出内容；
- 添加单条消息；
- 交互式合并接下来的多条消息；
- 搜索内容；
- 删除自己的投稿，管理员可删除其他人的投稿；
- 导入或导出整个池。

随机读取使用一个会补充的池：命中后有约三分之二概率暂时移出，池耗尽后重新装满。这减少短期重复，但不承诺严格等概率或永久不重复。

每条投稿保存文本、投稿人、QQ、时间以及可选来源群；展示时私聊投稿不显示群，群聊投稿会带群名。`setname()` / `setgroupname()` 等用户和群设置会影响之后呈现的称呼。默认删除目标是自己最近一次投稿，管理员才可越权删除他人内容。

### 每日与随机玩法

| 命令 | 功能与范围 |
|---|---|
| `.jrrp` | 个人今日人品 |
| `.jrxm` | 今日小猫及列表 |
| `.jrxdw` | 今日小动物；支持个人类别和权重 |
| `.jrgz` | 从当前群成员中选今日鸽子，群之间独立 |
| `.jrlp` | 从当前群成员中选今日老婆，按群隔离 |
| `.bbxm` | 从既有群聊日志重建“百变小猫”语料；属于维护入口，不只是一次随机反应 |
| `.bbxdw` | 管理百变小动物类别、前后缀和概率 |
| `.answer` | 答案之书；也可由自然语言 link 触发 |
| `.change` | 随机或指定数字的易经起卦 |
| `.jm` | 搜索或获取漫画内容；当前没有 op 检查 |
| `.setu` | 调用图片 API 返回随机图 |
| `.join` | 群内多人参与并随机选人 |

这些功能常通过 link 获得无前缀入口，因此命令名不是它们唯一的用户界面。

`.jm search <关键词>` 在进程内第一次搜索时才创建 `jmcomic` 站点 client，后续搜索复用它；加载 Bot 和导入命令本身不会再触发站点域名刷新。`.jm <本子 ID>` 在线程中检查 `data/jm/<ID>.pdf`，没有缓存时按设备级 `data/option.yml` 创建下载 option，成功后把 PDF 发回原聊天。两条路径都仍依赖已安装的 `jmcomic`，而下载路径还依赖本机 option 与其输出约定。

`.bbxm` 和 `.bbxdw` 从 `storage.get('bbxdw', 'settings')` 读取维护配置：

- `source_group_id` 是语料来源群；未配置时命令会显式提示，不会猜测或回退到源码常量。
- `excluded_fragments` 是可选的字符串列表；匹配到其中任意片段的语料会被排除。

`.jrlp` 从 `storage.get('jrlp', 'settings')['disabled_groups']` 读取禁用群列表。该键必须显式配置；空列表表示不禁用任何群，缺失或类型错误时命令会拒绝继续，避免迁移时意外启用原本禁用的群。以上设置属于 Bot 实例级运行配置，修改内存对象后会由后台同步线程在分散的十分钟检查窗口内落盘，正常退出也会强制保存；需要立即落盘时由管理员调用 `storage.save()`。

## 时间与持续任务

### `.later`

创建一次性延时或定时任务，支持相对时间和绝对时间。任务按群或私聊用户保存，并在重启后重新注册。普通用户只能安排简单字符串结果；执行任意 Python 表达式需要管理员权限。任务触发时沿用创建时的消息目标。

相对时间可组合 `Y/y`、`M`、`D/d`、`h`、`m`、`s`，例如 `1m30s`；绝对时间支持 `时:分[:秒]`、`月-日`、`年-月-日` 及日期时间组合。`.later` 列表，`add`（可省略）添加，`del <seq,...>|*` 删除，`set <seq> ...` 修改。任务执行环境提供 `later_repeat()` 供触发后再次安排自己。

### `.todo`

保存周期条件和表达式，按群或私聊用户隔离。后台当前每分钟检查一次条件，而旧帮助文本中“每秒检查”的说法已经不符合实现。

当前条件解析器存在重复定义和明显可疑路径，这个命令应视为待实机确认的旧功能；本文记录其设计角色，不宣称所有新增/编辑语法当前都可用。

`.later` 适合“在某一时刻做一次”，`.todo` 适合“条件周期性满足时执行”。

## LLM 聊天

### 中心聊天与 `.chattop`

- `.chattop [月份]` 查看某个自然月累计的调用次数与费用（月份为 1..12 指今年，或 `YYYY-MM`；默认当前月）。

主聊天入口不是点命令，而是 `mods.chat.capture_chat`；旧 `cond()`／`call()` 仅保留公开兼容名。在允许聊天的群或私聊中，以下行为可触发：

- @ Bot；
- 以“柚子，”或她的任一名字（`identity.names`）开头，名字后面跟全角或半角逗号、空白都算；
- 私聊里对方发来的任何消息（`#` 子命令除外）；
- 戳一戳 Bot；
- `#...` 聊天控制命令。

别的唤醒方式调用 `chat.wake(event, kind)`：link 节点、`.py` 或其它模块在这条消息的派发过程中判定要叫醒她时调它，`kind` 原样出现在她看到的唤醒原因里；不带消息时用 `chat.wake(reason=..., kind=...)`，随时能调，她正忙就排着。她自己用 `wake_me` 埋唤醒：过一会儿、到某个时刻、某个窗口来消息、等某人的后续（来了或超时都叫她，只叫一次）、某个 Python 条件成立，也能给窗口或一整类窗口盖限时的覆盖层：`follow` 期间每条消息都叫醒她，`mute` 期间都不叫（消息照样未读，master 的话压不住）。她在群里说完话，那个群自动 `follow` 5 分钟，她连着两次 `dismiss` 就停。被叫醒了没什么要做的，她用 `dismiss` 把这次唤醒（或者从某一行“这次唤醒你的是”起）从上下文里清掉，消息下次画面里还在；那以后她发过话就不能清。潜意识默认开（`#subconscious off` 关）：这一段每长 5 万 token，她下一次请求末尾会多一条提醒（这一段多长、能收哪几段）；收不收、收哪段、摘要怎么写由她自己调 `compress`，收掉的唤醒原样归档（`-folded`），这次调用和结果也一起从眼前消失。循环总开关默认开（`#loop off` 关）：由她自己调用 `loop("在做什么")` 显式开启一串，外部唤醒不再自动挂起空循环。开启后每次唤醒结束后隔两秒再叫醒她，一轮接一轮；她用 `wait(秒数)` 隔一会儿再来，用 `loop(stop=True)` 结束这一串。她一个动作都没做的那几轮间隔翻倍、最长半小时；没人干预就转到夜里整理时停，维护者叫停她那一轮也会停。

只有戳 Bot 会立即触发 LLM；群内其它成员互戳会登记为窗口未读，不单独唤醒模型，之后出现在该群的窗口画面里（chatlog 记录的通知行）。

主聊天由一位中心 agent 跨窗口处理。`#status`、`#model`、`#models`、`#prompt`、`#image`、`#audio`、`#reasoning`、`#effort`、`#limit`、`#reflect`、`#subconscious`、`#loop`、`#awaker`、`#debounce`、`#observer` 和 `#help` 可查看全局状态；`#use_model`、`#model note` 及带参数的 `#prompt`、`#image`、`#audio`、`#reasoning`、`#effort`、`#limit`、`#reflect`、`#subconscious`、`#loop`、`#awaker`、`#debounce`、`#observer` 修改全局状态，要求 op。`#status` 一键查看全局所有核心开关与运行状态；`#image [off|lazy|eager]` 与 `#audio [off|lazy|eager]` 控制多媒体读取档位（默认均 off；audio 的 off 仅提示时长，lazy 转存本地 mp3 并展示 file:/// 供调 `audio__listen`，eager 自动多模态转录并在画面呈现台词与语气）；`#model [selection]` 查看当前或指定模型单价与能力，`#model note <provider/model> [备注]` 查看或设置模型评价备注（写 clear 清空）；`#models [供应商]` 列出当前或指定供应商的所有模型、单价及备注；`#prompt [set <全文>]` 查看或改写她对自己的认识，也就是笔记 self（`data/notes/self.md`，放在系统提示最前面，取代旧的提示词与命名设定；她只能在夜间反思里改）。私聊叫醒她时，她干活期间对方会看到“正在输入”。中心 agent 只要不交接就一直在同一段上下文里：交接后第一次被叫醒时以做法笔记、上次交接留下的 recent、最近一篇日记、最近 8 段交接归档的年鉴索引（`data/notes/years.md`）和一份目录开头，之后每次唤醒只往后追加叫醒她的窗口画面（chatlog 原文格式）、第一次出现的人或群的笔记和叫醒原因，其余由她自己召回。笔记是 `data/notes/` 下她随时能改的普通文件。她调用 `tidy`、这一段超过整理阈值（未发言时有 2 次唤醒宽限，先在末尾提示交接）、或夜里到点时交接：在同一段末尾确认各类信息都已在笔记和当天日记里，然后这一段归档到 `data/context/archive/`。`#limit <画面条数> <整理阈值>` 的两个值是从没看过的窗口的首屏条数（默认 80；已有看到位置时只补 3 条旧记录接话）和整理阈值（token，默认 500000，约是模型上下文的一半，即整理条件里的 `limit`）；旧的 token 上限与整理百分比第一次读到时删掉、用默认。`#awaker [set <规则>]` 查看或改写她的唤醒规则（笔记 awaker，每行一条 `every 10m 理由`、`daily 23:30 理由`、`at 2026-10-23 08:00 理由`、`on g123 理由`、`wait g123:QQ号 until 2026-10-23 10:30 理由`、`when 表达式 -> 理由`，或覆盖层 `follow g123 until 2026-10-23 22:30 理由`、`mute bili until 2026-10-24 08:00 理由`；`at`、`on`、`wait`、`when` 响过就划掉，覆盖层到期划掉，她平时用 `wake_me` 写；理由 `reflect` 是夜间交接与反思，默认 `daily 04:00 reflect`）。`#reflect [now]` 查看上次反思时间或立即跑一次夜间交接与反思：先交接手上这一段，再用新的一段像人排查一样读归档的上下文和原始记录反思，不对外说话。`#reasoning drop` 让以前几次唤醒的思考不再带回这一段，默认 keep。`#effort [default|off|none|low|medium|high|max]` 查看或设置主模型思考等级（管理员），默认 default（按模型自身默认）；`off`/`none` 原生关闭思考（例如 DeepSeek 系列极速返回），也支持设置 `low`、`medium`、`high`、`max` 调整思考深度。`#observer [on|off|model [selection]|effort [level]|context [recent|full]|prompt|set <全文>|reset]` 查看或设置旁观助手（Observer，修改需管理员）：在中心会话被唤醒时执行严格单轮旁观，检测未登记黑话与存疑指代并检索查证、暴露做事的非预期情况与规则冲突、提醒对话节奏与 wait，可直接用 `load_notes` 挂载已有笔记至当前段；无盲区时静默不打扰。`#observer` 查看当前状态、模型、思考等级、上下文模式与提示词概况；`on|off` 开关；`model` 查看或设置模型（默认 `deepseek/deepseek-flash`）；`effort` 查看或设置思考等级（默认 `off`）；`context [recent|full]` 查看或切换上下文模式（`recent` 仅看上一轮唤醒，大幅削减 token 开销；`full` 携带整段历史前缀缓存，默认 `recent`）；`prompt` 查看提示词与 Checklist；`set <全文>` 整份替换 `data/notes/observer.md`（留空回落默认）；`reset` 恢复默认配置。旧窗口聊天设置不再读取，也不自动并入全局；只有 `#hint` 仍按窗口独立配置。`聊天开始/聊天结束`是普通内容。模型用 `read_log(window, count, before)` 读任意窗口的聊天记录原文，`search(keyword)` LLM 开局默认激活 `meta` 模块，直接获得共享 `.py` 环境执行工具和三个工具模块管理工具。完整目录及已加载模块说明在首次请求成为正式工具状态 input（位于笔记之后、第一条窗口画面之前）；之后变化在请求边界追加差异 input，不改写旧描述。模型用 `load_tools` 激活 last-good 模块，用 `list_tools` 取完整最新状态和磁盘差异，用 `reload_tools` 显式应用修改。闲置超过一小时的模块下轮不再激活，但已发送的函数定义保留并由调用 guard 提示重装。现有模块覆盖戳一戳、图片、视觉外援、时间、延时任务、天气、高德地图、联网搜索、B 站冲浪与互动、自管浏览器、安卓备用机控制、邮箱、TOTP 验证码、表情柜、语音合成、合并转发、文件发送、头像获取、宿主机文件与后台命令、用户 storage、子模型任务分派、夜间反思记忆系统和 MC 百科查询；不会自动热加载。历史上明确禁用的工具只在 `mods/tools/disable/README.md` 留有决策记录，仓库中没有对应实现。工具 schema、模块格式、循环回写和高权限边界见独立的 [LLM 文档](llm.md)。

## Minecraft 与宿主服务

| 入口 | 功能 |
|---|---|
| `.mcversion` | 查询 Minecraft 版本并管理群订阅 |
| `.mcf` | 编辑服务器 datapack/mcfunction |
| link 中的服务器启停短语 | 启动、停止或重启 Minecraft 服务 |
| link 中的 `\\mc ...` / 双反斜杠入口 | 发送 Minecraft 或 screen 命令 |
| link 中的 `% ...` | 调用已连接的远端服务 |

这些能力依赖当前设备和外部服务，不是可移植的纯聊天功能。

本机传统拓扑中，screen 负责启动 Minecraft 进程和读取控制台，RCON 负责快速发送服务器命令并取得返回；screen 能看到部分 RCON 不返回的控制台输出，但通常更慢、输出也可能更杂。Bot 重启会丢失内存中的 RCON 连接，需要重新连接；自动连接、路径、screen 名、RCON 地址和密码都属于 `data/pyload.py` 的设备配置。

`.mcf` 直接创建/修改 datapack 中的函数与函数标签，依赖私有 Minecraft 设备配置，并显式要求 op。link 中更具体的双反斜杠入口必须排在更宽的单反斜杠模式前，否则会被前者截断；这正是线性 link 顺序属于行为的一例。
