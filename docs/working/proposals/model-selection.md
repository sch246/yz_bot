# 模型选择的宽松解析与在线模型列表

> 状态：已实现；本文作为决策记录保留
>
> 最近更新：2026-09-17

本文记录 2026-09-17 关于「配置里没有的模型」的一批决定，以及同一批对默认模型、视觉模型和价格表的调整。
当前契约以 [LLM 文档](../../llm.md) 为准；这里只保留取舍、被排除的做法和推翻条件。

涉及的位置：`mods/llm/models.py`（`resolve_model`、`UNKNOWN_MODEL_CAPABILITIES`）、
`mods/llm/__init__.py`（`LLMClient.list_models`）、`mods/chat.py`（`_models_report`）。

## 背景

`resolve_model` 曾是所有模型路径的唯一入口，而且是硬校验：供应商不在配置里、模型不在该供应商的
`models` 字典里，都直接 `ValueError`。它同时被 `describe_image`、`generate_response`、计费
（`chat.inc_call_tokens_cost`）和 `#model` / `#use_model` 命令层调用。于是「配置里没有」的后果是：

- 换一个还没登记的模型，必须先在配置里补一行才能试；
- 计费那一路抛在流式回调里，会把整轮聊天掐成一条 `#` 错误；
- 存量里两个不带 `/` 的历史选择，每次聊天都被静默换成默认模型。

## 决定一：未登记的模型照常调用

- `resolve_model` 只要求**供应商**已配置——没有 base URL 与 API key 就不存在可调用的对象，仍然报错；
  模型名按原样下传，不再查本地表。
- 未登记的模型按 `models.UNKNOWN_MODEL_CAPABILITIES` 处理：`vision` 与 `function_calling` 都为真，价格为 0。
- 「这个模型存不存在」因此只有对端一个权威，本地 `models` 降级为纯元数据（价格与能力）。

代价与理由：

- 打错的模型名不再被本地拦下，换来一条供应商报错。可诊断性没有丢：那条错误仍然出现在聊天里，
  并且带 `#` 前缀所以不回流进上下文。
- 价格 0 表示这一轮不计费。宁可少算，也不因缺元数据而算错——价格表本来就是手工维护的近似值。
- 两个能力标志都为真，是因为它们只决定本地怎么拼请求（图片是否转 `data URI`、是否附带 tools），
  不决定对端是否接受。猜错的表现是一次 API 报错，而不是静默降级。

## 决定二：不支持裸模型名，历史遗留值改数据

`provider/model` 的分隔规则不变，不含 `/` 的选择仍然报错；`chat.get_model` 对这种值继续回退到默认模型。
因此**不为裸名字补默认供应商**：那是旧格式的残留，不是要维护的输入。存量数据按「改数据」处理——
两个窗口里存的历史裸名已直接改成 `deepseek/deepseek-flash`，不再靠每次聊天时的静默替换兜底。

## 决定三：`#models` 先问对端，取不到才用本地配置

`LLMClient.list_models(provider)` 请求对端的 `/models`，任何失败都返回 `None` 并把原因写进 llm 流；
`chat._models_report` 据此二选一，并在末尾一行说明这次用的是在线列表还是回退后的本地配置。
本地没有元数据的行只显示名字（价格为 `-`、无能力标记），不替对端猜。

理由：一条查看用的命令不该因为网络或密钥失败而变成报错，但也不该在能取到权威清单时继续展示陈旧的一份。
列表是给人看的，所以在线取到的结果不参与解析，只影响展示。

## 同一批：默认模型与视觉模型切到 `deepseek-flash`

| 模型 | 能力 | 输入 | 输出 |
|---|---|---|---|
| `deepseek-flash` | 图像理解 + 函数调用 | 2 | 8 |
| `deepseek-v4-pro` | 函数调用 | 9 | 27 |

价格单位是人民币元/百万 token，写的是官方**高峰时段**价——空闲时段减半，而配置里只能写一个数。

- `default_model` 改为 `deepseek/deepseek-flash`。旧名 `deepseek-v4-flash` 与
  `deepseek-v4-flash-vision-exp` 保留在配置里（同一系列、按 Flash 计费），以免存量窗口的选择解析不到。
- `vision_model` 从 `bytecat/gpt-5.4-mini` 改为 `deepseek/deepseek-flash`：切换当时 bytecat 渠道持续
  503「模型过载」，而 deepseek 能识别网络图与 `data:` URI 图。视觉 token 单价因此明显上升，这是接受的取舍。
- 文档里已不存在的 `deepseek-chat` 与 `deepseek-reasoner` 从 deepseek 渠道删除（当时仓库内无引用）。
- 源码里的 `default_config()` 只在首次创建空配置时使用；设备实际使用的是 `data/storage/llm_system/config.json`。

## 被排除的做法

- **把模型做成白名单并工具化查询**：模型清单的权威在对端，本地复制一份只会长期不同步。
- **未知模型一律拒绝，只是把报错提前到命令层**：这就是改动前的行为，见背景。
- **缓存在线模型列表**：`#models` 是低频管理命令，缓存会引入失效判据，收益只是省一次请求。
- **为未知模型猜测价格**：宁可计 0，也不引入一份猜出来的价格表。

## 什么时候该推翻它

- 如果某个供应商对未登记的模型名不报错、而是回落到另一个模型，价格 0 会让计费静默偏低；
  那时应改成按同类模型估价，或把该供应商的模型重新登记回配置。
- 如果在线 `/models` 开始明显变慢或频繁失败，说明它不该继续挂在命令的同步路径上。
- 如果未登记模型的「能力全开」开始造成难以诊断的失败（例如对端把图片当文本报错），
  那时应该给能力加一个显式的窗口级设置，而不是恢复白名单。
