# 在一次计算中重新组装上下文

2026-11-02 方案与实施取舍记录。上下文概览、分身最终答复交付、准备权限继承，以及 fork、构造和主行动的同调用换 ctx 已在隔离集成树实现并验证；主线集成和生产切换状态见[整份验收](../tasks/context-reassembly/acceptance.md)。本篇保留[原子与串线](one-purpose-stateless-core.md)的落地理由与后续问题，接口合同以[实施规格](../tasks/context-reassembly/spec.md)、[LLM 文档](../../llm.md)和[交互模型](../../interaction-model.md)为准。

本轮补齐两项能力：**一次计算可以换上下文继续；子计算交回最终答复，完整探索另留入口。** 构造、行动、分身共用引用与重新组装能力。构造自身需要的材料，也能由前一次思考准备、由当次检索和分身继续补足。

实现复用 journal 的经历、view 的有序引用和现有 `run`。一次计算的执行所有权保持不变，期间可以产生多个 ctx。第一版保持现有唤醒与串行调度，不增加任务树或自动依赖失效系统。

## 实施前的问题与调查依据

实施前，`construct → main → settle` 已把准备、行动、沉淀分开，但每个 `run` 内仍持续追加工具结果；`fork` 返回子运行全部 assistant 文本的拼接。构造的第一份材料由 `material(wake)` 固定组合目录、黑板、todo、时间线和画面；本轮仍保持这份开场默认。

11 月 2 日调查的一次行动有 42 次工具调用，首轮 prompt 为 5,045 token，末轮为 32,939 token。工具结果共 50,238 字符，其中前 23 次查找入口和读取源码占约 82%。这次始终在调查同一个问题；找到计量入口后，后续计算仍背着寻找入口时的源码与搜索结果。

依据是日志 `20261102-2061` 至 `20261102-2227` 对应的调用与结果，以及该段接口 usage。字符数和 token 数分别统计。它说明同一目的下也会更换所需材料，支持提供重新组装的能力；不能据此承诺所有长行动都应拆开，或预先给出省费比例。

另外一次 `IndexError` 发生在画面准备阶段，首次模型输出之前，与这次已完成的长行动分开处理。

## 原子与线在这里怎样落地

- 已有消息、工具结果、笔记快照和新生成的结论，都是可引用的材料。一个材料可以参与多次组合，无须归属某棵树。
- view 表达本次把哪些材料放在一起、以什么顺序呈现。原文留在 journal 或已有笔记版本中。
- 一次输出可以是结论、感受、一个更好的问题、下一段的材料选择，也可以是未知；输出内容由当次计算决定。
- 构造是一种用途。它使用与其它计算相同的引用、检索、委派、交付和重新组装能力。

这里没有把“原子”规定为最小消息长度，也没有新增 Atom 数据库。一次工具结果内部需要分段时，继续使用有出处的选区。已有引用足以承担第一版的材料身份。

“干净”指材料服务于当下思考。情绪、关系和表达的来路可能正是必要材料，不能按字数或是否属于事实自动剔除。

## 本轮实施取舍

原方案提出 `return_result(text, refs)` 作为显式成果出口，另以自然结束的最终答复兜底。[实施规格](../tasks/context-reassembly/spec.md#分身交付与限制)选择只用最后一条无工具调用的 assistant 答复交付，出处写在正文；取消、失败、没有最终答复各自标明并保留 ctx。没有新增 `return_result`，也没有再把探索文本拼成成果。

`reframe` 由模型主动使用，可以在目的已变时用，也可以在目的未变、但所需材料已变时用；普通追加仍适合短而紧密依赖的步骤。新段按选择带入 refs、focus 与接续 note，旧材料仍能沿 ctx 展开。具体参数、独占批次、请求确认、关联归档及失败行为见[运行中重新组装上下文](../../llm.md#运行中重新组装上下文)，请求和 usage 口径见[上下文概览](../../llm.md#上下文概览)。

执行所有权仍属于同一次调用：主行动保留 wake 和窗口，构造保留总时限与最终一份 assemble；分身继承父运行的材料和操作限制，自身生命周期工具按职责提供。这让准备材料的计算也能准备自身材料，无须固定层数的 Meta-Construct。换材料不主动把执行权交给另一项待办；真正挂起 wake 再由全局队列择机恢复，需要另行设计 claims 与等待者的所有权。

journal 留下材料与关联事实，内存 state 持有调用控制权。模型可以换材料继续，程序不按调用次数或长度强制触发，不增加任务树或自动依赖失效图。取消与原有绝对截止时间跨段延续，未知外部结果仍是未知，不自动重放动作。

## 构造材料选择的后续方向

本轮已经让构造能使用 `reframe` 和准备型 `fork`：需要查某条关系、比较几份记忆或阅读一个范围时，它可以把调查交出去，收回最终答复后重新组装自己的材料，最后仍只交一份 `assemble`。初始 `material(wake)`、todo 全文与各份索引的默认组合没有改变。

原方案进一步考虑把 `material(wake)` 中固定全文改成**必要现场与可展开的材料入口**。这一默认调整没有纳入本轮，仍需实际遗漏和总账证据：

- 当前唤醒与消息、身份、构造职责、近期黑板继续提供当下坐标。
- 笔记目录、todo、时间线、最近运行作为可引用的材料块，入口显示范围、数量、大小和展开方式。当前场景需要的部分才展开；目录截断或只取最近一段时明确写出未覆盖范围。
- 既有 recent 中的 `@ref` 用于留下下一次构造建议先看的材料。沉淀或反思可凭刚经历的事情调整这些入口，构造也可以当场拒绝、补充或更换。选择建议和原始材料都仍有出处。

这样，构造开场的知识一部分由前一次计算准备，新的现场继续校正它。新消息并不经过一个无背景的小分类器来决定“是否值得查记忆”；每次仍进入构造，现成路径只是可复用的起点。此取舍沿用[快路径撤回的结论](one-purpose-stateless-core.md#183-快路径撤回说话一律经过构造2026-11-01-续)。

这里的变更有真实代价：少展开材料会增加漏掉联系的机会，按需读取也可能增加串行延迟。若后续改变默认，需要保留完整目录与区间枚举入口，让构造能够请求对所关心范围逐项检查，并返回该范围的已检查、未检查、失败项；“搜到几个结果”不充当范围内读完的证明。

本轮接线没有撤掉全量开场材料。以后每块从默认展开改为入口时，都要能检查它遗漏过哪些有用联系，再让构造与其已有准备记忆决定选择。

## 怎样从使用中积累改进

每段记录 focus、选入材料、生成的结果和接续出处。无需给每一块强写一份理由；选择发生改变时留下原因，就能复盘“为什么带进来、什么时候发现不需要、后来是否又补读”。

沉淀可以据这些轨迹改进现有笔记和入口。例如，把找运行态入口的有效路径写进已有自查 Skill；把人物笔记拆成当前印象与可展开经历；在 recent 给下次留下有用材料引用。她也可以记录“这个选择没有起效”，修订或撤掉先前建议。

原始轨迹是证据，笔记和 Skill 是可修改的理解。自动保存所有输出为热记忆、按使用次数自动晋级、为全部结论建立失效传播 DAG，都不属于第一版。版本变化提示能说明依据变过，是否影响当前结论仍由实际阅读判断。

## 那次 42 次调用会怎样处理

1. 用上下文概览直接区分首请求和当前请求，获得材料清单与接口 usage。无需先读数百行运行源码，也不会把调查追加的材料算成开场材料。
2. 如果还需核对组装机制，调用分身查相应入口，只交回函数位置、计量口径与依据。
3. 取得计量入口后，当前行动可 `reframe`：带入问题、统计结果、必要出处与尚未查明处，继续解释；此前的源码和失败探索留在旧 ctx。
4. 下一次同类调查能沿已留下的自查入口开始，仍可在代码变化或结果异常时回查依据。

这条路径中，观察入口直接消除已发现的绕行；最终答复交付和重新组装承担其它调查也会遇到的材料管理。它们分别解决问题，不能只因最终 token 减少就把功劳全部归给 reframe。

本轮删除 fork 拼接探索自语的交付职责，以真实工具所属 run 定位 current，并把换段时的上下文准备交给当前段；wake 认领、已读确认和最终清理仍由原有执行线负责。首请求概览覆盖系统头、工具声明、view、附件与末尾 hints，保存来源和大小而非整包请求正文。服务端 usage 与本地字符估算分别呈现，缺失不当作零。

## 真实使用中仍需观察

真实使用另看效果，不能用合成通过替代：

- 是否减少重复探索与无关材料，是否引入更多补读、误解或遗漏；
- 最终回应是否仍理解原问题、关系与表达的来路；
- 构造及子计算合计的 token、缓存、费用与端到端时间，而非只看主行动变短；
- 哪些目的适合追加、哪些需要分身或换段，失败后能否顺着引用找回缺失材料。

以长调查、短聊天、依赖较早关系经历的回应、调用有副作用工具的行动分别观察。人工挑选的样本只支持其覆盖范围；后续出现反例时回看材料选择与依据，修订策略或机制。若换段反复丢失必要材料或总成本增加，就保留旧段继续追加的能力，并撤回对应默认选择。
