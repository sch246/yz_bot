# `#hint`：给窗口存一段自动执行的代码

> 状态：已实现（2026-09-17；命令面与求值都在 `mods/chat.py` 内，见文末「实现注」）
> 最近更新：2026-09-17 15:56（`set` 切分取整段、求值改用 `py.loc` 副本）

## 背景

1. **用户看不出“循环还在不在跑”。** 一串 LLM 轮次里，循环继续和循环停下没有任何可见差别。
2. **“当前上下文用了多少”没有出口。** token 数只在 `chat.get_handler.handle` 里临时算完就丢，用户看不到。
3. **已有一个边界约定，但它不是自动信号。** link 的 `chatstart`/`chatend`（节点在 `data/storage/links.json`，条件 `柚子聊聊天$`/`柚子不聊了$`）会写入 `聊天开始`/`聊天结束`，`chat._selected_events` 撞到就 `break`。可是它们**只在用户说了那句话时才触发**——挂不上“循环结束”这件事（13:22 草籽指出）。

## 决定

`#hint` **本质就是文本管理**：给某个聊天窗口存一份自己的代码文本，和 `#prompt` 一系没有两样。至于“这段文本会在聊天结束时被自动求值并发送”，是**另一回事**，分开看（见第二节）——它不该混进命令本身的语义。

### 一、命令面：管理一段窗口文本

**模型（15:34 草籽定）**：只有**两份**配置，各是一个字典：

- **全局默认**：`storage.get("", "hint")`（`""` 命名空间是既有惯例，见 `storage.get("", "settings"/"links"/"chat_groups")`）
- **本窗口**：`getchatstorage()["hint"]`

**生效配置 = 两份按显式顺序合并**：`{**default_hint, **chat_hint}`（窗口的覆盖默认的，两侧都只认同名的 `code` / `on` 两个键）。不搞别的间接层。

- **发不发** = 合并结果里 `code` 非空 **且** `on` 为 `True`。
- **`on` 的缺省**：合并结果里没有 `on` 键 → 视为 `False`。
- **允许“只有 `on` 没有 `code`”的窗口配置**：想在本窗口单独关掉默认提示，写一个 `{"on": False}` 即可，`code` 仍从默认继承。
- **`#hint set <源码>` 写入的窗口配置是 `{"code": 源码, "on": True}`**（15:34：`set` 之后默认设成 `True`）。

| 命令 | 行为 |
|---|---|
| `#hint` | 切换**本窗口**配置的 `on`：写 `getchatstorage()["hint"]["on"]`，`hint` 键不存在就**就地创建**（故只写窗口级、**不波及全局默认**）；**并返回新状态**（无论开关到哪边都要有回话） |
| `#hint get` | 显示**合并后生效的** `code` 与 `on`（**只显示，不运行**），并标出 `code` 来自窗口还是默认 |
| `#hint set <源码>` | 写本窗口配置 `{"code": 源码, "on": True}`：`set` 之后的**剩余整段**原样取（首尾 strip，行内换行保留），过 `cq.unescape`；返回状态 |
| `#hint set`（无参） | **显式**清掉本窗口配置、回落全局默认（14:05 草籽：“显示覆盖”是“显式覆盖”的手误，含义取 A）；返回状态 |
| `#hint default` | 切换**全局默认**配置的 `on`（`storage.get("", "hint")` 的 `on` 键，不存在就创建）；返回新状态 |
| `#hint default get` | 显示全局默认的 `code` 与 `on`（**只显示，不运行**） |
| `#hint default set <源码>` | 写全局默认 `{"code": 源码, "on": True}`：`set` 之后的**剩余整段**原样取（首尾 strip，行内换行保留），过 `cq.unescape`；返回状态 |

**没有 `del`**（14:08 草籽）：窗口级“不用了”用 `#hint set` 无参清掉配置、或 `#hint` 切到关；默认级“不用了”用 `#hint default` 切到关。源码是劳动成果，toggle 不该顺手删掉它。

保存用 `storage.save()` / `data.save()`。

**op 专属**（13:22 草籽定）：hint 是**用户可写的代码、跑在特权环境、还每次聊天自动执行**，权限与 `.py`/`.link` 同级，比只改提示文本的 `#prompt` 高一档。

- `cond()` 派发前用 `op.is_op(context.current())` 判权；非 op 的 `#hint` **不接管**（返回 `False`）。
- 提醒复用 `op.require_op` 的节流约定，避免连点刷屏（13:58 待定 6 定为“对”：**不静默**，给节流提醒）。

### 二、这段文本如何被使用（另一回事）

**触发点**（13:22 确认）：`chat.chat()` 的 `finally`（`context.end_turn` 之后），且**仅当本次调用持有该窗口的一轮**。

- `while` 里每个 `return` 和异常都经过 `finally`——正好只要“循环停”这一个信号；
- 每轮 `_run_chat` 返回时不经过——不会“每句都刷”；
- `if not owner:` 的早退**不算**结束（那轮由别人驱动）；
- `window is None` 的单轮 chat 与 `.chat` 单句**不触发**（13:58 待定 2：没有“循环”，弹出来反吵）。

**求值**：
- **环境**：共享动态环境 `py.loc` 的**一份副本**（读名字照旧；代码里的赋值只落副本，跑完 `py.loc` 一个键都不多，见「实现注」），作者拿到的名字与 `.py`、link 一致（`sendmsg`/`getlog`/`storage`/`identity`…）。
- **语义**：**上升为 `py.eval_last(source, environment)`**（13:58 待定 4 选 b）——前面各行 `exec`，最后一行 `eval`；末行为空、以 `#` 开头、或结果为 `None` → 不发。顺手把 `link._eval_last` 那份私有实现改为调用它，消掉重复（**要紧接着 reload `py` 和 `link`**）。
- **注入名字**：`window`（`history.window(...)`）、`usage`（最后一次中心请求的事件文本 token 估算）、`event_count`（该请求里的不同正式事件数）、`context_limit`（该请求实际使用的事件数/token 上限）。后三项在中心 agent 仍活跃时冻结，不能等退出 agent 模式后再从原触发窗口猜。
- **输出**：发到窗口的消息自带 `#` 前缀（`"#" + cq.escape(str(result))`），`_selected_events` 因此跳过它——统计不回流进模型、也不自指。

**“已用上下文”**：`chat.context_usage()` 是唯一出口，hint 只调它、不自己算。**本地估算（13:22 定）**：即 `get_msgs(return_token=True)` 的 `used`（统计进上下文的那部分聊天消息文本 token）。零新状态；它是**下界**。

**同步发**（13:22 定）：`sendmsg` 本来就在每个 LLM 轮里同步调，结束提示没理由特殊，不走注入队列。

### 三、异常安全（13:58 新增，必须定死）

hint 是“用户写的代码、每次聊天自动跑”，**必然**会遇到写错、抛异常、`sendmsg` 失败。规则：

- 求值与发送的**任何异常都吞掉、只写日志**，**绝不抛回 `finally`**——否则用户一段烂代码就能污染聊天主流程的返回路径。
- 出错信息照现成惯例**用 `#` 开头发送**（同 `link._report_error` 发 traceback 的做法），因此同样不进模型上下文。

### 四、`#help [name]`（照 `.help`）

现在 `_subcommand` 只认 `#help` 无参（`name == "help" and not tail`），`#help hint` 打不出来。照 `mods/help.py` 的两级形态扩一下，**不加特判**：

- `#help`（无参）：列所有 `#` 子命令，`#{pattern} — {首行摘要}`。
- `#help <name>`：显示该子命令的**完整**说明；查不到 → 照 `.help` 的 `该命令不存在！`。
- `_SUBCOMMAND_HELP` 的第二项从“单行”升级为“可多行”说明，摘要取 `description.splitlines()[0]`（对应 `.help` 的 `cleandoc(__doc__).splitlines()[0]`）。
- `model` 有两行（`model`、`model <selection>`），按首 token 匹配会**一起列出**。

**不做 op 过滤**：单 `#help` **列出所有**（含 op 专属的 `hint`）；非 op 去执行 `#hint` 时才被拒。按 op 隐藏某项“可以有”，但当前不做——`#help` 是所有人的发现入口，为它加特判不值。

`#` 前缀由现成机制保证：输出经 `call()` 加 `#`，命令本身不进模型上下文。

## 被排除的做法

- **把开关拆成与代码正交的独立 flag（v4 的两级正交模型）。** 15:26／15:34 草籽两次否掉：不设独立的 `hint_on` / `hint_default_on`，而是让 `code` 与 `on` 同处一个字典、靠 `{**default_hint, **chat_hint}` 合并。少一层间接，也天然支持“只有 `on`”的窗口配置。
- **`.chathint` 独立模块 / `chat` 定义 on_end 钩子。** 会与 `chat` 形成双向依赖，而同阶段（FEATURE）没有依赖边就会重演 12:39 那种 `indegree=0` 乱序加载失败。`#hint` 活在整个 `chat.py` 内，**零跨模块加载依赖**——这是选它的硬理由，不只是“跟 prompt 一系更像”。
- **把 `聊天结束` 当触发点。** 那是 link 里“用户说了才发”的约定（13:22 草籽指出），**不是**循环停止的自动信号；而且它的语义是**可回看的上下文边界**，与“报告运行状态”不是一回事。混用会让用户重开聊天时被带上一行统计。
- **异步 / 走 `connect._events` 注入发送。** 见第二节“同步发”。
- **`#hint del` / `#hint default del`。** 14:08 去掉：不再有“删源码”这个动作，清除/关闭都用 toggle 或 `set` 无参。
- **provider 真值（问一轮拿 `prompt_tokens`）。** 13:22 定为本地估算：真值要新增一份“每窗口上次用量”的内存状态（重启即空）并在 `get_handler` 多写一处；而用户要的只是“大概用了多少”，不值这份状态。
- **写进 `py` 或 link 的通用求值路径。** 那是“执行任意代码”的入口；hint 是“某窗口每次聊天都自动跑”的求值，权限与事故面不同。（注：`py.eval_last` 只是**复用求值语义**，不是把 hint 挂进 `.py` 命令。）
