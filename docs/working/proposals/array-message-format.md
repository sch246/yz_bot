# 数组消息格式迁移：逐步放弃 CQ 字符串

> **长期方向，尚未实施。** 维护者 2026-09-23 将「放弃 CQ，使用数组消息格式」列为目标；这不表示生产 NapCat 已切配置，也不意味着现有历史、link 与命令的字符串语义可以直接删除。现行事实见[运行架构](../../architecture.md)，调查和原方案 B 的取舍见[消息表示](message-representation.md#b-换用-onebot-数组消息格式)。

## 要替换什么

当前入站 `message` 是 CQ 字符串；at、reply 与正文由 `mods.msgs` 的纯函数投影，原始字符串仍是记录和展示的权威。迁移目标是由设备发送数组段，让结构本身表达消息类型，而不是继续从文本正则反推 CQ。**这不是把每条旧 CQ 字符串再解析成数组就宣称切换完成。**

## 开始迁移前

1. 清点原始消息进入 chatlog、history、模型、link、命令和发送路径的位置，区分依赖「消息的意义」与依赖「字面 CQ 串」的消费者。先确定数组段怎样稳定渲染给仍需字符串的入口，不悄悄改变可配置 link 条件。
2. 用不接触生产实例的合成事件验证 reply、at、图片、纯文本与混合段在现有入口判定、回声记账和模型投影中的行为；分别说明旧格式档案重建和新格式实时事件怎样共存。
3. 只有验证了上述边界和回退路径，才单独安排 NapCat 的 `messagePostFormat: array` 切换；不得借文档计划直接修改设备配置或运行状态。

**尚未决定：**历史记录是否保留原样、模型/人类分别看到什么文本投影、出站 CQ 写法何时退休，以及原本以 CQ 字面量匹配的 link 规则是否迁移。这些要在对应切片到站时裁决，不把「选择数组方向」偷换成所有接口语义已定。
