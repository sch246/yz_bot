# GAM 与 Nemori 源码对照

> 状态：2026-11-01 源码阅读记录，不是运行合同，也不批准实现。读的版本是 GAM `565db2c`（2026-03-14）和 Nemori `d2a6dff`（2026-04-16），只读代码与提示词，没有运行。论文层的定位和边界见[研究地图](memory-and-self-evolution-research.md#按需组装与提前准备11-01-增补)。柚子一侧的事实对应当天的 main（经历日志重写已合入，生产迁移另行执行），以[运行架构](../../architecture.md)和[LLM 文档](../../llm.md)为准。

研究地图把这两个项目列为与新底座最接近的公开实现：GAM 主张保留原文、按请求在运行时组装，Nemori 用预测落差决定写什么。这里看它们的代码实际做了什么，再和柚子现在的做法逐项对照。

## GAM

[仓库](https://github.com/VectorSpaceLab/general-agentic-memory)里有两代实现，MIT 许可。

### `research/`：论文版

**写入。** `MemoryAgent.memorize(message)` 每次收一段文本，粒度由调用方决定。它让模型写一段 abstract，提示词里附上**全部已有 abstract**（逐行 `Page i: …`），用来统一人名和术语，同时禁止写入只在旧记忆里出现的信息。页由 `[ABSTRACT] …` 头和原文组成；abstract 列表只追加，带去重。

**读取。** `ResearchAgent.research(request)` 循环，类里默认最多 3 轮，README 示例用 5 轮。每轮四步：

1. **规划**：读全部 abstract，输出还缺哪些信息、用哪些工具、关键词、语义查询，以及要整页读的页号（最多 5 个，禁止编造）。
2. **检索**：多个关键词拼成一串做一次 BM25，取前 5；每条语义查询各取稠密向量前 5；按页号直接读页。结果按页去重。
3. **整合**：把新证据并入一份针对问题的事实摘要，删掉离题内容，禁止加解释，带来源页号。
4. **反思**：两次调用。先判断信息够不够；不够就生成最多 5 个后续检索问题，拼成一句，作为下一轮规划的请求。

整合和“够不够”始终对照**最初的问题**，后续问题只用于检索。abstract 全量列表就是目录，每次写入、每次规划都整份读，规模上是一个线性增长的单层目录。

### `src/gam`：现版，“agent 文件系统”

**写入。** 模型先为整份输入写摘要、分析该怎样切块和怎样写记忆，再按行号决定切点：以章节标题和话题转换为主，提示每块约 40–160 行，不留只有标题的块。每块生成英文 snake_case 标题、描述结构的 TLDR 和一段记忆摘要。系统按 TLDR 生成或调整主题目录，叶子文件存**原文**加标题与创建时间，每个目录的 README 写下属文件的摘要。增量加入时，先判断新内容归入已有结构还是另开顶层主题；每加入 5 次（`reorganize_threshold`），由模型提出合并、拆分、改名、移动并执行，再更新受影响目录的 README。

**读取。** `TextChatAgent` 把知识库概览和**完整目录树**放进系统提示，提供 `ls`、`cat`、`grep`、BM25 四个工具，多轮探索后输出 `<answer>`，附来源路径和置信度。

两代之间的转向很明显：从“abstract 列表加向量检索”换成“目录树、README 摘要、原文叶子和 grep”。这和研究地图记录的 LongMemEval-V2 AgentRunbook 结论同向，也和柚子现在的形状很接近。

## Nemori

[仓库](https://github.com/nemori-ai/nemori)，MIT 许可，存储用 PostgreSQL 和 Qdrant。

**缓冲与切分。** 消息按 `(agent_id, user_id)` 缓冲，是一对一助手的模型。未处理消息达到 `buffer_size_min`（默认 2）就触发处理；一次处理的消息达到 `batch_threshold`（默认 20）才调模型分段，否则整批作为一个情节。分段提示要求对话题转换高度敏感、“拿不准就切”，每段约 2–15 条，30 分钟间隔算边界，并且**允许不连续的下标**：交错进行的话题可以各归各段。

**情节。** 每组消息生成一个标题、一段第三人称叙述和时间戳。叙述要求写出谁、何时、讨论了什么、做了什么决定、**表达了什么情绪**，相对时间换成绝对日期。原消息存在情节的 `source_messages` 里。

**合并。** 新情节与已有情节按向量找候选（配置默认相似度 0.85、前 5 个），交给模型判断是否同一事件。合并时删除两条旧情节，存一条新的，原消息拼接保留。按代码推断，早先语义记忆的 `source_episode_id` 会指向已删除的情节，未运行验证。

**predict-calibrate。** 情节生成后：

1. 用情节向量取前 10 条已有语义陈述；
2. **预测**：只给模型这个情节的**标题**和这些陈述，让它重建“这一段大概发生了什么”，重实质、不重文风；
3. **校准**：把原始消息和预测放在一起，只提取“原文有而预测缺失或说错”的知识，再过四项价值检验：六个月后还成立、具体可搜、有助于预测用户需要、脱离上下文能懂。提示词明确跳过“暂时的情绪或反应”；
4. 没有已有陈述时，退回直接抽取。

**语义记忆。** 原子陈述句，只追加。与旧陈述冲突时两者并存，没有更新或失效标记。类型按英文关键词分类，中文陈述全部落进默认的 `identity`。

**检索。** 情节和语义各取前 10，向量（Qdrant）与全文（PostgreSQL）结果用 RRF（k=60）融合，一次检索，没有循环。

## 与柚子对照

| | GAM | Nemori | 柚子（2026-11-01 main） |
|---|---|---|---|
| 原文 | 论文版页内存原文；现版叶子文件存原文 | 情节内 `source_messages`，合并时拼接 | chatlog 存窗口原文；经历日志存给她看过的全部条目，稳定编号，只追加 |
| 切分单位 | 调用方给定；现版按文档结构切 | 批量按话题分组，允许交错 | 唤醒和交接段；没有按话题切 |
| 谁整理 | 固定流水线里的模型调用 | 固定流水线 | 她自己：当场写笔记、交接时补齐、夜间反思修订；observer 只提醒 |
| 记忆形态 | abstract 列表；现版目录树加 README | 情节叙述加原子陈述 | Markdown 笔记（人、群、global、recent、主题等）、日记、年鉴 |
| 写入过滤 | 要求保留全部重要信息 | 预测落差加四项价值检验，丢掉情绪 | 她自己判断，没有固定过滤 |
| 修改与冲突 | abstract 不改；现版目录可重组 | 陈述只追加、冲突并存；情节合并删旧条目 | 笔记改写前备份到 `.history/`，每个版本在日志里是一条条目，旧依据仍在 |
| 召回入口 | 全部 abstract 作目录，加 BM25、向量、页号；现版目录树加 grep、BM25 | 向量加全文，RRF 融合 | 开局目录（按修改时间最多 60 份，每份列首行前 80 字，报告遗漏数）；每次唤醒自动带人和群笔记（最多 20 份）；面包屑按笔记名和别名子串匹配；`search` 按子串查聊天、笔记日记和归档段；`read_log`、`read_actions`、`read_context` |
| 召回循环 | 论文版固定四步、最多 3 或 5 轮；现版由 agent 自由探索 | 单次检索 | 她在一次唤醒里自己多次调工具；`fork` 可带引用开分身 |
| 评测 | LoCoMo、HotpotQA、RULER、NarrativeQA | LoCoMo、LongMemEval | 没有固定基准；[回放实验](memory-replay-evaluation.md)与[估值提案](memory-valuation-and-index-evolution.md)在研究中 |

## 读出来的几件事

**GAM 的召回循环不让材料改变问题。** 论文版的四步是“召回前辨认缺什么、召回后决定要不要再找”的一个最小可读实现。但整合和判断够不够都对照最初的问题，后续问题只是换一种检索说法。草籽 10-31 设想的[召回前后的计算](context-prediction-and-permeability.md#召回前后的计算以及笔记与搜索的共同调整)里，返回的材料可以改变问题本身；这一步 GAM 没有做。它的停止条件也只是轮数上限加一次模型自评。

**GAM 现版和柚子的笔记几乎同构。** 目录树、每个目录的摘要、原文叶子和 grep，对应柚子的笔记目录、首行描述、笔记全文和 `search`。差别有三处：GAM 的目录由模型按 TLDR 自动生成，每 5 次重组一次，柚子的笔记由她自己命名和组织；GAM 每个目录有一段 README 摘要，柚子的目录只有每份笔记的首行；GAM 把完整目录树放进每次查询的系统提示，柚子的开局目录有 60 份上限。

**Nemori 的“预测”是新意过滤，不是被未来检验的预测。** 它只用本段自己的标题做线索，落差衡量的是“标题加已知陈述推不出来的部分”。[基础讨论第四节](memory-foundations-discussion.md#四用预测统一写入与读取)说的预测，是由后来真实发生的事检验的预期，两者名字相同、做的事不同。Nemori 的做法仍可参考：写入时先问“我原本以为会是什么”，只记意外的部分。

**Nemori 的价值检验会系统性地丢掉情绪和关系变化。** 四项检验面向“长期了解用户”的助手：六个月后还成立、脱离上下文能懂，并明确跳过暂时的情绪。柚子的目标里有陪伴，[感性表达本身也是目的](context-prediction-and-permeability.md#感性与理性表达的目的滋养与裁剪)；原样搬过来，被过滤掉的恰好是她最需要记住的那部分。

**交错切分有现成写法。** Nemori 允许一个情节由不连续的消息组成，这是多人群聊里话题交错的一种直接处理。柚子现在按唤醒切，交错的话题由她在笔记里自己拆开。

**两者都没有处理好冲突和来源。** Nemori 冲突并存、不标记，情节合并后来源会断；GAM 的 abstract 写下就不再改。柚子用带版本的笔记加经历日志，旧依据和改动都留着，这一点更完整。缺的是“一条结论被后来的经历推翻”的显式记号，现在只能靠她改写笔记时自己写明。

## 不照搬的部分

- **固定流水线替她整理。** 两个项目都由外部流水线写记忆；柚子的设计是她自己写，研究地图“暂不引入”也排除了无来源的自动整理者。
- **另起一套存储。** PostgreSQL、Qdrant 和向量库都不构成引入理由；向量检索作为额外入口是否有用，可以离线单独测。
- **Nemori 的价值检验原样使用**，理由见上。
