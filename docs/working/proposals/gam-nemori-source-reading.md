# GAM 与 Nemori 源码对照

> 状态：2026-11-01 源码与论文对照记录，不是运行合同，也不批准实现。源码固定为 GAM `565db2c`（2026-03-14）和 Nemori `d2a6dff`（2026-04-16），只读，没有运行；论文版本及全文核对范围见下文。论文层的定位和边界见[研究地图](memory-and-self-evolution-research.md#按需组装与提前准备11-01-增补)。柚子一侧记录当天 main 的代码形态（经历日志重写已合入），不代表生产进程或数据已迁移，当前实现说明见[运行架构](../../architecture.md)和[LLM 文档](../../llm.md)。

研究地图把这两个项目列为与新底座最接近的公开实现：GAM 主张保留原文、按请求在运行时组装，Nemori 用预测落差决定写什么。这里看它们的代码实际做了什么，再和柚子现在的做法逐项对照。

## GAM

[仓库](https://github.com/VectorSpaceLab/general-agentic-memory)里有两代实现，MIT 许可。

### `research/`：论文版

**写入。** `MemoryAgent.memorize(message)` 每次收一段文本，粒度由调用方决定。它让模型写一段 abstract，提示词里附上**全部已有 abstract**（逐行 `Page i: …`），用来统一人名和术语，同时禁止写入只在旧记忆里出现的信息。页由 `[ABSTRACT] …` 头和原文组成；abstract 列表只追加，带去重。

**读取。** `ResearchAgent.research(request)` 循环，类里默认最多 3 轮，README 示例用 5 轮。每轮四步：

1. **规划**：读全部 abstract，输出还缺哪些信息、用哪些工具、关键词、语义查询，以及要整页读的页号（最多 5 个，禁止编造）。
2. **检索**：多个关键词拼成一串做一次 BM25，取前 5；每条语义查询各取稠密向量前 5；按页号直接读页。结果按页去重。
3. **整合**：把新证据并入一份针对问题的事实摘要，删掉离题内容，禁止加解释，带来源页号。
4. **反思**：两次调用。先判断信息够不够；不够就生成最多 5 个后续检索问题，拼成一句，作为下一轮规划的请求。

整合和“够不够”始终对照**最初的问题**，后续问题只用于检索。abstract 全量列表就是目录，每次写入、每次规划都整份读，规模上是一个线性增长的单层目录。

### `src/gam`：现版，“agent 文件系统”

**写入。** 模型先为整份输入写摘要、分析该怎样切块和怎样写记忆，再按行号决定切点：以章节标题和话题转换为主，提示每块约 40–160 行，不留只有标题的块。每块生成英文 snake_case 标题、描述结构的 TLDR 和一段记忆摘要。系统按 TLDR 生成或调整主题目录，叶子文件存**原文**加标题与创建时间，每个目录的 README 写下属文件的摘要。增量加入时，先判断新内容归入已有结构还是另开顶层主题；每加入 5 次（`reorganize_threshold`），由模型提出合并、拆分、改名、移动并执行，再更新受影响目录的 README。

**读取。** `TextChatAgent` 把知识库概览和**完整目录树**放进系统提示，提供 `ls`、`cat`、`grep`、BM25 四个工具，多轮探索后输出 `<answer>`，附来源路径和置信度。

两代之间的转向很明显：从“abstract 列表加向量检索”换成“目录树、README 摘要、原文叶子和 grep”。这和研究地图记录的 LongMemEval-V2 AgentRunbook 结论同向，也和柚子现在的形状很接近。

## Nemori

[仓库](https://github.com/nemori-ai/nemori)，MIT 许可，存储用 PostgreSQL 和 Qdrant。

**缓冲与切分。** 消息按 `(agent_id, user_id)` 缓冲，是一对一助手的模型。未处理消息达到 `buffer_size_min`（默认 2）就触发处理；一次处理的消息达到 `batch_threshold`（默认 20）才调模型分段，否则整批作为一个情节。分段提示要求对话题转换高度敏感、“拿不准就切”，每段约 2–15 条，30 分钟间隔算边界，并且**允许不连续的下标**：交错进行的话题可以各归各段。

**情节。** 每组消息生成一个标题、一段第三人称叙述和时间戳。叙述要求写出谁、何时、讨论了什么、做了什么决定、**表达了什么情绪**，相对时间换成绝对日期。原消息存在情节的 `source_messages` 里。

**合并。** 新情节与已有情节按向量找候选（配置默认相似度 0.85、前 5 个），交给模型判断是否同一事件。合并时删除两条旧情节，存一条新的，原消息拼接保留，新情节的 `metadata.merged_from` 保存两个旧 ID。需要纠正原记录中的“来源会指向已删除情节”：表定义是 `ON DELETE SET NULL`，因此按所附 schema 推断，旧语义记忆的 `source_episode_id` 会置空；未见把旧语义条目重新指向新情节的步骤。这是静态代码判断，未运行数据库验证。出处：[合并写入](https://github.com/nemori-ai/nemori/blob/d2a6dff6e5481214a0be6a2d10147feccfc16244/nemori/core/memory_system.py#L132)、[外键](https://github.com/nemori-ai/nemori/blob/d2a6dff6e5481214a0be6a2d10147feccfc16244/nemori/db/migrations.py#L37)、[合并元数据](https://github.com/nemori-ai/nemori/blob/d2a6dff6e5481214a0be6a2d10147feccfc16244/nemori/llm/generators/merger.py#L166)。

**predict-calibrate。** 情节生成后：

1. 用情节向量取前 10 条已有语义陈述；
2. **预测**：只给模型这个情节的**标题**和这些陈述，让它重建“这一段大概发生了什么”，重实质、不重文风；
3. **校准**：把原始消息和预测放在一起，只提取“原文有而预测缺失或说错”的知识，再过四项价值检验：六个月后还成立、具体可搜、有助于预测用户需要、脱离上下文能懂。提示词明确跳过“暂时的情绪或反应”；
4. 没有检索到已有陈述时，退回从情节标题和叙述直接抽取；这一路不直接读取原始消息。

**语义记忆。** 自动生成路径将原子陈述追加入库，未见语义冲突的自动更新或失效步骤；库另有显式删除接口。类型按英文关键词分类，不命中这些关键词的中文陈述落进默认的 `identity`。

**检索。** 情节和语义各取前 10，向量（Qdrant）与全文（PostgreSQL）结果用 RRF（k=60）融合，一次检索，没有循环。

**LoCoMo 的页粒度存在论文与源码差异。** 论文第 5 页统一说输入按 2,048 token 切页，没有交代 LoCoMo 例外。固定代码的 [`build_session_chunks_for_sample`](https://github.com/VectorSpaceLab/general-agentic-memory/blob/565db2cc2518d377e44389b82aecf3cc129d5fe5/research/eval/locomo_test.py#L51) 则按数据集 `session_N` 取整段，附时间、说话者、消息 ID 和可选 session summary，之后[每个 session 调一次 `memorize`](https://github.com/VectorSpaceLab/general-agentic-memory/blob/565db2cc2518d377e44389b82aecf3cc129d5fe5/research/eval/locomo_test.py#L329)，没有按 token 再切。能确认的是此 commit 的脚本行为，不能倒推论文成绩究竟由哪一份脚本生成。现版 `src/gam` 的文件系统实现也没有在这篇 v1 中得到评测。

### Nemori：蒸馏、切分与情绪的证据

**predict-calibrate 对直接抽取。** 两版都把已经发生的情节作为待重建对象，依据其标题／cue 与相关旧知识生成预测，再与原始消息比落差；不是对尚未发生事件的前瞻预测。旧知识的召回本身使用了完整新情节的向量，因而也不能称为只凭事前知识的盲测。

v3 第 8 页表 3 在 LoCoMo 上，用语义记忆单独作答：predict-calibrate 的 LLM-judge 得分为 0.615／0.696，直接抽取为 0.518／0.623（依次 gpt-4o-mini／gpt-4.1-mini）。v4 改用 0–100 分，第 8 页表 5 的对应对照在关闭语义管理时为 **65.0／74.9 对 52.0／65.5**；开启管理时为 **64.6／74.7 对 51.7／66.0**。这里同时固定为“只用语义记忆”，才较接近蒸馏方式的比较；不能拿完整系统 73.0／80.8 与直接抽取比较后，把差额全归于预测。附录 D.1.6 与 D.2 的提示词也不只相差预测输入，筛选措辞不同，所以它证明的是这两个具体流程的成绩差异。[Nemori v3 §4.3](https://arxiv.org/pdf/2508.03341v3#page=8)、[v4 §4.4、表 5](https://arxiv.org/pdf/2508.03341v4#page=8)

**切分消融在 v4 才有。** v3 逐条消息调用边界检测器（置信阈值 0.7、最大缓冲 25 条），没有单独的切分消融。v4 改为默认每 20 条观察窗口内分组，再跨窗口合并相同事件；第 8 页表 5 将自适应分组换为固定 20 条块，LLM-judge 从 73.0 降为 68.0、从 80.8 降为 75.7，即下降 5.0、5.1 分。它未单独删除跨窗口情节合并，也未测试多人群聊。第 14 页表 11 中，gpt-4.1-mini 的窗口为 5／10／20／30／40 条时，整体分为 80.4／80.7／80.8／81.2／80.7，支持这组窗口范围内的稳定性，不是无限增大窗口的保证。[Nemori v3 §3.1.1、§4.1.4](https://arxiv.org/pdf/2508.03341v3#page=4)、[v4 表 5](https://arxiv.org/pdf/2508.03341v4#page=8)、[表 11](https://arxiv.org/pdf/2508.03341v4#page=14)

**没有情绪／关系变化专项成绩。** 两版 LoCoMo 都只分单跳、多跳、时间、开放域；LongMemEval 分偏好、助手信息、用户信息、跨会话、时间、知识更新。v4 附录 D.1.2 要求情节叙述保留表达的情绪，D.1.6 又让语义提炼忽略暂时状态和情绪；D.2 的直接抽取还把关系列为保留类别。因此能说语义支路有过滤倾向，不能说整套系统必然丢掉情绪或关系变化，更不能用总体问答分证明陪伴表达改善。[Nemori v4 表 2、表 8、附录 D](https://arxiv.org/pdf/2508.03341v4)

### Nemori v4 与固定代码未完全对应

- v4 §3.3.3 与附录 D.1.7 有语义 `new/merge/conflict`，冲突时替换旧条目；固定代码的自动生成路径只有 [`generate` 后 `save_batch`](https://github.com/nemori-ai/nemori/blob/d2a6dff6e5481214a0be6a2d10147feccfc16244/nemori/core/memory_system.py#L164)，没有接上这套语义管理。只追加是这个 commit 的实现事实，不是 v4 的完整方法描述。
- 论文主实验检索为 10 条情节、20 条语义，附前 2 条情节原文，使用向量相似度。固定代码默认 10／10，使用向量与全文融合。论文的检索成绩不能直接归给当前混合检索实现。
- v4 附录 D.1.6 的比较提炼提示要求保留预测遗漏的长期事实；“六个月后还成立”等四项测试写在 D.2 的直接抽取提示中。固定代码把这四项测试也加到[比较提炼提示](https://github.com/nemori-ai/nemori/blob/d2a6dff6e5481214a0be6a2d10147feccfc16244/nemori/llm/prompts.py#L93)，并明确禁止语义陈述包含时间／日期（第 133 行）；这与 v4 附录 B.1 用预先提炼的绝对日期解释时间推理优势不同。是否实际损害成绩未复现。
- 固定代码在[未召回旧知识时直接抽取情节叙述](https://github.com/nemori-ai/nemori/blob/d2a6dff6e5481214a0be6a2d10147feccfc16244/nemori/llm/generators/semantic.py#L48)，而论文直接抽取对照的输入写作 raw episode。上述消融的结论应停留在论文所声明的配置，不能当成这个 fallback 的实测成绩。

## 读出来的几件事

**GAM 固定最终任务，但允许材料引出新子问题。** 论文版的四步实现了“召回前辨认缺什么、召回后决定要不要再找”。整合与充分性检查一直对照原始任务；但后续问题由已整合的事实和缺口生成，可能引入新的实体、因果线索与检索方向，不能只算作换一种说法。论文附录第 17 页的 follow-up 提示与固定代码 `research()` 都支持这个区别。草籽 10-31 讨论的[召回前后的计算](context-prediction-and-permeability.md#召回前后的计算以及笔记与搜索的共同调整)还允许重划原来的问题和判断范畴；GAM 没有明确改写顶层任务的步骤。它的停止条件是轮数上限与模型对材料充分性的自评，这项自评不是外部验证。[GAM v1 附录](https://arxiv.org/pdf/2511.18423v1#page=17)

**GAM 现版和柚子的笔记有相似入口，保存的内容与整理者不同。** 两边都能列文件并搜索，但 GAM 叶子保存原文，柚子笔记是她自己写的理解，原始经历另存日志。GAM 目录由模型按 TLDR 生成、每 5 次加入后重组，每个目录有 README 摘要，并把完整目录树放进查询提示。柚子的笔记由她自己命名和组织，代码中的开局目录有 60 份上限。不能仅凭“目录＋搜索”认定二者结构等价，生产提示实际带入哪些材料另待核验。

**Nemori 的“预测”是新意过滤，不是被未来检验的预测。** 它只用本段自己的标题做线索，落差衡量的是“标题加已知陈述推不出来的部分”。[基础讨论第四节](memory-foundations-discussion.md#四用预测统一写入与读取)说的预测，是由后来真实发生的事检验的预期，两者名字相同、做的事不同。Nemori 的做法仍可参考：写入时先问“我原本以为会是什么”，只记意外的部分。

**Nemori 的语义支路排除暂时情绪，整体记忆仍保留另一条路径。** 固定代码的四项检验面向长期用户知识，明确跳过暂时情绪，但情节叙述要求保留情绪，原消息也还在，关系本身属于语义抽取类别。柚子的目标里有陪伴，[感性表达本身也是目的](context-prediction-and-permeability.md#感性与理性表达的目的滋养与裁剪)；这让该过滤条件是否合用成为需要核对的问题。论文没有情绪或关系变化的专项实验，不能由提示词直接断言整个系统丢失这类材料，或已经证明不适合陪伴。

**交错切分有现成写法。** Nemori 允许一个情节由不连续的消息组成，这是多人群聊里话题交错的一种直接处理。柚子现在按唤醒切，交错的话题由她在笔记里自己拆开。

**冲突处理与来源保留须按版本和路径分开看。** 固定 Nemori 代码没有自动语义冲突处置，旧情节合并后，旧语义来源按 schema 会置空；合并情节仍存原消息和旧 ID。v4 论文则描述了语义冲突替换。GAM 的 abstract 只追加，但页保留原文，研究整合也带来源页号。因而不能把它们概括成“没有来源”。柚子 main 的版本笔记与经历日志保留了另一种修订过程；是否有“一条结论被后来经历推翻”的明确记录，以及这些记录能否实际帮助重审，仍需另查，本文没有做运行比较。

## 不照搬的部分

- **固定流水线替她整理。** 两个项目都由外部流水线写记忆；柚子的设计是她自己写，研究地图“暂不引入”也排除了无来源的自动整理者。
- **另起一套存储。** PostgreSQL、Qdrant 和向量库都不构成引入理由；向量检索作为额外入口是否有用，可以离线单独测。
- **Nemori 的价值检验原样使用**，理由见上。

## 待调查

源码与论文说明了机制和所报问答效果，但没有回答柚子自己的笔记是否接近“只写落差”、实际怎样召回、失败后会不会换问题，也没有证明这些方法能改善表达或长期积累。生产材料的只读调查另记；本轮未接触生产数据、调用模型或运行公开项目。GAM 的 LoCoMo 论文成绩与固定脚本的切页差异、Nemori v4 论文方法与固定代码的管理和提示词差异，仍不能靠静态阅读消除。
