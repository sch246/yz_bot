# 可自维护的同相上下文

> 状态：未实现的认知架构提案；本文记录北极星语义、已经形成的判断和需要证伪的假设，不描述当前运行行为。

当前事实仍以[交互模型](../../interaction-model.md)、[运行架构](../../architecture.md)和[运行边界](../../runtime.md)为准。本文不要求立即建立统一框架、消息 class、图数据库或自修改运行时；它先说明未来实现不能无意间封死什么，以及怎样区分真正的认知闭环与只把过程写进日志的表面相似。

本提案从多轮讨论中逐步形成；触发每次修正的关键原话、被推翻的中间理解和概念索引单独保存在[讨论来源与演化索引](self-maintaining-context-discussion.md)。本文负责凝练当前判断，讨论记录负责保留它的来路。

## 核心修正

目标不只是让 LLM 读到更多历史，也不只是建立分层记忆。更接近的描述是：建立一台以消息注入为主要节拍、又能跨多个时间尺度演化的外显循环机器。它以结构化 context 作为可读、可编辑的隐状态，以“LLM + 普通函数和工具”的一次或多次求值作为状态转移。

每条消息注入以后，生成回复的模型不一定直接看到最初的聊天窗口。当前 context 可以先经历检索、展开、压缩、抵消、分支、多次 agent 求值和规则选择，形成一个新的 context；最终回复只是这个新状态产生的一项外部效果。

```text
当前 context + 新消息
  → 中间 context₁
  → 中间 context₂
  → ……
  → 下一 context
  → 为最终回复专门构造的 context
  → 可见输出
```

这里真正需要外显的不只是事实和结论，还包括：哪些内容被选中或压低、使用了什么变换规律、产生过哪些中间状态、为什么选择某个分支、留下了什么未完成过程，以及这些过程怎样改变以后对消息的理解。

因此系统的基本单位不应预先假定为“笔记节点”或“函数调用”。更承重的候选单位是一次可重新引用、展开和求值的状态转移。

## Context 既承载状态，也承载操作

同相性不等于把消息、笔记、索引、prompt 和规则全部塞进一个带 `role` 的 JSON。统一外形只能减少转换，不能让数据与操作真正组合。

这里所说的同相性是：消息、笔记、草稿、索引、规则、agent 任务、中间结果和求值过程共享一种可以结构化组合的表示；同一片 context 可以在一个阶段作为被观察和编辑的数据，在另一个阶段参与产生下一 context。

可以用 Lisp 的三个动作理解这种角色变化：

```text
quote   让一片 context 暂停求值，成为可观察、可编辑的数据
eval    让一片 context 在给定环境和能力下参与求值
splice  把求值结果组合进后续 context
```

这不表示所有 context 语义相同。事实、假设、规则、草稿和副作用请求仍需保留来源、作用域、版本、置信、能力与提交状态等区别；同一种表示的价值，是这些区别本身也能进入 context，而不是藏在另一套无法由系统观察和修改的框架里。

本文尚未决定 context 的具体语法或能力模型；`quote/eval/splice` 只是辨认角色变化的语义参照，不是已经选定的操作语言。为了让最初的实验具有可验证的因果边界，至少需要一个暂不由实验对象同时改写的求值支点：更高层 evaluator 可以由 context 描述、检查和改写，宿主只完成当次最小归约、限制能力并决定何时提交外部效果。否则“关于操作的描述”和“正在执行的操作”无法区分，自修改也失去可检验的因果含义。这个支点以后能否进一步缩小或由同相 evaluator 重新表达，仍是未决问题。

## 求值轨迹先于静态关系

长期关系不一定首先表现为预先命名的图边。今天的消息与前天的内容真正发生联系，是因为某次状态转移同时消费了它们，并据此生成了新的 context。

```text
今天的消息 + 前天留下的 context + 当前变换规律
                    → 新 context
```

这次共同参与的导出过程就是最原始的关系证据。话题身份、索引、引用边和摘要可以在以后把它压缩成更便宜的结构，但不能取代它的来源。一个系统若只保存反应物和产物，不保存足以理解关系如何形成的求值切面，就仍然无法从局部维护自己的认知过程。

在这个视角下：

- 聊天消息、草稿和普通笔记是被冻结后仍可寻址的 context；
- 索引在被阅读时是折叠结构，在被求值时也可以是“怎样构造下一切面”的预测或操作；
- 黑板是当前求值环境中已经物化的工作集，不是长期知识的缩小副本；
- 话题是能跨越多次局部求值而重新恢复的结构，不必等同于一段连续时间；
- 一条主线是复杂潜在结构上的当前求值轨迹，而不是要求持久世界本身退化成一条线。

维护因此不是必须打开全局图。一次具体转移可以被 quote 成局部切面，展示它的输入、所见 context、所用操作、中间分支、结果和 continuation；修改其中一部分后再重放或用于未来求值。若编辑只能改变一份说明文字，后续状态转移并不消费它，系统仍然没有自维护能力。

## 外层结构也是预测机器

内层 LLM 把大量局部语义规律压缩进不可直接编辑的权重；外层 context 系统则把另一类预测铺成可见结构：未来什么可能被需要、哪些关系应当变得可达、当前应构造怎样的求值环境。

可以把最终回复粗略分解为：

```text
历史与当前消息
  → 外层 context 过程预测并构造下一有效 context
  → 内层 LLM 在该 context 中预测局部变换和输出
```

索引位置、折叠程度、话题激活、摘要、路由规律和黑板内容都在表达这种结构先验。新消息既提供内容，也检验此前对“什么会有用”的预测。

这里的预测对象不是抽象的“相关性分数”，而是：在一个约定的未来范围内，哪些 context、关系或操作会被后续求值实际读取，并帮助降低取得有效下一状态的代价。若结构长期把未使用内容放在近处、遗漏后来必须昂贵下钻的内容，或虽然命中却没有改善后续状态，它的预测就失败了。具体范围和代价函数仍需实验定义。

这条路径没有增加已经发生过的世界证据，但改变了证据之间的条件结构、可达距离和对当前任务的有效信息。LLM 权重还会带入先验并提出原始消息中没有显式写出的关系；这些新增内容是待后续检验的假设，不应伪装成已经观察到的事实。

## Chatlog 是发生轨迹，不是无偏地面真值

完整原始记录仍然重要：它提供来源、回看和重挖的最低边界；有损摘要不能取代它。[Chatlog 双向恢复提案](storage-and-history.md#chatlog-双向恢复)仍是建立历史访问能力的直接前提。

但“原始日志是唯一地面真值，所有其它东西只是单向投影”并不充分。柚子根据某个黑板和某套变换规律产生输出，输出改变群友接下来的反应，新的反应又进入日志。因而日志忠实记录的是某个历史策略实际走过的 on-policy 轨迹；换一套 context，未发生的反事实对话不会藏在日志里等待恢复。

投影由此会回流：

```text
日志与既有 context
  → 构造黑板和输出
  → 输出改变外部对话
  → 新事件进入日志
  → 成为以后 context 的材料
```

只保存入站和出站消息，也不足以重放这条认知轨迹。至少在比较或解释认知策略的实验中，还需能关联当时使用的 context、prompt 或规则版本、重要中间结果、工具观察、提交的状态变化和外部效果。需要保留到什么粒度仍未决定；本文只否定“聊天正文单独足以成为认知过程真相源”这一过强假设，而不是在这里预定新的日志字段。

自我描述尤其具有回流性。柚子写下关于自身的笔记后，这篇笔记可能进入未来 context 并改变她的行为；它既是描述，也是塑造后续事实的行动。世界观察、关系假设、自我模型与操作规则可以共享表示，但必须保留各自的来源和可修订性。

## 经验既包含走过的路，也包含没有走的路

被否决的候选、失败的探索和当时成立的限制会逐渐形成未来求值的河道。只记录“最终做了什么”会丢失 `why not`，使系统不断重试旧失败，或在条件已经变化后继续服从一个不可见的旧禁忌。

负向经验不等于永久禁令，也不要求保存每个模型产生的全部分支。它至少要求系统能在重要取舍上保留：当时考虑过什么、为何没有采用、依据来自哪里、适用范围和重新检查的条件。以后展开这一切面时，柚子能够重新判断河道是否仍然帮助水流，而不是把历史经验当作不可侵犯的边界。

`why not` 只有进入以后求值才构成经验：例如过去因某个条件否决的候选再次出现时，后续 context 能读取原理由、检查条件是否仍成立，并据此继续抑制或重新开放该分支。若否决理由只存在于审计文本中，从不影响也不能被未来状态重新检查，它仍不是河道的一部分。

这也修正了“检索未命中就是损失”的简单闭环。未命中可能表示：

- 结构没有把后来需要的内容放在近处；
- 查询或路由选错了方向；
- 世界真的出现了新内容，旧结构本来就不该命中；
- 系统正确承认未知；
- 既有滤镜已把对话引向自己熟悉的范围，使表面命中率虚高。

因此未命中可以成为预测误差信号，但不能直接等同于损失。一个只优化命中率的系统，可能通过不断收窄话题和重复自身来得到漂亮指标，并在此过程中失去感受新信息的能力。

未来评估至少需要同时观察两种方向：

- 可达效率：真正需要的 context 是否已在近处，构造它需要多少下钻、token 和 agent 求值；
- 开放程度：新话题和反例能否进入，黑板是否被陈旧结构垄断，系统是否仍会重新检查高置信但久未验证的河道。

持续出现一部分需要重新理解的内容不是纯粹故障，而可能是系统仍与变化环境接触的代谢。探索配额、无既有索引的重新阅读、旧结论的置信衰减或其它扰动机制都是待验证候选，不在本文中提前规定为答案。

## 多个时间尺度上的自修改

每条消息后的快速循环与每天、每月的慢速巩固具有相同形状：读取一组 context，经过求值，生成新的 context，并可能修改以后使用的变换规律。睡眠式离线整理可以作为大范围重放、比较和谨慎提交的候选窗口，但“只有睡眠才能改规则”不是本体要求。

更重要的不变量是：一次已经开始的原子求值必须知道自己采用哪一版语义。运行中产生的新操作可以成为下一次状态转移的输入，不能让同一次求值前后悄悄换律而失去解释边界。

可能存在多种时间尺度：

```text
一次 agent 求值内    使用固定的当前语义
消息与消息之间       改变注意、局部操作或 continuation
一段会话之后         重组草稿、主线和局部索引
每天的慢循环         重放经验并提出巩固或规则修改
更长时间尺度         调整高层先验并重新检验旧结构
```

不同尺度是否真的需要不同机制尚未决定。项目当前以完整重启作为代码和复杂运行状态的原子切换边界；新的认知循环不能让动态自修改吞掉明确命令、取消、权限和重启等恢复入口。

## 与当前实现的边界

当前系统没有上述认知运行时：

- OneBot 事件以普通 dict 进入唯一消息路由；
- `mods.context` 持有当前事件与 continuation；
- `mods.history` 持有每个窗口近期 256 条事件；
- `mods.chatlog` 追加完整可读聊天历史；
- LLM 每次从当前窗口近期历史重新构造请求；
- link 是有序列表中的首个命中反应，不是会自我维护的 context 求值图。

这些职责见[运行架构](../../architecture.md#唯一消息路由)和[交互模型](../../interaction-model.md#入口有优先级)。提案不能把愿景倒写成现行事实，也不能在没有证据时用统一 Session、Manager、DTO、图数据库或 agent 框架覆盖已经证明有用的普通 dict、函数、线性优先级和直接能力。

后续实验仍必须保护现有用户可见不变量：明确命令和取消入口优先、continuation 的交互线范围、群共享与私聊隔离、不同状态各自的归属，以及动态部分损坏时可观察、可禁用、可重启恢复。

## 最小可证伪实验

第一个实验不验证“笔记系统是否好用”，只验证自维护 context 是否具有因果意义。

1. 准备几条交错的合成消息，使其中一条主线在后面才显出需要特殊处理的规律。
2. 初始 context 不包含这条规律；一次中间 agent 求值根据已经出现的消息生成一片新的操作 context。
3. 把这片操作组合进下一状态；让后续消息的状态转移实际读取并使用它。
4. 保留这次求值切面，展开并修改刚生成的操作，再从相同提交点重放；重放只重新计算纯 context，已发生的外部效果作为观察输入而不再次执行。
5. 设置两个对照：禁止注入该操作，以及在后续消息处理完成后才注入。

作为这个首轮实验的操作性判据，只有同时观察到下面的因果链，才算出现了所要验证的最小认知程序：

```text
运行中产生操作
  → 操作进入后续 context
  → 后续求值实际消费操作
  → 下一状态发生可辨别变化
  → 编辑操作并重放会相应改变结果
```

若操作只存在于日志、解释文本或不可执行的笔记中，后续行为没有读取它，这个实验应判定失败。

第二类实验用于检验结构预测而非只证明自修改：按时间顺序用早期消息形成 context，再观察以后真实需要的内容是否已在近处，同时记录错误激活、长期占据黑板的无关内容、新内容进入率和昂贵下钻。重放只能比较同一段历史上的候选策略，不能消除日志本身受旧策略影响的 on-policy 偏差；这项限制必须留在实验结论中。

实验首先使用合成事件和纯 context 变换，不导入 `main.py`、不连接真实 QQ、不读取生产 chatlog，也不把模型产生的副作用发送到外部。只有当模型的不确定行为本身成为待测变量时，才需要在受控环境中调用真实 LLM。

## 尚未决定的问题

- 什么是足以支持组合和求值的最小 context 语法；统一表示应落到多深？
- 哪个最小 evaluator 必须留在宿主层，哪些求值规律可以安全地进入 context？
- 一次求值轨迹要保留什么，才能兼顾可维护性、成本、隐私和后续重放？
- 如何区分观察事实、模型假设、自我描述、规则与副作用请求，同时不重新长出彼此隔绝的多套语言？
- 局部切面修改如何发现自己可能破坏的不可见状态范围、权限和恢复不变量？
- 哪些负向分支值得保留，何时衰减或重新检查，怎样避免 `why not` 本身变成新的垃圾堆？
- 如何区分有害未命中、正确未知、新颖性和由系统自身引导产生的虚假高命中？
- 当下 observation 强烈反驳既有经验或规则时，如何让当前求值暂时停止受其支配，同时保留双方等待后续复审，而不是立即永久改写或一直服从到慢循环？
- 快速在线适应、会话级整理和睡眠式巩固分别允许修改什么，怎样提交和回退？
- 如何评估反事实策略，而不把一次 on-policy 历史误当成所有可能世界的代表？

在这些问题获得实验支持前，本文只确立方向和辨别标准，不预先承诺目录、类、存储格式或完整运行时。
