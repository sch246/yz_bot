## 1. 第一性公理（Axioms）

任何涉及大模型判断、上下文拼装与跨线调度的机制，必须同时满足以下五条公理：

- **A1（判据在场与预测备妥公理）**：语言模型能正确判断一件事，当且仅当判断所需的全部判据出现在它当前的上下文里。任何认知主体（从单条线到主线）本质上都在做**预测**（即将到来什么消息）或**声明**（准备接收什么相关消息），必须在信息到达之前备好判断所需的索引与痕迹。备好索引不等于展开全文，但**索引一旦丢失，主体就处于“不知道自己不知道”的盲区**。
- **A2（最小留存与注入不落库公理）**：任何内容进入或留存在某条线的上下文中，**当且仅当该线后续的运行需要它**。“程序现场查得到”绝不是把信息塞进上下文的理由；每多塞一条无关状态，就为后续每次决策平白增加一份干扰判据。当次求值前由程序现算的召回候选与状态提示，只能挂在当次请求尾部（瞬态 `Hint`），求值结束即丢弃，严禁写入持久历史（注入不落库）。
- **A3（负反馈必留公理）**：模型的记忆完全来自上下文；现实中执行过某个动作，不等于下一轮运行的模型知道自己执行过（默认参考系是“尚未执行”）。“刚刚做了什么、试过什么行不通、得到了哪些可能改变后续方向的印象”是抑制重复动作的负反馈栈帧，收尾与折叠**绝不为空**；但留下的形态必须是改变后续方向的紧凑印象，而非冗长的探索原文。
- **A4（衍生缓存可追溯公理）**：认知判断不能每次从原始记录现算（否则无法检索，也付不起算力），也不能脱离原始记录作为独立规则硬维护。所有事实、印象与经验判断都是**可追溯的衍生缓存**：平时以紧凑结论参与预测和检索，同时保留指向底层不可变原子的引用号，需要核对原委时可无损展开，来源永不抹去。
- **A5（单写者串行权威公理）**：每条线的内部状态，以及每个不可并发的外部副作用端口（聊天窗口对外发言、嘴、手机控制等），各自只有一个串行写入者。跨线影响必须通过向目标线发送消息、由目标线在自身轮次内整合完成，禁止并发直接改写他线状态。

## 2. 基本本体统一：原子（Atom）与线（Line）

系统持久层只有两种数据结构：**原子**与**线**。此前讨论中出现的“分叉、线程、窗口、目的线、对象线”，全部统一为**线（Line）**在不同运行阶段的切面，不再划分类型。

### 2.1 原子（Atom）

原子是只追加、不可变的最小语义记录，带全局唯一引用号（`atom_id`）与时间戳、来源元数据。现有系统中的 [`journal.py`](../../../mods/chat/journal.py) 条目（收到消息、模型回复、工具调用与结果、折叠摘要）、[`chatlog`](../../chatlog-format.md) 消息行、笔记的历史版本，都是原子。

- **不可变性**：原子一旦落盘永不原地修改；后续修正通过生成新原子并改变线上的引用来实现。
- **无归属共享**：原子本身不属于某一次“会话”。同一个 `atom_id` 可以同时出现在任意多条线的引用列表里，物理存储只有一份。

### 2.2 线（Line）：`分叉 = 线程 = 窗口 = 线`

线是系统中**唯一**的有状态认知与并发主体。磁盘上的一条线只是一个普通数据结构：

```python
# 概念结构（落盘为普通 JSON / Markdown，不封装专有类）
{
    "name": "line:fix-build",          # 稳定可读名称（如 "person:alice", "line:fix-build", "line:main"）
    "aliases": ["构建修复", "插件编译"], # 供精确匹配与召回的别名列表
    "past": [...],                     # 指向过去的预测索引（事实/印象 + 上下文敏感额外索引，带 atom_id 来源）
    "present": [...],                  # 指向现在的原子引用序列（近期关键事件 + 已折叠的方向修正印象）
    "future": "...",                   # 指向未来的当前目标/未闭环空缺（空串表示当前无待办势差）
    "claimed_windows": ["g123"],       # 当前认领的热连接窗口标签
    "claimed_at": {"g123": "..."},     # 每个认领窗口最近一次活跃的时间戳（用于认领保鲜期衰减）
}
```

每条线配一个标准的双向消息端口（与 [`windows.py`](../../../mods/chat/windows.py) 及 [`mods/agents/__init__.py`](../../../mods/agents/__init__.py) 同构）。四个常用词对应的只是同一机制的不同侧面：

| 称呼 | 在统一模型中的真实含义 |
| --- | --- |
| **线（Line）** | 实体本身：带名称、别名、`过去/现在/未来` 原子引用序列与收发端口的持久单元 |
| **分叉（Fork）** | **生成或归约动作**：从父线当前前缀共享引用拉出一条新线，或在同一条线上替换压缩前缀 |
| **线程（Thread）** | **运行态切面**：当前有未处理唤醒、正占着执行器跑轮次的那条线 |
| **窗口（Window）** | **双向通信端口切面**：收发接口与外部通道（如 CLI 代理 `codex:code`、聊天房间端口）采用同一套非阻塞投递协议 |

> **关键区分：专注线 vs 外部群聊端口**。端口协议相同，不等于“一个 QQ 群就是一条自治的专注业务线”。围绕具体事项、人物或专题建立的**专注线**具有明确内聚边界——若划分得当，分发到它头上的消息本来就属于它的职责，在内部消化即可，无需再向外转发；而**群聊（如 `group:A`）除了提供现场对话连续性与串行对外发言口之外，没有任何主题共性**，任何人都可能随时在群里抛出任意话题。因此未认领的外部群消息必须先经主线（`line:main`）按关注目录分发（仅显式回复已认领专注线的追问可单跳续接并支持超界退回），而不能绕过主线把群当成封闭自治线（详见第 6 节）。

### 2.3 永久存在、零休眠成本与“势差归零”

“一条线程一直存在有什么问题？一直存在不就变成长期的了吗？”——在统一模型下，**所有线默认在磁盘上永久存在，不设“短时目的线”与“长期对象线”的类型界限，也不设孤儿分叉垃圾回收（GC）**。

1. **存在态与活跃态正交（休眠零成本）**：磁盘上存着一千条线，与当前有几条线在跑完全独立。活跃态仅由 [`attention.py`](../../../mods/chat/attention.py) 中的待处理唤醒集合决定；没有唤醒信号的线只是静态文件，占 **0 算力、0 线程、0 上下文 token**。
2. **长短周期自然涌现**：刚为某件具体小事分叉出来的线，起初 `future`（目标）占比大、`past` 很薄。若两轮办完后再无人提及，它就永久安静地留在磁盘上；若此后几天同一话题、同一个人或同一故障反复找上它，它的 `present` 在多轮交互中不断向 `past` 沉积，**无需任何类型转换或数据迁移，它自己就长成了长期线**（不同实体只是“过去”与“接续”的占比不同）。
3. **永久存在 $\neq$ 永久挂着订阅（显式 `close=True` 势差归零、防误清保护与窗口认领保鲜期 TTL）**：由于 `future`（当前目标）同时充当动态消息订阅声明（见第 4.1 节），若一条一次性分叉办完事回传后，仍把旧目标原封不动留在 `future` 字段里，数月后出现同关键词时系统会误以为它仍在等待该事项（幽灵订阅）。因此规定：**当一条线明确判断当前目标已办结或放弃时，显式传入 `close=True` 将 `future` 清空归零（势差 $= 0$）并释放窗口认领**；而为防止模型在日常多轮对话或阶段性 `compact` 时因省略参数、未调 `compact` 或顺手填 `"none"` / `""` 误把未办完的事丢掉，**凡未显式传 `close=True` 的普通轮次、自动整理兜底、省略 `future` 或传入 `""` / `"none"` / `"无"` 等占位词，一律默认原样保留现有 `future` 不变**。同时，**保留未办完的 `future` 绝不等于永久垄断聊天窗口**：窗口热认领附带活跃时间戳 `claimed_at` 与保鲜期（`CLAIM_TTL_SECS`，默认 2 小时）；若某窗口闲置超过保鲜期仍无交互，系统自动收回该窗口的 `claimed_windows` 认领，让后续新话题回到 `line:main` 重新接受 `cold` 分诊（线的 `future` 目标本身完整保留，可供主线 BM25 召回续接或通过显式 `[CQ:reply]` 硬连接直接重激活认领）；此外夜间换页归档（`roll`）在清空各线未折叠 `present` 前，自动将 `[first_id ~ last_id]` 原子范围与精简摘录折叠入日志、归并进 `past` 预测索引并同步写出 `handoff:<window>.md`（含 `line:main` 的 `handoff:me.md`），杜绝静默丢上下文。

## 3. 正交轴一：线系统与并发通信演算（Line / Actor System）

线系统只规定多条线之间的引用共享、派生、消息传递与寻址，不关心单条线内部如何整理记忆。所有操作均保持底层原子不可变。

### 3.1 四种基本操作语义

#### （1）新建分叉：`Fork(parent, name, target) -> line_id`

当父线 `P` 需要把一项子任务或需要独立收发消息的事项剥离出去时，调用分叉工具并传入可读名称 `name`（若同名线已存在且适用，见 3.2 节“先查后分”）与初始目标描述 `target`：

- **零拷贝共享前缀**：在分叉瞬间 $t_{\text{fork}}$，新线 `C` 直接引用父线 `P` 此刻的上下文前缀引用列表（`P.past + P.present`），不复制底层原子文本。若紧接着对 `C` 求值，100% 命中 `P` 已算好的 KV 前缀缓存。
- **分叉视野上界定理（Fork Horizon Bound）**：由零拷贝共享与公理 A1 直接导出——在分叉刚发生时，子线 `C` 与父线 `P` 拥有的信息完全相同；**`C` 后续有能力顺藤摸瓜展开或检索哪些深层材料，严格受限于分叉那一刻 `P` 已经持有的索引与痕迹**。`P` 自己已经丢失索引的东西，`C` 不可能凭空知道要去查。
- **分叉点非对称尾部追加**（使父子看到各自视角而共享同一前缀）：
  - **父线 `P` 追加**：`[tool_call("fork", {"name": name, "target": target}), tool_result(line_id)]`，工具**同步立即返回 `line_id`**，父线不阻塞。这一步无需程序额外拼接元数据行，父线上下文里天然同时留下了三样决策判据：**做过分叉这件事（负反馈） + 子线句柄 `line_id` + 子线正在追的目标 `target`（订阅声明）**。
  - **子线 `C` 追加**：`[fork_marker(target=target, source=P.name)]`，并将其 `C.future` 设为 `target`。子线一醒来就明确知道自己是分叉、初始目标是什么、办完或目标变更时该往哪个源线（`P.name`）回传。

#### （2）同线自我压缩与轻量改标：`Compact(L)` 与 `Future(L)`

压缩与分叉在线系统上是同一个原语：压缩就是**在同一条线 `L` 上保持身份不变的前缀归约**；而修改 `future` 目标与折叠 `present` 原文相互解耦：

- **轻量改标 `Future(L, future, close=False)`（[`line__future`](../../../mods/tools/line.py)）**：当本轮对话尚短、无需折掉 `present` 原文，只想单独立项或更新未闭环目标（或显式传 `close=True` 办结释放窗口）时直接调用，零折叠开销并同步写出 `handoff:<window>.md`（在线模式下调用 `handoff` 或直接改写 `handoff:<window>.md` 同样只同步 `future` 而不折叠 `present`）。
- **原地折叠 `Compact(L, summary, ..., close=False)`（[`line__compact`](../../../mods/tools/line.py)）**：`L` 在自身当前前缀末尾执行一次压缩调用（批量更新 `L.past` 事实索引、生成涵盖本段探索拐点的折叠原子 `fold_atom`；省略 `future` 或传 `"none"`/`""` 默认保留原 `L.future`，仅 `close=True` 清空 `L.future`）。
- 随后 `L` 将自身 `present` 中已被 `fold_atom` 概括的那段过程原子引用替换为 `[fold_atom_id]`（`fold_atom` 内部保留被折叠的原始 `atom_id` 列表以备追溯，满足 A4）。
- **引用安全保证**：由于替换只修改 `L` 自己的引用数组，底层 [`journal.py`](../../../mods/chat/journal.py) 中的原始原子丝毫无损；此前在 $t < t_{\text{compact}}$ 从 `L` 分叉出去的任何子线 `C` 所持有的旧前缀引用依然完好有效，互不踩踏。

#### （3）跨线消息、插话与超界交还：`Send` / `hand_back` 与慢工具自动后台化

向一条**已经存在**的线（无论是专注任务线 `line:fix-build`、人物/实体线 `person:alice`、外部 CLI 代理 `codex:code`、还是手机等串行端口线）发送消息、插话或回传结果，统一走单向非阻塞投递：

- **与 `Fork` 的前缀边界对比**：`Fork` 生成新线时继承的是**发送方（父线）的前缀**；`Send` 投递给既有线时，消息原子追加在**接收方 `recipient` 自己的前缀**末尾，双方上下文各自独立演进。
- **轮次边界并入与结束自主权**：
  - 若 `recipient` 当前休眠，消息进入其待处理批次并触发唤醒（由 [`attention.py`](../../../mods/chat/attention.py) 调度）。
  - 若 `recipient` 正在执行工具循环，新消息在当前工具轮次结束边界并入其 `present`（插话）。**外部新消息到达绝不强行中断或逼迫正在运行的线立即压缩收尾**；收到插话后是继续做、转向还是收尾回传，完全由 `recipient` 自己决定。
- **慢工具 5 秒自动转后台（全双工防卡死）**：任何前台耗时工具调用（如 [`host.py`](../../../mods/tools/host.py) 命令执行、代码运行等）超过约 5 秒仍未返回时，自动剥离为后台任务并立即返回任务句柄；当前线在步骤边界即可正常接收新插话或先行回复，待后台任务完成时再作为事件重唤醒该线，消除单轮长耗时工具造成的半双工“耳聋”。
- **超界交还 `hand_back(reason)`**：当某条消息因显式回复链（`[CQ:reply]`）或活跃认领直达专注线 `L`（见 6.2 节），而 `L` 对照自身 `future` 判断该消息已偏离本线职责或切换了新话题时，调用一次 `hand_back(reason)` 将该消息连同简短理由退回 `line:main` 重新分诊，无需硬着头皮越界处理。
- **串行端口互斥**：手机控制、同一聊天窗口的对外发送等物理上不可并发的副作用，各自受单写者串行锁与人工堤坝（[`#gate`](../../../mods/tools/meta.py)）保护（满足 A5）。

#### （4）只读看截面与前缀探针：`Inspect(L)` 与 `Probe(L, question)`

当一条线（如主线）只想了解另一条线 `L` 的进展而不需要打扰 `L` 转向时，严格区分**只读观测**与**发消息通信**：

- **看截面 `Inspect(L)`**：直接只读读取 `L` 已落盘的 `(name, past摘要, present最新折叠印象, future当前目标)`（等同于跨窗口读取交接笔记）。零模型调用、不唤醒 `L`、不往 `L` 的上下文里塞入“进展如何？”之类的管理噪音。
- **前缀探针 `Probe(L, question)`**：当截面摘要不够、确需向 `L` 的完整长上下文追问某个具体细节时，以 `L` 当前的原子引用序列为只读前缀，在末尾临时拼上短问题求值一次，取回答案后即丢弃该临时后缀。既 100% 复用了 `L` 的前缀缓存，又不修改 `L` 的持久状态，且彻底避免了两条单写者线互相同步等待回话造成的死锁。

### 3.2 寻址与关联发现：`名称 + BM25` 为主，`ID` 为即时句柄

跨线建立联系走两条互补通道，其中**语义关联是主通道**：

1. **主关联通道：`线的名称 + 别名 + 中文二元组 BM25`（天然关注目录）**
   - 每条线创建时赋予人类与模型直读的名称（如 `person:alice`、`line:refactor-mouth`）及按需生长的 `aliases`。
   - **零额外维护的全局关注目录**：磁盘上所有线各自的预测头 `(name, aliases, past, future[正在做什么])` 直接合成为全系统的关联索引——复用 [`notes.py`](../../../mods/chat/notes.py) 已验证的**中文二元组 + ASCII 词 BM25**（`similar`），**不索引 `present` 中的原始对话流水**，也无需单独维护第二张“谁关注什么”的登记表。
   - **ACT-R 水下岛屿衰减**：召回排序叠加 [`notes.py`](../../../mods/chat/notes.py) 的小时粒度量化激活度（`ranked`，$\ln \sum (T - t_j)^{-0.5}$）。近期常读写、正挂着未闭环 `future` 或高水位的线浮在水面以上；几个月前只跑过一次的分叉无需删除，激活度自然衰减沉入水下，平时不抢占预选名额，一旦未来输入精准命中其名称或冷门关键词又能重新浮出。
   - **先查后分（Reuse-before-Fork）**：派生新任务前，若名称或 BM25 已浮现出同主题的既有线，优先 `Send` 唤醒该既有线续接，避免同一件事碎成几十条近义分叉。
   - **对上下文有界性的核心贡献**：正因为任何沉睡或运行中的线都能随时靠 `名称 + 别名 + BM25` 重新召回，**主线与各父线完全不需要在自身上下文中永久背负一张“所有已知线 ID 注册表”**。
2. **即时精确通道：`ID`（`line_id` / `atom_id` / `reply_to`）**
   - `Fork` 刚返回的 `line_id`、`fork_marker` 里的源线标识、消息直接引用回复链（`reply_to`），用于在刚派发或刚收发后的短周期热路径上零歧义直达。
   - `past` 与折叠条目中记录的 `atom_id`，用于公理 A4 的精确溯源展开。

## 4. 正交轴二：单线记忆系统（Single-Line Memory System）

**仅一条线自身就已经是一个完整的记忆系统；记忆系统与线系统是两个相对正交的维度。** 线系统解决多主体拓扑与通信；记忆系统解决在任意单条持续运行的线上，如何围绕“预测未来输入并准备判据”来组织上下文，并在时间趋于无穷时保持每一块有界。

### 4.1 单线四段式结构与缓存排列顺序

单条线每次求值时，严格区分**持久消息前缀**与**当次请求尾部**（对齐 `messages` 与 `hints` 的分离）：持久消息按变化频率从慢到快排列为 `过去 -> 现在`（保证多轮 `assistant -> tool` 循环纯尾部追加、前缀 KV 缓存零失效）；而线上的持久状态字段 `future`（供动态订阅与 BM25 检索）在求值时与瞬态 `Hint` 一并作为不写入持久消息列表的请求尾部挂载：

```text
持久消息前缀：[ 过去 Past（慢变头部） ]  ->  [ 现在 Present（纯尾部追加/低频折叠段，含目标变更留痕） ]
当次请求尾部：                                                                              + [ 未来 Future（当前目标态） + 瞬态 Hint（门卫浮现） ]
```

1. **`过去（Past）`：面向预测的紧凑认知索引**
   - 构造是为预测服务的，`past` 中**仅存放后续最可能需要用到的内容索引，绝不在此展开历史长文**。
   - **事实与印象即索引**：通常所说的“事实 / 总体印象”本身就是最核心的常驻预测索引（每条附带 `atom_id` 来源指针；平时靠这几句话直接判断，遇到争议或需要细节时再顺指针展开原子）。
   - **上下文敏感的额外索引**：超出基础事实/印象之外的专项经验、历史关联线索引（例如某人的过往事件索引、某工具的踩坑条目）本身具有上下文敏感性，按线分支局部挂载（见 4.3 节）。
   - **逻辑沉积与情感沉积双轨并存**（源自[河道与岸](river-banks-and-voice.md)）：
     - **逻辑认知（石头与河岸）**：可压缩为明确结论或负向排除条件（“某接口不支持批量参数”），遇到新证据时**原地覆写修订**。
     - **情感认知（流量水位与峰值原话）**：情感一压缩成摘要就会失真。记录方式保留**峰值时刻的原话片段 + 当时的情绪水位**（衡量期望与现状之差的变化猛烈度）。高水位代表高驱动力，可漫过日常负经验形成的自然河岸（如开心时主动分享），但**绝不可漫过人工堤坝**（如 [`mods/tools/meta.py`](../../../mods/tools/meta.py) 中的 `#gate` 硬门禁）；随时间自然退潮，不在逻辑对错维度上被覆写。
   - **聚合节点（人是根 Root）**：像 `person:alice` 这类长期实体不是单一目标能概括的一条窄任务，而是辐射出多条关联线的**根（Root）**。其 `past` 除总体印象与事实外，将旧式按日期平铺的叙事流水账替换为**关联线索引**（每条仅记日期、事项名、关键拐点与目标线引用），按需由 BM25 浮现。

2. **`现在（Present）`：关键事件流与负反馈栈帧**
   - 存放上次沉积进 `past` 以来的**关键内容原子**与**已折叠的方向修正印象**。
   - **关键内容判据**（暂行工作判据）：**一个原子是关键内容，当且仅当另一条线、或这条线将来的自己会依赖它**。双方的外部发言（对方线依赖）、命中他线订阅的事件（他线依赖）、以及“试过某路不通”的碰撞拐点（未来的自己依赖以防重做）均属此类；纯只读中间探查在目的达成后即可折去原文。
   - **折叠即显意识浪花沉降**：两次关键事件之间的多轮工具探索，经 `Fold` 归约为一条非空印象——写明“刚做了什么、排除了什么、获得了什么改变后续方向的结论”（公理 A3）。

3. **`未来（Future）`：接续栈与动态订阅声明**
   - 本体数据是一段未闭环的栈（当前正在做什么、还缺什么结果），语义上指向尚未到来的那一段空缺（势差）。
   - **目标描述即订阅声明**：判断一条新消息与本线是否相关，唯一依据是该消息是否影响朝此目标推进的判断。**直接描述目标本身就是最准确的动态订阅声明**；严禁另外维护一份静态的“`我关注 xx 信息`”列表——静态关注清单是在写下那一刻对目标做的窄化投影，会漏掉事先没想到的关联信号，在单条线上制造自我滤镜。
   - 当本线中途修正目标时，可通过 `line__future`（不折叠 `present`）或 `line__compact` 更新，订阅范围随之自动更新；当事项彻底完结时，显式传 `close=True` 令 `future` 置空（势差归零）。

4. **`瞬态尾部（Ephemeral Hint）`：请求级门卫浮现**
   - 每次调用模型前，由程序根据当前输入现算：精确别名命中（`mentioned`）、BM25 关联线与关注目标召回（`similar`，含各候选线的 `future` 当前目标与 `past` 摘要），以及必要的端口未读状态提示。
   - 仅拼在当次 API 请求末尾，模型读完作答后即丢弃，永不落入 `past` 或 `present`（公理 A2）。

### 4.2 单线记忆的状态转移算子

单条线 `L` 内部的记忆演化完全由四个算子闭合驱动：

| 算子 | 触发时机 | 状态变换（`前 -> 后`） | 缓存与溯源性质 |
| --- | --- | --- | --- |
| **`Append(a)`** | 收到消息、模型输出或工具返回 | `present <- present + [a]` | 纯尾部追加，前缀缓存 100% 保留 |
| **`Fold(span -> f)`** | 阶段性探索到达拐点或上下文接近折叠水位 | 模型在同一前缀上生成非空方向印象原子 `f`（含 `covers=span`），`present` 中 `span` 替换为 `[f]` | 折叠点之前的前缀不变；原始 `span` 留存日志可追溯 |
| **`Sediment()`** | 事项完结、线空闲沉淀或 `present` 折叠条数超界 | 将 `present` 中跨事件成立的事实/印象原地合并入本线 `past`（涉及他线实体则通过 `Send` 发往对应实体线串行沉积），移出已吸收的旧 `present` 条目 | 重整慢变头部（低频发生），重建稳态长前缀 |
| **`Retarget(g', close)`** | 目标推进、转向（`line__future` / `line__compact`）或彻底办结（`close=True`） | `close=True` 时 `future <- ""` 并释放窗口认领；`close=False` 时忽略空串/`"none"` 占位词保留原值，或更新 `future <- g'` | 无需折叠 `present` 即可独立改标；仅 `close=True` 触发势差归零 |

### 4.3 正交耦合定律（线系统 $\perp$ 记忆系统的唯一交界面）

线系统与单线记忆系统各自独立定义，二者只在以下三个精确位点发生耦合：

1. **`Future` 充当路由谓词**：单线记忆中的 `future`（目标/空缺）直接作为线系统中消息关联与 `BM25` 预选匹配的订阅声明，不设第二套路由规则表。
2. **`Fork` 传递此刻的 `Past + Present` 视野**：分叉操作将父线当前的 `past + present` 引用完整共享给子线，决定子线初始可展开的索引上界（3.1 节分叉视野上界定理）。
3. **线自身充当上下文分支（Line as Contextual Branch）**：记忆系统中那些“上下文敏感的额外索引”之所以不会在全局堆爆，正是因为**每一条线本身就已经是一个天然的语境分支**——属于 `person:alice` 的专项经历索引只挂在 `person:alice` 线上，属于 `line:fix-build` 的编译排错索引只挂在该工程线上。进入哪条线（或从哪条线分叉），就自动激活了哪个分支下的局部索引，无需全局上下文承担全量索引成本。

## 5. 全组件有界性定理与证明（Boundedness as $t \to \infty$）

要让一条线在无限时间流（事件总数 $N \to \infty$）中持续接收消息而不崩溃，不能靠“分叉出去做完再压缩回来所以大概不会爆”的定性直觉，**必须严格证明每一次求值时活跃上下文的每一个组成部分都有与 $N$ 无关的常数上界**。

### 5.1 引理：仅靠压缩/分叉（“现在”）不可能实现无损无限吞吐

**证明**：设一条持续接收外部事件的线经历了 $k$ 次分叉或阶段折叠（随时间 $t \to \infty$，$k \to \infty$）。

1. 由公理 A3（负反馈必留），每次折叠或分叉返回留下的方向印象长度至少为某个正常数 $c_{\min} > 0$（不能折叠为空）。
2. 若系统只有 `present`（“现在”）而没有状态合并层：
   - 若保留全部历史折叠印象，则 `present` 的总长度至少为 $\sum_{i=1}^k c_i \ge k \cdot c_{\min} = \Theta(k) \to \infty$，必然突破模型上下文窗口与注意力分辨极限；
   - 若到达固定窗口 $W$ 后直接丢弃最早的折叠印象（FIFO 截断），则 $W$ 步之前确立但此后一直未重提的关键事实与负向经验（例如三个月前确认的某人忌讳或某宿主机禁忌）将连同索引一起彻底蒸发，违反公理 A1（“索引没了就真不知道自己不知道了”）。

因此，单靠“现在”的分叉与压缩不足以支撑无限运行；**必须存在能够将无界序列归约（Reduce）为有界状态寄存器的“过去（`past`）”层**。$\blacksquare$

### 5.2 五大组成部分的有界性构造与不变量

设任意时刻 $t$ 某条线求值时的总上下文长度为 $L(t) = |Past(t)| + |Present(t)| + |Future(t)| + |Hint(t)|$（其中父线上的分叉派发痕迹计入其自身的 `Present` / `Past`）。系统通过以下五条机制保证 $L(t) \le B_{\text{total}} = O(1)$：

| 组成部分 | 潜在无界增长源 | 有界化归约机制 | 复杂度上界 |
| --- | --- | --- | --- |
| **1. 单线 `Present`** | 轮内高频工具调用；跨轮折叠印象不断累加 | 轮内探索经 `Fold` 压为单条印象；当 `Present` 达到水位 $B_{\text{present}}$ 或空闲沉淀时，触发 `Sediment()` 将长期有效信息并入 `Past`，旧折叠退入磁盘归档（保留 `atom_id` 可查） | $\le B_{\text{present}} = O(1)$ |
| **2. 单线 `Past`（基础事实/印象）** | 若按日期追加“经历流水账”，长度随天数 $\Theta(t)$ 线性膨胀 | **严格禁止追加式流水账**。基础事实与总体印象采用**原地状态改写（In-place State Merge）**，只描述实体当前的收敛认知并更新来源 `atom_id`；其体积仅取决于实体有效属性维度，与运行时间 $t$ 无关 | $\le B_{\text{facts}} = O(1)$ |
| **3. 单线 `Past`（上下文敏感额外索引）** | 关联事项、历史分支与冷门踩坑随年份持续增多 | 双重约束：(a) **线即分支分片**——额外索引分散在各自所属的人物/工具/专题线上，不汇入全局；(b) **水下岛屿衰减淘汰**——单条线内部若额外索引超过预算 $B_{\text{extra}}$，按 ACT-R 激活度（结合情感水位权重）将长期未命中的低激活条目沉入水下（移出常驻 `Past`，留在磁盘上供 `BM25` 在未来相关时由 `Hint` 重新浮现，底层原子永不删） | $\le B_{\text{extra}} = O(1)$ |
| **4. 单线 `Future` 与主线/父线派发痕迹** | 待办目标越攒越多；主线高频分发外部消息导致派发记录无限堆积 | (a) `Future` 只存当前未闭环目标，更新走原地改写（`Retarget(g')`），完结即置空（`Retarget("")`），复杂子项通过 `Fork` 拆成独立线；(b) **主线“不出力”且同构归约**——外部原始对话长文不进主线持久前缀（收到文本 $\neq$ 留下原文），主线 `Present` 仅记简短 `[Fork/Send 派发 + 返回印象]`，并在达到水位时同样执行 `Fold -> Sediment`（或换日归档）合并入 `Past`；无常驻活跃分叉 ID 表，后续靠 `名称 + BM25`（检索 `future != ""` 或 `past`）召回目标线 | $\le B_{\text{future}} = O(1)$ |
| **5. 全局休眠线集合与 `Hint`** | 磁盘永久保留的历史线总数 $M(t) \to \infty$ | 休眠线占 **0 运行时上下文**；求值前门卫预选仅扫描各线预测头，按 `别名命中 + BM25 + ACT-R 激活度` 截取前 $K$ 条摘要拼入瞬态 `Hint`（且求值后不落库） | $\le B_{\text{hint}}(K) = O(1)$ |

综上，对任意运行时间 $t \to \infty$ 与任意总事件数 $N \to \infty$，任意单次模型求值的活跃上下文严格满足：

$$L(t) \le B_{\text{facts}} + B_{\text{extra}} + B_{\text{present}} + B_{\text{future}} + B_{\text{hint}}(K) = O(1)$$

且因底层原子只追加不删除、`Past` 保留来源指针、磁盘休眠线可经 `BM25 + 名称` 随时再浮现，系统在严格有界的上下文内保持全历史可追溯与可唤醒。$\blacksquare$

## 6. 外部消息分发：不出力主线（Dispatcher）、专注线边界与群的定位

面对多窗口并发到达的外部消息，消息应当绕过主线直投局部，还是先统一进入调度器（`line:main`）？如果回到现实组织管理与人体神经系统的运作方式，答案由**专注线的内聚判据**与**群的无共性本质**直接决定。

### 6.1 专注线的内聚判据 vs 群聊的无共性本质

1. **专注线（Focused Line）的内聚判据**：
   - 一条划分得当的线，围绕单一内聚事项、人物或专题建立。**如果一条线划分合适，分发到它头上的消息本来就属于它关心的范围，在它内部直接消化即可，根本不需要再往外转发**（若某条线运行中频繁需要把消息往外转交，说明它的职责边界从一开始就划错了）。
2. **群聊（`group:A`）为什么不是自治专注线**：
   - **群除了提供“现场对话连续性”之外，没有任何主题共性**。同一个群里上一秒在讨论构建报错，下一秒就可能转向聚餐或某人的私事。正因为群可能收到任何领域的消息，直接面对原始群消息的那一环，就**必须知道（或能随时召回）系统当前关心的所有事项**。
   - 倘若把每个群当成绕过主线直达的“自治业务线”，要么该群对全局正在推进的事项失明，要么就得给每个群补上全局反向订阅桥接与跨窗脉搏，等于强迫每个群都重造半个主线。
3. **群/聊天窗口端口的两个真实职责**：
   - **入站提供房间连续性切片**：外部消息照常落入 [`chatlog`](../../chatlog-format.md) 与 [`screen.py`](../../../mods/chat/screen.py) 维护该房间的近期对话上下文；当某条事件交由专注线处理时，完整的窗口连续性切片按引用附给目标专注线，让专注线看清对话现场，而不塞进 `line:main`；
   - **出站提供单写者串行发送口**：专注线决定往 `group:A` 说话时，经窗口级单写者串行锁与 [`#gate`](../../../mods/tools/meta.py) 人工堤坝直接发出（[`mouth.py`](../../../mods/chat/mouth.py) 保持默认关闭作为可选润色开关，不强制增加第二模型改写延迟与信息损耗），保证多条专注线不会在同一窗口抢话（公理 A5）。

### 6.2 现实管理机制映射：外围反射 + 不出力主线攒批分诊 + 硬连接快路径与 `hand_back`

借鉴现实组织管理与 `dsh-superagent` 验证过的工单订阅机制，外部输入走**外围确定性过滤 -> 冷启动经主线批量分诊 / 热连接单跳续接 + 超界交还**闭环，兼顾全局态势感知与单跳响应速度：

1. **外围确定性反射（下达的规则自治）**：
   - 明确命令（`.`）、取消逃生口（`^C`）、确定性规则（[`.link`](../../interaction-model.md)）、批次防抖与唤醒门禁（[`awaker.py`](../../../mods/chat/awaker.py)）构成不占模型注意力的基层反射，直接拦截或消化无需上升到认知层的信号；被拦下的异常边界保留轻量统计供夜里反思审阅，防止规则陷入带滤镜的正反馈循环。
2. **冷到达与未认领消息：先进不出力主线（`line:main`）攒批分诊**：
   - 凡无既有硬连接认领的外部消息，统一进入 `line:main`（持有稳定逻辑名 `line:main`，跨日归档时逻辑地址不变）。若 `line:main` 正忙于上一批分诊，新到达事件自动入批合并，下一轮一并看、一并派。
   - **为什么主线不会过载（“知道有哪些活跃，知道状态，它又不出力”）**：`line:main` 不跑调查工具链、不起草群聊回复、不在持久前缀中保留外部长对话（仅记一行精简到达头与 `[Fork/Send 派发 + 返回印象]`，完整 `screen.py` 切片只挂给目标专注线）。求值时结合常驻活跃态势与 `Hint` 中零模型开销的 `别名 + BM25` 关注目录召回，当场调用 `Send` 或 `Fork` 即结束本轮。
3. **热续接与硬结构连接（1 跳直达 + 认领保鲜期衰减 + 主线免唤醒留痕 + `hand_back` 兜底）**：
   - 当外部消息通过显式回复链（[`msgs.py`](../../../mods/msgs.py) 解析的 `[CQ:reply,id=...]`）直接回复某条专注线 `L` 发出的消息，或在某聊天窗口正处于唯一活跃专注线 `L` 的保鲜认领期内（`claimed_at` 距今不超过 `CLAIM_TTL_SECS`，默认 2 小时）时，属于结构明确的同一对话串：消息**单跳直达 `L`**（免去 `line:main` 额外模型调用），同时程序向 `line:main` 追加一条免唤醒的轻量 `follow_up` 留痕（保证主线下次醒来时全局态势不缺失）。
   - 一旦窗口静默超过 `CLAIM_TTL_SECS`，窗口认领自动释放（不清空 `L.future`），几小时或隔天的新话题自然回到 `line:main` 走 `cold` 分诊；若后续有人用 `[CQ:reply]` 显式引用 `L` 之前的发言，仍由轨道 1 直达 `L` 并在 `L.future` 非空时自动刷新窗口认领。若认领期内群友借旧串歪楼聊起无关新事，`L` 对照自身 `future` 调一次 `hand_back(reason)` 即可当场退回 `line:main` 重新分派。
4. **专注线的偶发横向转交（同构召回）**：
   - 专注线在自身职责内闭环运行；仅当执行途中偶然撞见明显属于另一关注领域的副产物（如排查代码时发现某人的行程变更）时，使用同一套 `BM25 + 别名` 关注目录召回目标线直接 `Send` 过去，或回传 `line:main` 统筹。

### 6.3 与“绕过主线直达”方案的对照：四类管理故障在根源消解

若违反上述结构，让外部窗口消息绕过 `line:main` 直接进入局部线，会立即陷入四类管理故障（也是此前试图用“跨窗脉搏 + 反向桥接”打补丁的根源）：

1. **跨窗因果失明（违反公理 A1）**：某人在 `group:A` 说“刚重启了构建机”，5 秒后在 `private:B` 问“怎么连不上了”。若 `group:A` 绕过主线，私聊消息里又没提 `group:A`，主线连 `group:A` 刚发生过事这一索引都没有（不知道自己不知道），根本想不到要去查 `group:A`。
2. **全局待办订阅漏检**：主线或 `line:book-dinner` 正挂着目标“等大家定好时间就订座”，讨论却发生在 `group:A` 里。局部线按公理 A2 不背负全局所有待办目标；若消息不经主线，两边同时沉默，订阅直接漏检。
3. **靠发聊天消息轮询进展引发语境污染与死锁**：主线因失明而被迫向局部线发普通消息询问“进展如何”，既污染对方上下文、白跑模型轮次，又会在对方忙于工具时面临同步等待死锁（而主线掌握态势后，即便偶需深查细节，也只需走 3.1 节零污染只读 `Inspect / Probe`）。
4. **定时器盲目抢话**：[`awaker.py`](../../../mods/chat/awaker.py) 唤醒主线时，若主线不知道某窗口 3 秒前正处于密集对话中，极易往里盲目投递冲突话题。

| 路由架构 | 外部消息直投局部（主线全盲） | 外部直投局部 + 脉搏/桥接补丁 | **外围反射 -> 冷到达经不出力主线分诊 / 热连接单跳续接（+ `hand_back`）** |
| --- | --- | --- | --- |
| 群与专注线的职责边界 | 混淆（把无共性的群当成自治线） | 混淆（靠补丁让每个群代行主线职责） | **清晰（群只管连续性与串行外发；专注线按职责内聚闭环）** |
| 跨窗秒级接续与全局态势 | 失明（不知该问谁） | 靠跨窗脉搏事后追平，仍有时间窗缝隙 | **天然完备（冷到达进主线 + 热续接附免唤醒 `follow_up` 留痕）** |
| 活跃与沉睡关注目标的匹配 | 漏检 | 需额外维护反向桥接规则 | **统一（主线直看活跃线 + BM25 召回全盘 `future/past`）** |
| 主线自身负载与响应延迟 | 极低（但丧失调度能力） | 中 | **低且快（主线不出力攒批派活；热连接单跳直达免二跳）** |

## 7. 反模式判例表、现有模块映射与预设工程默认值

### 7.1 反模式判例表（设计审查红线）

以下十四种做法均在推演或早期试写中被证伪，后续实现与评审直接作为否决项：

| 编号 | 被否决的做法 | 违反的公理或模型机制 |
| --- | --- | --- |
| 1 | 把上下文组织成单根前缀树或封闭 session 列表 | 原子组成的是引用网而非单根树；前缀复用可以发生在任意线的任意起点 |
| 2 | 在每个分叉或专注线的 `Hint` 里列出全局所有开着的线或无关窗口动态 | 违反 **A2**：程序查得到不等于该给模型看；无关判据直接导致上下文与注意力爆炸 |
| 3 | 以为“交接只存下一步待办，顺利执行完折叠就可以为空” | 违反 **A3**：模型没有上下文外记忆，不写刚做过什么就会反复重查重做 |
| 4 | 在人物/对象 `past` 中按日期无限追加叙事性“经历”段落 | 违反第 5.2 节有界性：把归档线压平为 $\Theta(t)$ 流水账，挤占常驻窗口且极少被读到 |
| 5 | 让沉淀脱离原始原子单独归纳静态规则，或反过来每次从原始原子全量现算 | 违反 **A4**：不缓存则无法检索计算，脱离原子引用则变成不可证伪的死教条 |
| 6 | 把预选浮现的目录、时间线或召回片段写入持久前缀落盘 | 违反 **A2**（注入不落库）：既造成历史体积膨胀，又因每轮微变打碎前缀 KV 缓存 |
| 7 | 分叉时复制文本或挑拣改写父线前缀 | 破坏零拷贝引用共享与 100% KV 缓存复用，违背 3.1 节分叉初始对称性 |
| 8 | 另设静态字段维护“`我关注 xx 信息`”过滤列表 | 对目标做静态投影会漏掉未预料到的相关信号（自我滤镜）；`future` 目标描述本身就是订阅声明 |
| 9 | 外部新消息一到就强行打断并逼迫正在跑的线立即压缩收尾 | 剥夺线的结束自主权（工作区 `mods/chat/line.py` 每次行动末尾强制收尾即犯此错） |
| 10 | 把所有窗口的对话原文都塞进全局唯一的 `main.json` 并整条借用 | 工作区 `mods/chat/line.py` 的核心错误：主线留了不该留的长原文，各专注决策被迫背负无关群全天记录，击穿 **A2** |
| 11 | 划分“短时目的线”与“长期对象线”两套类型，并设计超时孤儿 GC | 过度设计：休眠线落盘零成本，长短周期由唤醒频率自然涌现，靠 `future` 清空即可消除幽灵订阅 |
| 12 | 发明封闭的权限令牌表，只靠随机 ID 维持跨线可达性 | 忽略了主关联通道是 `名称 + 别名 + BM25` 关注目录；强行保活 ID 表只会重新制造上下文泄漏 |
| 13 | 把毫无主题共性的群聊当成自治专注线绕过 `line:main` 直达（再用轮询消息或跨窗脉搏打补丁） | 混淆房间连续性与职责内聚边界：绕过不出力主线会导致跨窗失明、订阅漏检与轮询污染，打补丁则迫使每个群重造半个主线 |
| 14 | 在自身提示词塞满逻辑负向规则（石头），或反过来给每次发言强制套一层高损耗第二模型改写 | 河道被石头塞满会导致腔调僵硬；但强制每句过独立第二模型也会带来高延迟、拒发与技术细节截断，因此默认清理河道直发，保留 [`mouth.py`](../../../mods/chat/mouth.py) 作为按需可选开关 |

按[设计原则](../../design-principles.md)“先辨认已被长期使用证明的小机制，用普通数据与函数组合”，本规范主要构件在现有仓库中已有对应实现：

| 规范构件 | 现有代码基础与演进动作 |

### 7.3 预设工程默认值（免前期决策拍板）

为避免切换试跑前陷入繁琐方案抉择，结合近期线上运行数据（`#construct off` + `#mouth off` 稳态表现）预先锁定以下五项默认工程取舍，开箱即跑：

1. **现有 `data/notes/*.md` 零迁移**：人物卡（`person/*.md`）、`todo.md` 与专题笔记继续作为实体长期知识的单写者真相源；`data/chat/lines/<name>.json` 存放线的 `{name, aliases, past, present, future}`，其中 `past` 仅保存该线自身提炼的状态摘要与 `@note` 引用指针，与 `#construct off` 100% 向后兼容。
2. **`#mouth` 默认保持 `off`**：线上实测关闭 `#mouth` 后消除了每次发言约 11.5 秒的额外等待、约 25% 的拒发损耗与短意图传话对技术细节的截断；对外发言默认走窗口串行锁 + `#gate` 直发，无需额外开启第二模型改写。
3. **`line:main` 精简到达头 vs 专注线完整画面切片**：`line:main` 的 `present` 在 `[Fork/Send 派发 -> 返回]` 之前只记录一行极简到达头原子，绝不塞入群聊长文；完整的 [`screen.py`](../../../mods/chat/screen.py) 连续性切片只挂载给真正接活的专注线 `L`。
4. **首次 `Sediment()` 自动解耦父线前缀**：新分叉 `C` 刚诞生时直接引用 `line:main` 的前缀以 100% 复用 KV 缓存；若 `C` 后续演进为多次唤醒的长期线，在执行它自己的第一次 `Sediment()` 时即提炼出独立 `C.past` 并卸下最初借用的 `line:main` 前缀，彻底切断历史耦合。
5. **两阶段读取游标（`claimed` vs `committed`）**：复用 [`attention.py`](../../../mods/chat/attention.py) 现成机制——消息分派给 `L` 时先标 `claimed`（防止连续追问被重复分派），仅当 `L` 实际产出有效动作或回复后才执行 `screen.commit_read` 与 `attention.ack`，中途崩溃或被 `^C` 打断时未读现场丝毫不丢。

*（其余纯数值水位——如触发 `Fold` 的上下文预算、空闲 10 分钟沉淀计时器、主线凌晨反思换页或按水位滑动、情绪水位 `0~3` 自标校准——均设为运行期可调参数，不阻塞首轮落地。）*

## 8. 可切换实现计划：从 `#construct off` 分步演进

当前线上运行的 `#construct off`（`handoff:<window>.md` 交接模式）已具备 100% 收尾遵从率且成本比旧 `#construct on` 降低一个数量级，是极佳的安全基线。它的主要天花板只有三处：(1) 每次唤醒从零重拼 `handoff_spec`，首请求缓存命中率卡在 69%~78%；(2) 每次唤醒末尾强制多跑第 2 轮收尾请求（哪怕本轮无事可做）；(3) 遇到长耗时命令时整条循环半双工卡住。

因此实现不搞一次性推倒重来，而是保留 `#construct off` 完整不动，在 [`subcommands.py`](../../../mods/chat/subcommands.py) 新增 `#construct line` 开关，支持运行中 **1 秒无损切入与回退（`#construct line` $\leftrightarrow$ `#construct off`）**，分三步渐进交付：

### 第 1 步：单线持久前缀 + 按需原地 `compact` + 慢工具自动后台化（最小可试切闭环）

这一步直接修掉 `#construct off` 的全部三处天花板，同时替换工作区里那版有缺陷的 `mods/chat/line.py` 草稿，无需维护者做任何额外配置即可切过去体验体感：

- **改动范围**：[`mods/chat/line.py`](../../../mods/chat/line.py)、[`mods/chat/agent.py`](../../../mods/chat/agent.py)、[`mods/chat/construct.py`](../../../mods/chat/construct.py)、[`mods/chat/run.py`](../../../mods/chat/run.py)、[`mods/chat/subcommands.py`](../../../mods/chat/subcommands.py)、[`mods/tools/meta.py`](../../../mods/tools/meta.py)、[`mods/tools/host.py`](../../../mods/tools/host.py)。
- **具体动作**：
  1. **按名隔离线文件**：将单一全局 `main.json` 改为按线名存储 `data/chat/lines/<name>.json`（`{name, aliases, past, present, future}`），持久前缀只放 `[past -> present]` 原子引用；
  2. **注入不落库**：笔记目录、时间线、未读提示与当前 `future` 一律改走请求尾部 `Hint`（`session.add_hint`），不再写进持久历史打断缓存；
  3. **取消每轮末尾强制收尾**：日常唤醒直接在原前缀尾部追加 `present`，**单跳完成**；仅当模型主动调用 `compact` / `handoff`、上下文接近水位或触发 10 分钟空闲沉淀计时器时，才在同一缓存前缀上跑一轮折叠并同步写出 `handoff:<window>.md`（因此随时切回 `#construct off` 都能无缝接着最新交接笔记跑）；
  4. **慢工具 >5 秒自动转后台**：前台命令超时未完即返回后台句柄，完成后推事件重唤醒该线。
- **验收标准**：`run.py --check` 与 `--smoke` 通过；切换 `#construct line` 后日常回复降为单轮请求，连续对话首轮前缀缓存命中率升至 90% 以上，长命令期间发消息可正常插话响应；切回 `#construct off` 零丢状态。

### 第 2 步：不出力 `line:main` 攒批分诊 + 专注线 `Fork / Send / hand_back` + `BM25` 关注目录

第 1 步单线持久体感跑稳后，打开多线并发与跨窗总调度：

- **具体动作**：
  1. 将一次性线程池 [`mods/tools/agents.py`](../../../mods/tools/agents.py) `agents__fork` 升级为持久 `Fork(name, target) -> line_id`（零拷贝共享父线前缀引用 + 非对称追加 `fork_marker`），并补齐 `Send` 与 `hand_back(reason)` 工具；
  2. 将 `data/chat/lines/*.json` 的预测头 `(name, aliases, past, future)` 接入 [`notes.py`](../../../mods/chat/notes.py) 的 `mentioned` / `similar`（中文二元组 BM25）与 `ranked`（ACT-R 激活度），形成零维护全局关注目录；
  3. 接通 6.2 节双轨路由：无硬连接的冷到达进入 `line:main` 攒批分诊（只派活不出力，完整 `screen` 切片挂给目标专注线）；命中 `[CQ:reply]` 硬连接或单人窗口活跃认领的追问单跳直达目标专注线，并给 `line:main` 记免唤醒 `follow_up` 留痕，偏题时由 `hand_back` 退回。

### 第 3 步：跨线单写者沉积（`Sediment` 合流 `settle.py`）与人物 `Root` 线索引化

多线调度稳定后，收拢长期记忆沉淀闭环：

- **具体动作**：将独立事后进程 [`settle.py`](../../../mods/chat/settle.py) 合流为线自身的 `Sediment()` 算子；专注线收尾时提取跨事件认知通过 `Send` 发往 `person:<id>` 等目标线单写者串行归并，将人物笔记中旧式按日期堆叠的叙事段落逐步替换为带情绪水位与 `atom_id` 来源的关联线索引。
