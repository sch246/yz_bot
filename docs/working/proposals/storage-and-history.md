# Storage 热同步与历史恢复

> 状态：未实现提案

## 可选文件热同步

Storage 可以在不改变现有 `storage.get()` 调用方式的前提下增加可选热同步，但内存和磁盘不是平等主库。Bot 运行期间内存是权威，磁盘是可人工编辑的持久投影；只有内存自上次同步后未变，外部文件才允许反向载入。两边都变时，内存覆盖磁盘，因为编辑器通常还有撤回/本地历史，而未保存运行状态没有第二份来源。

一个始终被监视的 manifest 记录 storage 逻辑路径和可选最小写盘间隔：

```json
{
  "watch": [
    {"path": "/links", "write_interval": "realtime"},
    {"path": "llm_system/description_cache", "write_interval": "1s"},
    {"path": "some_namespace/options"}
  ]
}
```

省略时默认 `10m`。间隔表示同一文件两次成功写盘的最小距离，不是每次变化后重新等待；窗口内的变化合并。文件启动加载或新加入 watch 时视为刚同步。`1s` 表示至少间隔一秒，`realtime` 表示 watcher 一检测到 dirty 就写，实际延迟仍受检测周期约束。显式 `storage.save()` 和退出保存强制 flush，不受节流限制。

Manifest 以磁盘为权威并热加载；解析失败时保留最后有效列表。时间使用 monotonic clock，只有成功原子写入才推进 `last_write_at`。

每个文件保存上次内存与磁盘一致时的规范 JSON 摘要 `synced_digest`。现有调用方直接修改裸对象，因此同步器只对 manifest 中少量对象定期序列化比较：

| 内存相对 baseline | 磁盘相对 baseline | 动作 |
|---|---|---|
| 未变 | 未变 | 无操作 |
| 未变 | 已变且 JSON 有效 | 原地载入内存，更新 baseline |
| 未变 | JSON 无效或文件缺失 | 保留内存与 baseline，报告并等待 |
| 已变 | 未变 | 到达写盘间隔后原子写回 |
| 已变 | 已变或磁盘无效/缺失 | 内存优先；到达间隔后原子覆盖，失败则重试 |

比较使用解析后、键排序的规范 JSON，忽略纯格式变化。写盘使用同目录临时文件加 `os.replace()`；退出保存、显式 save 和周期同步共用一个底层写函数。Dict 用 `clear()/update()`、list 用切片替换，保持根引用；第一版只支持这两种可变根，嵌套引用不承诺保持。

Watcher 遇到并发变化导致的快照失败时跳过本轮、下轮重试，不写空默认值。只有出现真实跨线程一致性问题时，才为具体写操作增加小范围锁或事务函数，不预先包装所有 storage 值。

## 加载校验

检查器保持为普通函数：`check(value) -> None`，失败抛带路径和原因的 `ValueError`。`storage.get(..., check=...)` 在功能第一次认领数据时验证，并记住函数供热加载复用；不引入 schema DSL、校验 class、自动迁移或自动修复。

- 文件不存在：调用方可显式使用 default；
- 文件存在但 JSON 无法解析：报错，不当作不存在；
- checker 不通过：报错，不安装进内存；
- 冷启动没有有效内存：必要数据使其 feature 启动失败，可选功能可明确禁用自身；
- 热加载失败：保留当前有效内存并等待修复；
- checker 自身异常：保留 traceback，不能退回默认值。

Storage 可先收集解析结果和 `load_errors`，到功能认领路径时再决定影响范围。无人使用的遗留 JSON 不拖垮 Bot，被真实依赖的坏配置也不会静默变空。

## Chatlog 双向恢复

Chatlog 继续以实时追加的人类可读文本为主，不保存冗余全量 OneBot JSON。为了从历史恢复消息列表，应定义最小规范字段：事件类型、聊天目标、发送者、时间、消息 ID、正文/CQ 和回复关系。

Formatter 与 parser 对这组字段应满足 round-trip，并为文本格式增加版本和可靠转义。未知或少见字段可以进入紧凑 sidecar，而不污染日常正文；恢复结果必须标明哪些字段是原始事实、缺省值或推导值。

## 最小验收

- 未列入 manifest 的文件保持当前退出/显式 save 语义；
- 仅内存变化按配置间隔原子写盘，仅磁盘变化原地进入内存；
- 双边变化由内存获胜；非法 JSON、缺失和写失败不推进 baseline；
- manifest 可热增删目标，自己写出的文件不触发循环 reload；
- chatlog 最小规范字段可以格式化后再解析回等价消息列表。
