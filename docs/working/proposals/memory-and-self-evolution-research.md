## 阅读规则

每条材料都区分三件事：

1. **原文机制或实验结果**：作者实际实现、测量或报告了什么；
2. **本项目迁移推论**：它为何可能帮助柚子；
3. **边界**：它没有证明什么，哪些部分不能直接照搬。

二手综述只用于发现材料。机制判断优先回到论文、作者仓库或官方文档；某篇论文在自己的任务上胜出，不等于它定义了普适的记忆价值、索引形状或自我改进方法。

## 当前问题图

外部工作大致覆盖四个不同问题：

| 问题 | 需要观察的后续消费 | 代表材料 |
|---|---|---|
| 长经历怎样在有限切片中保持可用 | 未来问题能否找到必要来源，而不是只看到模糊摘要 | ReadAgent、RAPTOR、Generative Agents、A-MEM、MemGPT、SLA |
| 怎样从成败轨迹形成可复用经验 | 后续任务是否实际加载经验，并发生可归因的行为变化 | Reflexion、Voyager、ExpeL、Dynamic Cheatsheet、ACE、JitRL |
| 系统能否改进产生改进的方法 | 新的诊断、实验选择或候选生成方法，能否在下一次改进任务中胜过旧方法 | ADAS、DGM、Gödel Agent、Hyperagents |
| 怎样评价而不让结构指标冒充目标 | 检索、阅读、使用、迁移、保留、成本与安全能否分开报告 | LongMemEval、MemoryAgentBench、LongMemEval-V2、自演化综述 |

因此至少要分开两条能力链：

```text
经历 → 候选记忆／工具模块做法 → 后续聊天或检索任务实际使用

改进经历 → 候选诊断／实验／候选生成方法 → 后续改进任务实际使用
```

第一条成功只能说明任务层学习发生过；它不能单独证明系统更会自我改进。第二条还要在未参与方法形成的新失败上，比较旧、新改进方法产生的候选及其后续表现。

## 为什么同一批问题反复出现

这些工作通常不是在相同条件下竞争同一个完整解。它们先选择一些额外假设，把难题缩成可工程化、可评价的子空间，再在其中寻找满足特定性质的实现。因而一项机制成立时，首先要问它取得了什么性质，其次要问这个性质依赖哪些前提、把哪些问题留在了边界外。

### 由基本约束产生的问题

下面几类困难不会因为换一种数据库、索引或 prompt 自动消失：

1. **没有免费的判定者**：改进需要某种外部结果、任务标准或固定锚点。若系统同时任意改写候选和唯一评价器，就可能只学会证明自己变好；继续要求系统评价评价器会形成回归，必须由某些不可同时改写的现实结果、原始证据或治理边界截断。已经发生的后续事件可以检验相应预测；缺少免费反事实判定者，不等于缺少学习信号或回报候选。
2. **写入时不知道未来用途**：当前整理者无法预知未来会从人物、关系、情绪、任务、反例还是某个精确措辞进入。写入提取、事后巩固和按历史查询优化，都是拿不同代理量押注未来。
3. **压缩与保真不能同时免费取得**：在给定解码能力、预算和未知未来用途的条件下，有损摘要不能保证保留任意细节；反复整体改写可能继续丢失早期差异。保留原文与来源入口可以使遗漏有机会恢复，但仍需支付定位、读取与核验成本。
4. **有效性会随时间和语境变化**：事实可能过时、被纠正、在不同窗口同时成立，或只是观察角度发生变化。时间更新不必然是语义更新，冲突也不必然意味着旧记录应被覆盖。
5. **长程信用难以分配**：一条记忆被读取、一个工具模块被加载或一条路径被走过，不等于它因果上促成了结果；没有被使用也可能来自入口失败或尚未出现机会。
6. **存在不等于能取到和会使用**：内容物理存在、图上可达、工具返回正确证据，分别只解决存储、候选取得和暴露；模型是否认出用途并形成正确下一状态仍是另一层问题。当前回放已经实证过“短路径存在但实际大范围枚举”的反例。
7. **单条现实轨迹没有候选行动的反事实**：旧聊天只能证明旧策略之后发生了什么，不能告诉我们另一条回复会收到怎样的参与者反应。重放可以比较内部行为，不能凭空恢复未发生的社会反馈。

这些问题中的有限注意、未知未来、有损压缩、单一已发生轨迹和无免费判定者接近结构性约束；事实时效、社会反馈和多主体交错还依赖具体环境，但在持续群聊中确实存在。

### 由共同研究范式带来的盲点

另一部分重复不必是普适不变量，也可能来自论文共享 benchmark、任务形状和研究工具。以下是部分研究采用的简化条件，并非所有论文共同依赖，也不都属于方法成立的必要条件：

- 任务可以重置，可以从同一初态反复 A/B；
- 训练、验证与测试分布足够接近；
- 每个任务有明确成功信号、标准答案或环境 reward；
- 单用户、单 agent、单个活动切片足以描述当时状态；
- 一次动作的后果在较短 horizon 内出现；
- 评价成本低于候选搜索带来的收益。

这些条件可以简化结果判定和重复比较，但不会自动解决信用分配。柚子的生产群聊只满足其中一部分条件；隔离回放则能主动建立相同初态、冻结输入、限制副作用等条件。迁移时应逐项核对，不能仅凭环境不同认定机制失效，也不能把离线成立的结果直接推广到真实聊天。

## 问题 × 假设矩阵

下表是本项目对各研究族的迁移解释，不是论文作者共同采用的分类。

| 研究族 | 正面处理的性质 | 用来缩小问题的主要假设 | 在柚子这里仍未解决的部分 |
|---|---|---|---|
| ReadAgent、RAPTOR | 有界切片、层级摘要、原文回查 | 实验主要使用固定文档语料，可追溯到原始片段，问题通常有文档证据 | 未来入口未知、多人语境、长期纠正和索引维护 |
| Generative Agents、A-MEM、Graphiti | 来源、反思、关系链接、时间关系 | 经历可抽取成相对稳定的 note、实体或事实边 | 哪些关系值得写、错误抽取如何修订、链接是否实际可用 |
| MemGPT | 有限主上下文与外部记忆移动 | 宿主的容量阈值、驱逐和摘要策略可接受 | 自动管理是否遮蔽 agent 自身不会整理的问题 |
| ACE、Dynamic Cheatsheet | 增量 context／经验演化 | 后续任务与先前任务足够相似，执行反馈能指导整理 | 来源真伪、长期漂移、经验实际因果贡献 |
| Reflexion、ExpeL、Voyager | 从成败轨迹形成后续策略或可复用模块 | 任务可重复，结果清晰，后续试次可比较 | 群聊没有可重置反事实，社会反馈不受控制 |
| JitRL（非参数策略改进） | 经验以 advantage 直接修正动作分布，无需梯度 | 可比较的数值回报、能匹配的状态／候选动作与基础动作分布；实验按重复 episode 结算，分布可由 token logprob 或模型报告的置信度构造 | 已有预测结算与实践反馈候选；结果如何转成回报、结算跨度、动作对齐和邻域估值可靠性尚未验证 |
| MemoryBank | 时间衰减与取回强化 | 新近性和取回可作为价值代理 | 低频重要事实、入口失败和误用强化 |
| LongMemEval、MemoryAgentBench、LongMemEval-V2、StructMemEval | 把检索、更新、学习、使用等失败拆开评价 | 冻结数据集、证据和答案可作为 oracle | 开放目标、长期关系与评价协议自身演化 |
| ADAS、DGM、Gödel Agent、Hyperagents | 候选搜索、自修改与部分元能力评价 | 明确目标、可重复验证、可恢复初态；DGM 借编码任务与代码自改的能力重叠解释递归收益，Hyperagents 另行检验元修改能力 | 群聊效用与工具模块／代码修改不对齐，评价器也可能被迎合 |
| Stateless Language Agents（SLA） | 状态／上下文分离、harness 重建角色化上下文、证据驱动指派 | 目标单一且可执行、可重置、并行工作可显式指派、评测器受保护 | 开放目标与写入时未知未来用途、社会反馈、harness 自身演化 |

同一研究可能横跨多行；矩阵的用途不是给论文归类，而是在移植机制前强制写清五件事：它依赖的假设、希望取得或已在特定条件下验证的性质、留下的问题、假设失效时的表现，以及可以推翻迁移判断的实验。

对本项目而言，长期底座不应提前押注某一个特殊解。更稳妥的公共能力仍是保存完整经历、稳定来源与多重引用，允许有界读取和重放，把总结、hint 与工具模块修改作为可版本化候选，并让后续实践决定采用、修订或回退。Markdown Skill 只是无函数的工具模块，不是另一套载体。具体索引、遗忘、整理和自改策略留在这个底座上竞争。

## 长经历与索引

### 增量演化而不是整块重写

- [Agentic Context Engineering（ACE）](https://arxiv.org/abs/2510.04618)把长期 context 视为持续演化的 playbook，以生成、反思、整理和增量合并更新条目。论文明确分析了为了简短而丢信息的 **brevity bias**，以及反复整体改写造成的 **context collapse**；它在自己的任务中支持用增量更新缓解整体重写的信息损失。本项目可据此比较整体改写与局部修订，并按既有经历语义保留来源及旧版本。论文中的 helpful／harmful 计数是其任务里的整理信号，不是通用价值函数。
- [Dynamic Cheatsheet](https://arxiv.org/abs/2504.07952)让固定黑盒模型跨任务维护外部策略、代码和教训。它证明简单外部载体可以被后续任务消费；没有证明模型写下的每条经验都正确，也没有解决长期来源追溯。
- [Generative Agents](https://arxiv.org/abs/2304.03442)保存完整经历流，从经历形成高层 reflection，并让 reflection 指回支持它的记录；reflection 还可引用 reflection。它支持“原始经历不因总结消失”和“高层结论带来源”。论文的 recency／importance／relevance 权重服务于 Smallville 行为模拟，不能移作柚子的固定价值公式。
- [A-MEM](https://arxiv.org/abs/2502.12110)用 Zettelkasten 式 note、标签和链接，让新记忆连接旧记忆并演化旧 note 的属性。它支持多入口与可演化索引；本项目若借鉴，应把纠正写成带来源的新事件或新版本，不能静默改写已经发生的历史。AgentGuide 导读把 A-MEM 错链到 `2409.09908`；正确论文编号是 `2502.12110`。

### 分段阅读、摘要与反查

- [ReadAgent](https://arxiv.org/abs/2402.09727)由 agent 划分段落、生成带原页定位的 gist，并在需要时回看原文。论文中的 gist-only 弱于 gist+lookup，且某些任务里完整长上下文反而不如选择性查阅。它与“有界 `pull`—带正式号的覆盖结论—按需反查”很接近；固定页大小和文档边界不能直接等同于群聊经历流。
- [RAPTOR](https://arxiv.org/abs/2401.18059)递归聚类并总结文本，形成多层摘要树；论文比较中，跨层扁平检索可以优于只能沿严格层级逐级走。这支持总结的总结，但也提醒本项目保留跨层、跨主题和多父入口，不把检索锁进唯一父链。
- [MemGPT](https://arxiv.org/abs/2310.08560)把有限主上下文与外部存储组织成显式层级，提供模型主动访问、搜索和编辑外部记忆的机制，同时由宿主执行容量警告、FIFO 驱逐与递归摘要。本项目可以借鉴前者；后者会遮蔽当前回放要观察的自主整理失败，因此不直接复制。
- [Zep／Graphiti](https://arxiv.org/abs/2501.13956)用时态知识图整合对话与业务事实，并保留事实到 episode 的来源。它支持“当前解释可追到原始经历”和事实有效时间；实体关系图不等于统一经历流与覆盖 DAG，当前规模下也不足以证明需要图数据库。
- [HippoRAG](https://arxiv.org/abs/2405.14831)把语言模型、知识图谱和 Personalized PageRank 结合，用图关联扩展多跳检索候选。它支持在词面不重合时利用关系路径找材料；PPR 是检索排序信号，不是经历写入、覆盖、遗忘或记忆价值判据。
- [MemoryBank](https://arxiv.org/abs/2305.10250)以时间衰减和被取回后的强化模拟遗忘曲线。它可作为对照策略，但“很少被取用”也可能是入口失败或低频重要事实，不能据此自动删除。

### 状态与上下文分离

- [Stateless Language Agents（SLA）](https://arxiv.org/abs/2610.07625)（arXiv 2610.07625，v1 于 2026-10-06 提交，32 页，未经同行评审；[作者仓库](https://github.com/Alex-q-z/stateless-language-agents)目前只发布配图、无可运行代码）区分 **state**（跨调用持久、归 harness 所有）与 **context**（单次调用内 agent 看到的内容）：无状态 Advisor 每个 epoch 读 harness 重建的证据摘要并下发具体实验，并行 Worker 每次 trial 只得到自己的 assignment、保留候选和局部反馈，看不到其他 Worker 的 workspace 与完整历史；候选由 Worker 环境之外受保护的评测器打分，研究状态可 checkpoint 与回滚。它在软件工程、kernel 优化与算法设计上以最高 1B 累计 token 预算对比 EvoX、CORAL、SwarmResearch，报告更好的终值与更少的到达 token，Advisor 只占 0.24–0.51% token。
  - **原文机制与痕迹**：CORAL 的 GPU kernel 运行最后一次改进停在 231M token，此后到 1B 预算的最后 1,500 个 session 有 98% 不发起任何工具调用；libexpat 轨迹中两个 agent 在 13 分钟内把同一特性从相同父代各实现一遍且得分相同，其中一方此前已发过占用说明。
  - **本项目迁移推论**：它把“保留完整经历、稳定来源、有界读取，由 harness 决定每个角色看到什么”实现成可运行、可测量的系统，比固定摘要树更彻底——连编排者都不携带对话。它给“记录不等于会被消费”提供了外部实例，并提示可以单独测试一个无状态规划角色，而不是让同一个 agent 既回忆又决策。
  - **边界**：任务目标单一、可执行、可重置；持久状态包含候选快照、评价输出与完整实验事件日志，并非只保存小型候选集，但其用途仍围绕已知优化目标，没有处理开放聊天中“写入时不知道未来用途”的问题。harness 由人设计、自身不演化，不回答元层改进问题。多数任务配置只跑一次，单次运行成本数百至数千美元，代码未发布，数字只能作为方向性证据。
  - **2026-10-14 全文复核**：[HTML v1](https://arxiv.org/html/2610.07625v1) §3.1 区分测得无改进与实现／运行／正确性失败；§4.4 的 Advisor token 占比不能当成费用占比（后者为 1.20–2.29%）；§5 明说消融改变的是可见上下文，没有单独隔离“跨调用保留对话”这个变量，成本也未计执行与评测计算。附录 B.1 保存完整实验记录；附录 A 则允许 ACE 等跨任务经验为 Advisor 提供初始策略。因此值得借鉴的是持久证据与按用途构造上下文，不是“所有长期主体都应丢弃会话”的普适结论。

## 从轨迹到经验

- [Reflexion](https://arxiv.org/abs/2303.11366)把任务反馈与失败轨迹转成语言反思，供后续 trial 使用。它最直接地支持“失败轨迹 → 候选教训 → 后续真实消费”；论文也出现自测或反馈不可靠时反思反而伤害表现的情形，因此必须保存反馈来源与实际结果。
- [Voyager](https://arxiv.org/abs/2305.16291)根据 Minecraft 环境反馈、执行错误和自验证改进程序，只把成功的可执行代码加入 Skill 库并在新任务复用。它支持程序性 Skill 和未见任务复验；Minecraft 提供可重复外部判据，真实聊天没有同等的反事实 oracle。
- [ExpeL](https://arxiv.org/abs/2308.10144)比较成功与失败轨迹，以 `ADD`、`EDIT`、`UPVOTE`、`DOWNVOTE` 维护洞见，并在未见任务加载洞见和成功轨迹。它支持保留成功示例与抽象经验、区分已见练习和迁移；投票只是确定性任务环境中的启发式，不能成为记忆的因果信用或永久价值。

结合这些机制与本项目的可逆实验要求，我们采用下面的追踪链；它是本项目的实验设计，不是各篇论文共同实现的标准协议：

```text
来源摩擦／失败
  → 候选经验及其预期
  → 后续是否实际加载
  → 行为怎样改变
  → 外部结果或独立证据
  → 保留、修订或回退
```

没有后续消费，写入工具模块只能证明载体存在；没有独立结果，模型宣称“我学会了”不能证明实践改善。

### 记忆直接参与策略更新

- [Just-In-Time Reinforcement Learning（JitRL）](https://arxiv.org/abs/2601.18510)（arXiv 2601.18510，ICML 2026 poster，最新 v4；[代码](https://github.com/liushiliushi/JitRL)）把记忆当作非参数策略分布，而不只是待阅读的文本：每个 episode 结束后由 LLM Evaluator 给出逐步奖励 r_t 并聚合成折扣回报 G_t，以 `(state, action, G)` 三元组存入动态记忆；推理时对当前状态检索 top-k 邻居，用邻域回报均值估计 V̂(s)、Q̂(s,a)（未见动作以 α/|N(s)| 给乐观加成以维持探索），得到 Â=Q̂−V̂；再按 KL 约束目标 max_π′ E[A]−(1/β)D_KL(π′‖π_θ) 的闭式解 π*∝π_θ·exp(βÂ)，在 logits 上做加法更新 `z′=z+βÂ`，全程无梯度。WebArena 与 Jericho 上超过五种免训练基线，并在同一基座下超过 WebRL，成本约 $290 对 ~$9900。
  - **原文机制与痕迹**：消融显示增益来自 logit 更新而非检索到的文本——同一份记忆改成拼进 prompt（Prompt Update）后 Admin 49.46 / Reddit 53.02，低于 Logit Update 的 52.31 / 57.64；检索邻居 k 只在 8–14 稳定，文本状态优于稠密 embedding；冷启动下跨任务记忆占检索上下文近 47%，仍优于基线。定性例子中记忆把“直觉动作”的 logit 压下去、把经验上正确的动作抬起来（WebArena 里 Catalog 0.90→0.40、Marketing 0.70→1.40；Zork1 里 take platinum bar 0.92→0.42、echo 0.30→1.50）。
  - **本项目迁移推论**：追踪链“来源摩擦 → 候选经验 → 是否加载 → 行为改变”通常把经验作为 context 注入；JitRL 给出另一种可比较的消费形式——经验以 advantage 缩放的形式改变动作分布，不要求模型显式“读到”这条经验。群聊里可对照测试同一批候选经验：(a) 作为 hint／记忆注入上下文，(b) 作为对候选回复的打分修正。它把学习限制在一组离散候选动作上，与“多种回复候选 + 打分”形状相容。
  - **实现接口**：[v4 §5.1](https://arxiv.org/html/2601.18510v4#S5.SS1)同时提供 Token-level Logit 与 Verbalized Logit：前者读取候选索引 token 的 logprob，后者把模型报告的 0–100 置信度变成候选动作的 logits。因此原始 logits 访问不是硬性门槛；口述置信度也不因此等同于模型真实概率，仍需检验校准与效果。
  - **边界**：闭式解本身与 DPO／RLHF 的推导同源，新意在于在线检索回报，不是新数学；逐步奖励来自 LLM Evaluator，WebArena 按任务贡献评价，Jericho 结合游戏分数变化与动作效果，并非必须由环境直接提供每步奖励。评价可靠性会影响价值估计，但使用模型评价不等于没有真实反馈。状态表示、动作归一化和候选集构造按任务设计（WebArena 正则化 URL、Jericho 名词／动词摘要），迁移到群聊仍要检验哪些处境与选择可以共同估值。主实验每任务 5 个 episode（WebArena）／50 个 episode（Jericho），更新的是经验记忆与动作选择，没有验证改进方法本身的演化。

### 2026-10-14 回报问题复核：已有反馈，不等于已有可用估值器

先前的矩阵把柚子写成“无稳定回报”，末尾又把重复 episode、离散动作、回报与 logits 写成“四样当前都不具备”，遗漏了已有讨论，也把论文实验设定扩大成了方法的硬性门槛。这两项判断已修正。

[基础讨论第四至六节](memory-foundations-discussion.md#四用预测统一写入与读取)已经提出：以实际后续事件检验预测；让承诺、计划等未兑现预测保持打开，待兑现或落空时结算；预测测量函数／编码器输出，避免为比较而生成完整未来。[第九节](memory-foundations-discussion.md#九二阶惊奇与无常的可达性)又把学习尝试的结果作为预测对象；“常应常静”与噪声反例则约束什么变化应抵达行动。[实践反馈主线](self-maintaining-context.md#2-若上限存在怎样形成实践反馈循环)明确允许外部结果、用户纠正、后续体验与人工／模型评价。这些是已讨论的信号来源与候选判据，不应被改写成“没有回报”。

JitRL 将逐步数值奖励聚合为 `G_t = Σ γ^(u−t) r_u`，再从相似状态／动作的历史回报估计 advantage。它需要这些样本具有足够一致的含义，供局部比较；不要求每次回报值相同，也不能据此要求柚子采用一套永久不变的总分。[v4 附录 C](https://arxiv.org/html/2601.18510v4#A3)的收敛主张另有状态／策略正则性、条件零均值且方差有界的回报噪声、邻域覆盖、动作采样增长和慢策略漂移等前提。这些条件尚未在群聊上验证；证明允许策略非平稳，也不等于任意目标或环境漂移都已被处理。

向本项目迁移时，待验证的是哪些既有反馈可形成何种奖励、怎样结算长跨度结果、什么状态／动作算可比，以及旧回报在表示或偏好变化后还能否使用。连续事件流中另定结算窗口是迁移候选，并非本文已经验证的 JitRL 实现；不能用“不能重置群聊”直接否定学习。预测校验有真实后续事件作依据，但预测误差、学习收益与行动价值仍不是同一个量。是否以及如何由这些信号得到策略更新的标量回报，是现有讨论与 JitRL 之间要检验的接口，不是重新要求维护者从零定义目标。

## 自我修改与元层演化

### 候选档案与有限实证搜索

- [ADAS／Meta Agent Search](https://arxiv.org/abs/2408.08435)让固定 meta agent 读取不断增长的设计档案，以代码生成新任务 agent，在目标域验证后保存设计和指标。它支持比固定 prompt 模板更宽的候选表达，以及“保留档案而不是只沿最后一个赢家爬山”；它改进的是被搜索的任务 agent，搜索器本身仍由人固定。
- [Darwin Gödel Machine（DGM）](https://arxiv.org/abs/2505.22954)从 agent 档案选择父代，分析日志、修改自身代码，再用 SWE-bench 与 Polyglot 实证评价；可编译且仍保留编辑能力的候选进入档案。它支持保存分支、谱系、失败与暂时次优的踏脚石，而不是立即覆盖唯一正式版本。其承重假设是：自我修改本身也是编码任务，因此编码基准变好可代表更强的自改能力；这个对齐不能直接迁到群聊。档案维护、父代选择与开放式外循环仍固定，不是候选可修改的部分。
- [Gödel Agent](https://arxiv.org/abs/2410.04444)让 agent 读取并通过 Python 运行时检查、monkey patch 同时修改任务策略和自更新逻辑。它证明有限环境中可以暴露可读、可改、可评价的接缝；论文也报告临时退化、最终弱于初始策略和自改失败。生产 Bot 没有理由先照搬运行时 monkey patch。

### 任务能力不等于改进能力

- [Hyperagents](https://arxiv.org/abs/2603.19461)把任务 agent 与 meta agent 放在同一可编辑程序中，并明确指出 DGM 的特殊对齐：评价与自我修改都是编码任务，所以编码能力可能同时帮助两者；这种关系在编码之外一般不成立。论文以固定 meta agent、限定候选生成次数的 `improvement@k` 比较产生改进的能力，并检验跨领域迁移；这比只观察任务得分上升更直接地支持元层改善，但仍限于所测任务与预算。其父代选择与评价协议仍固定，论文也警告 evaluation gaming。
- [A Survey of Self-Evolving Agents](https://arxiv.org/abs/2507.21046)按“改什么、何时改、怎样改、在哪个领域”整理模型、context／memory、工具和架构演化，并把适应、保留、泛化、效率和安全列为不同评价面。它适合作查漏清单，不是本项目必须采用的模块划分，也不是“无限持续改进已经成立”的证据。

对本项目最重要的迁移是一个**对齐缺口**：柚子的目标发生在群聊、关系维持、检索和行动中，改动介质却可能是 hint、prompt、Markdown／Python 工具模块或其它代码。更会修改工具模块／代码，不保证更会聊天；某次聊天变好，也不保证下一次能提出更好的实验与改动。

因此：

- 普通任务的 Markdown 工具模块实践闭环应先走通，不把完整元修改设成首轮前置条件；
- 若声称“更会改进自己”，必须让旧、新改进方法处理未参与形成的新失败，在相近预算下产生候选，再比较候选的独立表现；
- 当前启用版本和候选档案分开。候选被回退不等于抹掉其来源、理由和结果，但也不要求所有分支永久继续运行；
- 评价器可以演化，但需要冻结的任务、原始证据、独立用户纠正或环境结果作为锚点，不能让候选同时任意改写自己和唯一判据。

## 评价与上下文工程基准

- [LongMemEval](https://arxiv.org/abs/2410.10813)把信息提取、多会话推理、时间推理、知识更新和拒答分开，并通过 oracle retrieval 显示“证据已取到”和“模型会正确使用”是两种失败。回放探针应分别报告检索失败、阅读／使用失败和更正错误。
- [MemoryAgentBench](https://arxiv.org/abs/2507.05257)覆盖准确检索、测试时学习、长程理解以及选择性遗忘／冲突更新。它可提供探针维度；基准中的 forgetting 可以只是从活跃上下文抑制，不支持物理删除原文。
- [LongMemEval-V2](https://arxiv.org/abs/2605.12493)把长期记忆扩展到工具轨迹，并比较显式 observation／event／strategy 池与“原始轨迹文件 + 工作流文档 + manifest + 检查脚本”的 AgentRunbook。它支持不先为全部历史建立向量索引，让 agent 用文件和工具选择证据；论文的自定义 Web 任务、延迟和成本不能直接代表群聊。
- [StructMemEval](https://arxiv.org/abs/2602.11243)显示简单 RAG 在结构化记忆任务上不足，而模型在被明确提示如何组织记忆后可以改善。这提示本项目值得测试：明确解释现有记忆操作，是否比仅提供工具更能改善整理；正式号、覆盖、反查、多重引用和工具模块这套具体协议的有效性仍需本地回放验证。

这些基准都没有给出普适的记忆总分。命中率、路径长度、调用数、图深、访问频率、重要度和压缩率分别能诊断不同问题；只有在具体后续任务中被实际消费并得到独立结果，才产生实践证据。

### 压缩视角的来源

[Minimum Description Length（MDL）](https://homepages.cwi.nl/~pdg/ftp/mdlintro.pdf)为描述结构与残差提供编码成本视角；[压缩进步](https://people.idsia.ch/~juergen/driven2008.pdf)要求在相同材料上比较旧、新压缩器，主要刻画学习进展和内在兴趣。它们都不自动等于未来任务价值。[Titans](https://arxiv.org/abs/2501.00663)的梯度惊讶与衰减属于参数记忆更新，不能直接作为外部事件索引的写入规则。项目中的具体测量假设、泄漏边界和校准顺序仍由[记忆估值与索引演进](memory-valuation-and-index-evolution.md)定义。

## 对当前实验的直接影响

这些材料不会替代当前主线，但给出了几组可证伪比较：

1. **整块重写与增量节点**：比较同一来源下的整体摘要改写和带来源的追加／局部修订，观察细节坍缩、纠正能力与可见 token，而不只比较摘要长度。
2. **gist-only、gist+lookup 与完整上下文**：分别测证据取得、答案使用和成本，避免把查到原文与答对混成一个指标。
3. **来源与多入口**：同一经历从人物、话题、任务和反例入口进入；检查多个索引能否落到同一正式号，而不是要求唯一树路径。
4. **任务层工具模块闭环**：真实失败产生候选 Markdown 工具模块，后续分支实际加载，记录载体消费、行为变化、结果与未见迁移；先完成这一步，再决定是否值得测试元层改进。
5. **候选谱系**：实验候选保存父版本、产生原因、预期、实际证据和回退结果；首版只需保存谱系，不实现 DGM 式自动种群搜索。
6. **任务层与元层分评**：聊天／检索表现用于评价任务做法；产生、筛选和修订候选的表现用于评价改进方法。两者不能互相代替。
7. **冻结锚点**：评价协议允许以后修订，但原始轨迹、冻结探针、独立结果和协议版本必须保留，防止系统只学会修改判据来证明自己变好。
8. **多预算点与冻结状态续跑**：借 SLA 的协议，从相同 checkpoint 出发只改一个变量（谁看到什么、有没有显式指派）续跑，并至少在两个累计 token 预算点分别报告；短窗口可能给出相反的排序。
9. **记忆的消费形式对照**：同一来源抽出同一批候选经验后，分别测“注入上下文”与“基础候选动作分布加上经验回报修正”，基础分布可由索引 token logprob 或模型报告的置信度构造；分开报告载体消费、行为改变与外部结果。后者还须验证回报含义与候选动作的可比性，不能把任意模型打分都称为 JitRL；这一步检验的正是“记录不等于会被消费”。

## 暂不引入

- 不因论文使用向量库、知识图或 memory manager 就新增第二份可写真相源；
- 不把 importance、访问次数、遗忘曲线、投票、路径数或压缩率变成自动晋级／删除规则；
- 不用单一 LLM curator 静默改写历史；
- 本文不新增生产自修改权限；实验候选不得自行扩大权限或绕过既有代码切换与恢复边界，运行时 monkey patch 不因论文采用而成为本项目方案；
- 不把旧聊天对旧回复的反应当成候选新回复的反事实反馈；
- 不让自动演化同时任意改变候选、唯一评价器和全部外层安全边界；
- 不把“有限任务上出现自改收益”写成系统上限无限、收益单调或完整外循环已经自治；
- 不因 SLA 这类无状态编排在可执行评测器上成立，就把群聊 agent 改成无状态编排，它验证的是有明确目标与判据的单一任务，群聊没有可重置反事实或免费判定者；
- 不因 JitRL 的任务实验成立，就直接在生产群聊引入自动策略更新：已有预测结算与实践反馈候选，应先检验它们如何形成可比较的回报及可靠的邻域估值；不能以“无稳定回报”、没有可重置群聊或不暴露原始 logits 为由跳过这些候选。本文的研究复核不授权生产策略更新。

## 当前结论

现有研究足以支持继续验证一种高上限、可逆的外部记忆与工具模块实践循环：保留完整经历，以带来源的增量节点组织它，让后续求值真实消费候选，并用新经历修订候选。它也清楚说明了下一层困难：群聊任务与修改工具模块／代码的元修改并不天然对齐。

研究仍没有给出“理想索引”的固定形状，也没有给出普适记忆价值函数。当前先完成任务层的可重放、可比较、可回退消费链；只有实际出现“不会产生或选择有效改动”的摩擦后，再比较元层改进方法。让以后发生的实践决定哪些结构真的有用。
