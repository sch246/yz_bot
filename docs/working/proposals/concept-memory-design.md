# 多维概念记忆设计草案（落地瘦身版）

> 状态：未实现的设计草案，经草籽、柚子与 Claude 多轮审阅。启动时间待定。
> 事故背景：2026-10-28 群聊里再见到收过的表情时没认出来（“初见失忆”）；原型测试里又凭蓝发把鲸鱼娘误判成芙宁娜。暴露的缺口有三处：图到了也不和柜里比对，没有“身份存疑”的写法，过后想比对时原图往往已经拿不到（QQ 图片链接的有效期可能比本地缓存的 15 天闲置清理期还短）。
> 理论背景：[memory-foundations-discussion.md 第十五节](memory-foundations-discussion.md#十五2026-10-28认知共轭不确定性目的论信息论与多尺度记忆对谈)，只作类比参照，不是代码约束。

## 0. 核心共识

**能被再认出的事物（角色、道具、黑话、技能）是概念；一张具体的图、一次排障是多个概念的交点。**

- 再认分三级，越往后越贵，前一级认出来就不往下走：md5 认同一份文件，dHash 认被压过的同一张图，图像模型认同一概念。
- 图像本身不好比较，要紧的是文本语义；最后一级靠“描述 → 粗定位 → 两图对比”。
- 惊奇才改印象。时间线不存进概念，需要时从 `chatlog/` 和日记派生。
- 人和群是活的，不压成固定摘要；`self` 是度量世界的尺子，不进概念库。

## 1. 不做什么

1. **`self` 不进库**；人与群也不压成印象，来源永不抹去。
2. **代码不写概念文件。** 概念笔记全部由柚子来写，代码只维护图片指纹和候选检索。
3. **表情不一图一份笔记。** 那句话和心情本来就在柜子索引里，再写一份就是抄两遍。
4. **判定权在柚子。** 模型比对的结论一律是“疑似”，由她确认或否认；标注保持中性，不替她定性语境。
5. **收图不变成填表。** `meme__collect` 仍是一句话加心情，与 [meme.py](../../../mods/tools/meme.py) 开头 `WHY:` 记录的维护者形状一致：md5 由代码算，角色由她自己填。
6. **`#image off` 不下载图片。** 这一档存在的意义就是不在任何群里到处下载图片。off 档只做不需要下载的那一级。

## 2. 存在哪里

### 柜子索引（storage `meme/index`）

每张表情的条目新增两个字段：

```
{file: <sha256>.jpg, md5: <32 位大写十六进制>, mood, note, added, last_sent, character: 鲸鱼娘}
```

- `md5`：`collect` 时由代码算出并存入。现有 73 张用一次性脚本从 `data/memes/` 补算，之后不再每次重算。
- `character`：由她在 `meme__edit` 里填，可以写 `? 疑似芙宁娜/鲸鱼娘`。不填也行。

### 概念笔记

只给能复用的概念写，例如 `角色:鲸鱼娘` → `data/notes/角色/鲸鱼娘.md`，以后也可以有 `黑话:`、`道具:`。都是普通笔记，`write_note`、`search`、`.history` 直接可用。这类笔记数量少，`listing()` 先不加跳过规则；真挤占了 `## 笔记` 再说。

> 柚子最初提过放到 `data/concepts/`，那是为了避免一图一份笔记挤满目录。表情不再单独写笔记以后，这个顾虑基本消失了。

样板 `角色:鲸鱼娘`：

```markdown
# 角色 · 鲸鱼娘 (whale-chan)
身份来源: DeepSeek 社区二创拟人形象（treapgogo.github.io/deepseek-whale-girl）
视觉特征: 深海蓝渐变长发、呆毛、白蕾丝女仆发箍、鲸鱼鳍状耳、深蓝鲸尾、蓝白女仆裙、金边蓝宝石领结
认知印象: “吞噬 token 却爱吃大白饭”。大尾巴粗得像船桨。
```

## 3. 识图规范

1. **看到的特征不等于身份。** 眼睛只能看到蓝发、女仆装，“这是谁”是推断。认不准就写 `? 疑似芙宁娜/鲸鱼娘`，身份要靠来源或问人确认。
2. **动作栏包含环境。** 除了自身姿态，也要记“旁边有人拿扳手修锅”这类核心冲突。
3. **图中文本是一等公民。** 梗图大多靠字，图中文本也是粗定位最稳的线索。

## 4. 再认流程

### 第一级：md5（不下载）

消息里 `[CQ:image,file=…]` 的 `file` 字段就是图片内容的 md5。柚子拿 chatlog 核对过：柜子 73 张里有 71 张的 md5 能在 `file` 字段里找到，另外 2 张是 10-24 导入的，来源不在消息流里；同一个 md5 会跨天、跨群反复出现，最多的一张出现了 164 次。

- 取 `file` 去掉扩展名，必须是 32 位十六进制才拿去比；花括号形式的临时名（如 `{FAFDDB49-…}.jpg`，老 `gchat.qpic.cn` 域名）不是 md5，跳过。
- 这一级是纯字符串比对，三档都做，`#image off` 也能认出原样重发的图。
- md5 只认同一份文件，加了字或裁过一刀就会变。

### 第二级、第三级：需要图片字节

| 档位 | 什么时候做 |
|---|---|
| off | 不做 |
| lazy | 图本来就要下载进模型输入时，顺便做 |
| eager | 图一到就做（挂在 `eager_cache_images` 这条到达路径上，[chat/\_\_init\_\_.py](../../../mods/chat/__init__.py)） |

- **第二级 dHash**：只判“同一张图被压过”，不判裁切，也不判同一概念。距离小于阈值就算疑似同图，再让视觉模型看一眼确认。柜子里的 dHash 由代码从 `data/memes/` 算出，存进索引。
- **第三级语义**：图像模型按固定栏位出描述（主体、角色、图中文本），拿描述在柜子索引的 `note`、`mood`、`character` 和概念笔记里检索候选，再把新图和候选原图一起交给图像模型比。结果分三档：同一张、同一概念（同角色、新构图）、无关。主模型不能看图时，eager 本来就会生成并缓存描述，可以直接复用。

## 5. 标注

保留原 `image_url`，在它后面追加一段文本，原图照样进视觉通道：

- 同一张：`[表情包: 电饭锅修理鲸鱼娘 #{meme_id}]`
- 同一概念：`[疑似 鲸鱼娘 新图 → 角色:鲸鱼娘]`
- 无关或找不到候选：不加标注

**结论第一次得出时就钉死。** 写进一张以“消息 + 图在消息里的位置”为键的缓存表，以后渲染只读这张表。柜子后来收了这张图、改了条目，这条旧消息的渲染也不变，前缀缓存不会因此断掉。这张表只存短字符串，不跟着本地图片缓存 15 天清理，否则清掉以后重判，结论又会变。标注不写回 `chatlog/`。

## 6. 落地路线

### Phase 1：md5，不下载

1. 索引加 `md5`，`collect` 时写入，并为现有 73 张补算。
2. 消息到达时读 `file` 字段，比对索引，结论钉进缓存表；渲染时附加标注。
3. `meme__edit` 加 `character` 参数。

**验收 A**：`#image off` 下，草籽原样重发一张柜子里的表情，画面出现标注；`lazy` 和 `eager` 下柚子仍能看见原图。

### Phase 2：dHash 与语义对比

按第 4 节的档位表接上第二、三级。

**验收 B**：在 eager 下，草籽发一张被压过的柜中表情，标注指向同一张；再发一张全新姿势的鲸鱼娘二创图，标注为“疑似鲸鱼娘新图”。

## 7. 待定

1. **dHash 阈值**：拿柜子 73 张和 chatlog 里同图不同 md5 的样本做对照实验后再定。
2. **第三级的调用范围与成本**：没被前两级认出的图，每张至少调一次模型出描述，有候选时还要再调一次比较。要不要限制群？
3. **候选检索**：取几个候选，是否以图中文本优先，实验后再定。
4. **缓存表的键与保留期**：用哪个消息标识做键、保留多久。
