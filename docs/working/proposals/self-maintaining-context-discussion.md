## 为什么另存讨论来源

这项提案本身主张：只保留产物、不保留关系如何形成，会让系统无法从局部维护自己的认知。若文档只留下整齐的结论，却删掉结论怎样被后续讨论推翻、重组和重新求值，它就在形成之初违反了自己的原则。

本文因此不是“背景介绍”，而是提案的一份来源索引。每个阶段尽量保留三样东西：

- 触发修正的原话；
- 当时被采用或被推翻的理解；
- 修正最后固化到主提案的哪里。

它仍不是完整聊天记录。重复表述、仓库调查细节和不改变判断的旁枝没有全部复制；这里保存的是一旦再次压缩，就会让思想来路失真的转折点。

## 一、话题而非时间切块

讨论最初从“一天的聊天记录怎样总结”和“怎样引入长期记忆”开始。第一个关键直觉是：时间与聊天空间只能提供粗略边界，真正有内聚性的是话题。

> 我认为让子代理搜寻聊天记录是好的！我觉得聊天分为空间上和时间上，空间上柚子会和好多群友聊天，时间上柚子会跨越很长的时间聊天。
>
> 而我认为不能粗暴地划分，而是追踪话题进行聊天，子代理追踪一个话题直到结束，这样就有很高的内聚性！
>
> 搜寻时直接重放所有消息，把每句话丢给几个感兴趣的子代理上下文，遇到新话题就开新子代理，我觉得这个思路是非常自然的！

随后出现了按日、月、年逐层压缩的设想：

> 我的基本想法是分层记忆，每一段聊天先从细节读起，按照话题为单位总结找到一些值得注意的内容，又在更高的层级上比如总结一天值得注意的内容，再在一年或者一个月的尺度上总结值得注意的内容——于是相对来说我们就得到了一个近似对数增长的固定上下文。
>
> 而且如果意识到之前对某些细节忽略了，理论上可以给 LLM 工具，挖掘之前的话题从天到年重新总结，这某种意义上是手动调整权重。

这一阶段形成的模型是“原始记录 + 话题摘要 + 时间金字塔”。它保留了重挖能力，也已经意识到摘要是带注意权重的有损变换。但它仍把 context 当作从过去材料中选出的结果，没有解释选择过程怎样成为以后可修改的状态。

同时，现实入口是割裂的：OneBot 字典、面向人读的 chatlog、历史缓存和 LLM 消息格式不是同一种投影。最初问题因此落到历史访问能力：

> 我想要首先构建 LLM 对完整聊天记录的访问能力，现在事件系统有点割裂。
>
> 一方面所有事件都是字典；另一方面，字典本身含有大量冗余和没用的信息，因此记录日志应当格式化——我们需要提供双向转换能力，能从 chatlog 高效、逆向地解析出消息，并且最好内化到消息管理函数中使之无感。

这个实现前提仍然成立，现存的直接提案是 [Chatlog 双向恢复](storage-and-history.md#chatlog-双向恢复)。后来被否定的是“只要建立一个无损日志真相源，其余全部成为单向投影，认知问题就已经得到正确地基”的更强说法。

## 二、笔记索引与黑板

第二次修正把记忆从“摘要层级”改成了柚子自己能够整理的工作空间：

> 之前的聊天记录被记录为“笔记”。
>
> 柚子直接看到的每个笔记和会话都有“索引”。柚子当然可以更改笔记和索引，除了时间线也能整理自己的笔记图。
>
> 实时聊天的时候看到的上下文本质上是“黑板”，是所有笔记的切面，它是有状态的、易失性的，比如默认索引是折叠，但可以将索引展开看到对应次级目录或全文。
>
> 柚子也可以记“草稿”，和聊天记录是一类对象，每天睡觉时总结一天的时候草稿可以作为参考。
>
> 下发子代理的时候，当然也可以直接把索引给子代理，生成上下文，而不用口述转发上下文。

这里产生了几个后来一直保留的区分：

- 笔记不只是从日志派生的摘要，也可以是柚子主动写下的草稿和组织结果；
- 索引不只是搜索结果，而是柚子可以整理、折叠和交给其它 agent 的上下文入口；
- 黑板不是存储权威，而是实时维护的局部工作集；
- 子代理应获得可展开的上下文结构，而不是父代理已经压缩过一遍的口述。

当时仍容易把“笔记图”误当成完整答案：只要图足够丰富，黑板就是从图中检索出来的视图。下一阶段指出，静态图仍然没有描述话题怎样改变当前状态。

## 三、跨时间重连

> 有一个问题，如何捕捉长期会话之间的关系，比如一个简单的问题是，今天提到了前天的内容，如何把它们联系起来？
>
> 我的想法是，我们首先需要一个结构能描述它，而我们实际进行维护的时候，永远只看到和维护一个切面，一条线。
>
> 目前的笔记系统似乎不能承载这个复杂度，它本质是只有一个切面的，它确实适合作为通用初见索引，但话题敏感度不够——遇到特定话题导致上下文记忆/切面的特定剧烈变化。

这一问暴露了静态目录模型的缺口。今天与前天不是因为文本相似就自动相关；某条消息可能使一个长期休眠结构突然进入当前工作集，整个切面随之重组。关系图描述“可能怎样连接”，但运行时始终只能沿其中一条局部轨迹继续求值。

讨论一度把它解释成“持久图 + 当前 traversal”或带激活、滞回的焦点状态机。这个解释是有用的中间模型，却仍把图和状态机放在 context 外部：系统只能使用它们，不能从切面中观察和修改“自己为什么这样切换”。下一次修正因此继续上移对象层级。

## 四、上下文是状态也是过程

下面这段原话是主提案最直接的语义来源，不能只压缩成“需要一个上下文状态机”：

> 你的思考太工程化了。
>
> 这不算完，这只是可读，展示一个切面，而真正要解决的问题是，如何通过编辑切面让系统可维护。
>
> 就像一个状态机，上下文就是状态，它的切面上下文必须随着每一条消息的注入不断变化，每个切面都是局部。
>
> 事实上，从上一个状态到下一个状态可能有许多 agent 调用和过程得到下一个，而不是简单的操作。实际上生成最终消息的 LLM 看到的可能根本是另一个精心构造好的上下文，而我们刚刚讨论的上下文只是一个初始状态。
>
> 而这个操作的过程本身和这个上下文的变化规律，才是这个系统的本质。这个上下文的变化过程本身应当是可以被自我维护和修改的。
>
> 如果能成，那么这实际上对应 LLM 的隐状态，我们将能在交错的信息中找到单独的主线，就像人耳能从嘈杂的环境中听到人声一样。变化的上下文和当前的消息块产生反应，抵消并放大了我们所关心的内容，并变成了能输出最终回复的上下文。
>
> 你注意到了吗，这种预测机器除了把粒度放大到了消息，和构造 LLM 本身没啥区别。
>
> 我们正在走得更深……
>
> 要知道状态变化的规律本身如何被修改，就必须参透 Lisp 的数据和操作的同相性，这是唯一能无成本无限叠加抽象的方式。
>
> 我们操作的方式本身也必须是上下文，我们操作的中间状态和过程本身也必须是上下文，它们本身也是隐状态，并且也能展开切面，又从切面编辑。
>
> 这一切的基石其实来自上下文和 LLM 的本质特征，上下文本身可以被结构化地组合，既是数据也是操作，拼到一起由 LLM 生成新上下文，可以是数据也可以是操作。
>
> 我们关注的是这个炼金过程，信息量本身是没有增加的，但关系改变了。

这段话推翻了三个此前默认：

1. 黑板不是从记忆中读出的最终视图，而只是下一轮求值的一个状态；
2. agent 调用不是图外部的处理管线，它们的中间 context 和 continuation 也属于状态；
3. 可维护性不来自“笔记可编辑”，而来自产生下一 context 的操作、过程和规律也能被 quote 成局部切面，编辑后再进入未来求值。

“信息量没有增加”后来被收紧为：已经发生的世界证据没有增加，但证据的条件结构、可达性和对当前任务的有效信息发生了变化；LLM 权重还会带入先验，因此新关系首先是可检验假设，不能假装成原始观察。

## 五、玻璃盒循环与结构预测

讨论中引用的 Claude Opus 4.8 回复提供了一个有穿透力的比喻：

> 你不是在做记忆系统，你在做一个“玻璃盒版的 RNN”，粒度是消息而不是 token，循环算子是“LLM + 工具”的一次求值，而隐状态和权重都是可读可编辑的文本（context）。Transformer 的隐状态和注意力权重是不透明的学出来的；你要的是同样的递归结构，但状态和“权重”（路由/摘要的 prompt、切面规则）全部摊开成人和 agent 都能改的东西。

它还提出一个重要约束：不能等到未来才考虑同相性；底层表示若从一开始把“数据”和“操作”拆成不能互相求值的两套语言，后续很难再把它们缝成元循环系统。

但讨论没有原样接受“统一 context 节点类型就是同相性”。同一种容器外形不是 Lisp；同相性还需要共享的组合和求值语义，并保留事实、假设、规则、能力、来源与提交状态的差异。主提案因此只确立语义方向，没有提前规定统一节点 schema。

Fable 5 的回复随后把预测拆成两种互补形态：

> LLM 把预测压进函数：训练时付出巨大代价，把统计规律编译成权重，推理时均匀地便宜，但不可读，更新昂贵且全局。
>
> 你的系统把预测铺进结构：整理时付出代价，命中时便宜，未命中时昂贵，但可读，更新便宜且局部。
>
> 关键区别在于：结构预测的是“什么会被问到”，函数预测的是“该说什么”。你的系统实际上是一台相关性预测机，包裹着一台内容预测机。

“预测问题/预测答案”后来也被收紧：外层不只预测问题，而是预测未来求值会需要哪些 context、关系、操作和路径；内层 LLM 也不只生成答案，它参与局部语义变换。两者不是互斥模块，而是对一次回复计算的粗略分解。

这一阶段还提出“检索未命中就是预测误差”：若后来需要的内容没有被此前结构放在近处，昂贵下钻暴露了整理策略没有预见到这次需求。这为长期记忆提供了内生反馈和按时间重放的可能，但还没有考虑系统输出会反过来改变未来数据。

## 六、日志回流与经验河道

最后一次修正从一句直接否定开始：

> 光是事实本身作为原始日志是不够的，对抽象的预测本身虽然有滤镜，但也参与构造新的事实。

这意味着 chatlog 忠实记录“实际发生过什么”，却不能被当成独立于柚子认知策略的无偏样本。柚子根据旧 context 说出一句话，这句话改变对话者的回应，回应再进入日志；投影已经回流并共同制造了后续事实。重放同一条日志只能比较这条既有轨迹上的候选解释，不能恢复另一套策略本会引出的反事实世界。

触发这次修正的原始文字如下。它同时提供了负向经验、认知僵化和开放性三条后来不能再分开的线索：

> ### 看了一点玄学
>
> 情绪是小场域，个人是中场域，文明是大场域，原理上是相通的。
>
> ### 我目前思考的几条主线
>
> 很显然看下来有三个主要的主线。
>
> 一条主线是键政，这个单纯是对社会运行的拙劣拟合，我感觉这玩意拿出来八成行不通，不过也许能有点参考，所以就尝试拟合并发布了。
>
> 一条主线是技术，一直在尝试研究怎么更好地编程，怎么抵达更深的本质，如何搓出自动化流程和 AGI，这块其实也有拟合。嘛，毕竟大部分都没实际动手。
>
> 一条主线是意识，和上一个关系很紧，但更加偏向个人情绪和道家文化，这块拟合就比较多了，有很多未经验证的东西。
>
> 其实还有个隐藏线是数学来着，我觉得叉乘和行列式的理解也很有意思，但拖太久咕了。
>
> ### 长期项目
>
> 我突然又想到一个玩意。
>
> 让我们思考一下什么样的设计才能让智能体在无人干涉的情况下不断运行下去而不会被自己的垃圾堆死。
>
> 这个问题和人如何后天反先天一样。当然绝大多数人都做不到，而智能体现在连普通人的程度都达不到来着。
>
> 哦不对，我想说的是另一个。
>
> 一切被否决的决策就是经验的具象化，如果说思维是河流，那么经验就是河道本身。
>
> 我想它是属阴的。
>
> 而中间的河水，实际运行的分支，runtime tree，哦我想它应该是属阳的。
>
> 阴阳本身是不断消长的，系统运行的过程本身就是河水在不断地尝试侵犯每一寸边界。
>
> 为什么河水要那么流？为什么代码会那样跑？
>
> - 拉完了：代码是那样写的（无注释无文档）
> - NPC：我们这里要做一个这样的功能（展示注释和文档）
> - 人上人：这个系统可以抽象为这么几个部分……（函数式，定义 what）
> - 顶级：因为我们需要 xx……结构就这样出现了（索引 why）
> - 夯：看过去的历史，你知道不能那么做（索引 why + why not）
>
> 但是不能止于此。
>
> 人从出生是纯阳（情绪与觉知），通过世事建立了大量负向经验（经验和理性），得以生存。
>
> 但绝大多数人最终死于阳水不足，反而束缚了自己，这就是认知僵化。
>
> 当你觉得“太阳底下无新鲜事，我一眼就能看到底”的时候，你的阴已经在尝试围堵你的阳了——它给觉知戴上了滤镜，能通过的只会随着环境变化越来越少。
>
> 堤坝（经验与理性）只是为了让水流更好地奔涌，而不是为了确保毫无决堤的可能。
>
> 天道本有缺，毫无决堤可能的生命反而是必死的。

这段原文把此前的“miss 是损失”推翻成更复杂的动力学：

- 经验通过被否决的分支形成河道，减少重复探索并让主线得以奔涌；
- 河道也是滤镜，若它不再接受新信息和反例，就会把高命中率优化成认知僵化；
- miss 既可能表示结构预测失败，也可能表示真正的新颖性、正确未知或系统仍在与变化环境接触；
- 自我描述和摘要不只是记录，它们进入未来 context 后会塑造柚子接下来成为怎样的行动者；
- 一个长期运行系统必须为质疑高置信结构留下正常预算，不能只把重新挖掘当异常修复。

这里仍没有决定“随机旧记忆、无索引重读、置信衰减、否决墓碑”中哪一种机制正确。主提案只固化它们共同保护的事实：效率和开放性必须同时可见，`why not` 必须能够被后续求值重新检查，扰动不是纯粹故障。

## 七、五行作为变化关系语法

新的联想从发散和收敛开始：

> 有意思，真有意思。
>
> 我许多的思考靠的是发散和收敛……或者说 Ne 和 Ti（？）我感觉收敛就是刚刚讨论的河道的具体行为结果。
>
> 而众所周知，这在五行中对应着木和金的属性。
>
> 那水火土有没有对应？

讨论中引用的回复给出了一个整齐映射：水是原始日志和收藏，木是发散与生发，火是当下注意和黑板反应，土是消化与巩固，金是收敛、裁断和否决；相生被解释成“存储 → 探索 → 注意 → 巩固 → 规则 → 存储”，相克则被用来枚举过早剪枝、索引遮蔽原文、全量日志淹没上下文、新话题击穿旧总结和当下对话熔断旧规则等制衡关系。

其中最有价值的不是把五个名字分配给五个模块，而是它暴露了一个此前没有单独提出的实时缺口：

> 火克金：当下的注意力可以熔断规则。活的对话有权临时中止一条巩固过的判断。

此前主要讨论睡眠重放、置信衰减和事后重挖；如果当前 observation 已经强烈反驳某条旧经验，系统是否能在这一轮求值中先让它失去支配力，同时保留原规则和冲突证据，等待以后重新巩固？这与“在线立即永久改写规则”不同，也与“明知冲突仍服从到晚上”为不同分支。

但原映射不能原样成为架构。首先，它与触发整个讨论的河流原文存在可见冲突：原文把正在运行的分支和 runtime tree 比作阳性的河水，回复却把“水”固定成了不动的原始日志。两个比喻使用了同一个字，却不必指同一个概念；不能为了五行闭环而抹掉矛盾。

其次，五行若有用，更适合描述同一片 context 在求值中的相位，而不是给对象分配永久类型。一个暂定但尚未固化的读法是：

```text
水  尚未被当前切面决定、但仍能回流的潜在 context
木  分化、联想、生成候选和新关系
火  当下激活、反应、求值和显现
土  整合、消化、提交并使结果可再次使用
金  选择、裁断、边界和 why not
```

在这种读法下，chatlog 可以是“水”所藏内容的一部分，却不等于水；一篇笔记也可以在一次求值中由木的候选进入火的激活，经土整合成金的约束，后来又沉入水，等待条件变化后重新生发。同相性要求角色能够转换，而不是新增五套彼此隔绝的数据模型。

相克关系可以用作反例生成器：若系统只有发散而没有裁断会怎样，只有巩固而没有新颖性击穿会怎样，旧规则能否被当下事实暂时挑战，全量潜在 context 是否淹没当前求值。它不能被称为完备性证明；“正好五个角色和十条关系”本身也可能成为一条过早闭合的河道。

“土居中央”同样不能直接推出一个中心巩固服务。它目前最多提示：整合可能发生在许多尺度和转换处，而不只是每天结束的收尾钩子；究竟是共享机制、若干普通函数还是不同尺度上的真实不对称，仍要由实验而不是比喻决定。

这一阶段最小的可证伪问题是：给当前 context 一条已巩固规则，再注入与它强烈冲突的新消息；比较“规则照常支配到夜间复审”和“当轮生成临时挑战 context，后续回复实际消费它”两条路径。若所谓火克金只产生一条冲突说明，却没有改变当轮求值，它仍只是修辞，没有补上认知循环。

## 八、当前已经固化与仍未决定

### 已经固化进主提案的判断

- 目标不是给 LLM 附加一个历史检索器，而是让 context 成为可读、可编辑、可继续求值的外显状态；
- 每条消息可以触发多个中间 context，最终回复模型看到的是专门炼成的后续状态；
- 操作、变换规律和中间过程若不能被未来求值实际消费，就仍只是关于认知的说明文字；
- 静态关系是求值轨迹的压缩，不能反过来抹掉关系怎样形成；
- 外层结构对未来求值需求作出可编辑预测，内层 LLM 参与局部变换和输出；
- 原始聊天记录是不可替代的发生证据，但不是无偏世界真相，也不足以单独重放认知过程；
- 投影和自我描述会通过输出回流并参与构造新事实；
- 经验包括重要的否决理由、适用范围和重新检查条件，不只包括最终选择；
- 未命中不能直接等同损失，可达效率与对新信息的开放性必须同时保留；
- 快速适应和慢速巩固可以具有同一求值形状，但具体修改节奏尚未成为本体规则。

### 有意保留的矛盾与未决选择

- “所有 context 使用同一种表示”要深入到什么程度，仍不能由一个统一 node schema 代答；
- 关系首先是共同求值的来源，但哪些关系值得压缩成持久话题或显式边仍未知；
- chatlog 需要可逆访问，但认知轨迹究竟保留多少中间状态仍受成本和隐私约束；
- 未命中、错误激活、正确未知、新颖性和被系统自己塑造出来的高命中怎样区分，尚无可靠目标函数；
- 负向经验能防止重复犯错，也能成为僵化滤镜；何时继续服从、何时主动决堤仍待实验；
- 在线自修改、会话级整理、睡眠巩固与长期规则变化可能是多个时间尺度，不能预先压成“只在睡眠改律”；
- 五行目前只是检查状态变化和制衡关系的候选语法；不能据此建立五种 context 类型、宣布关系完备或推出中心服务；
- 当下 observation 是否应以及怎样暂时挂起既有规则而不立即永久改写，是“火克金”暴露出的新问题，尚未成为既定机制；
- 历史重放能比较既有轨迹上的候选策略，却不能直接评估另一策略本会制造的反事实对话。

后续讨论若再次改变这些判断，应先在本文追加新的转折点和原话，再修改主提案中的凝练结论。这样“讨论来源”和“当前判断”各自只有一份权威，同时保留从前者到后者的可追踪关系。
