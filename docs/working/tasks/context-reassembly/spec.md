## 问题与交付

一次模型运行持续追加探索过程，材料需求改变后仍带着旧源码和搜索结果；当前自查入口无法直接区分首请求与调查后的请求；fork 拼接全部 assistant 文本作为成果；构造开出的分身未继承只读工具限制。画面解析还存在空结果被直接取 `[0]` 的独立错误。

本次交付：可核对的上下文概览；分身最终答复与轨迹入口；准备型分身的限制继承；可主动重组材料并在同一次计算内继续的 `reframe`；构造和主行动的实际接线。新机制使用已有 journal、view、run 和工具 binding。

材料可以被多次组合。目的未变但材料需求已变，也允许换段；情绪、关系和表达来路同样可以是必要材料。构造提供信息、提醒与洞察，由行动自主判断。第一版保持现有串行 wake 所有权，不增加全局任务调度、任务树或自动依赖失效图。

## 实施边界与顺序

独立先做：空解析修复、分身交付与权限、上下文概览。然后实现辅助运行换段，接入构造，最后接主行动。主行动接线属于本次验收范围；不能只因分身测试通过就省略。

本次不新增 `return_result`。自然结束的最后一条无工具调用 assistant 答复就是交付，出处可以写在正文；取消、失败、没有最终答复分别标明，不从中途文本猜出成功成果。

构造开场的固定材料保持原默认。此次赋予它观察、选区、委派和换段能力，不把 todo、目录、时间线一律折叠，也不改生产笔记、策略、self 或配置。整体缓存命中高低及哪个块值得改默认，留给上线后的实际账单与遗漏反馈。

## 上下文概览

扩展 `read_context`，兼容现有正文、分页和 match 用法，提供 `detail="outline"` 与 `request="first"|"latest"`。current 指向当前工具所属运行，包括 construct、fork、main；不会把子运行误认成主 wake。显式 ctx 的归档同样能查询。

概览返回当前段的 focus/goal、稳定 ctx、材料引用与来源、字符数、请求范围，以及服务端实际报告的 prompt/completion/cached usage。实际 token 与估算严格区分；cached 未报告不能当作零命中。first 是第一次实际发出的请求，不是不断增长的当前 view。

首请求边界覆盖系统头、工具声明、view 材料和末尾 hints。工具 schema 单列，不通过字符估算声称服务端每块 token。若记录位于供应商转换前，则明确是转换前请求构成；usage 仍来自供应商。概览不返回聊天或笔记正文，不另存一份完整请求文本；已有来源复用引用，临时提示只存组成与大小等必要元数据。

记录首请求与最近请求和相应 usage，范围标记随归档保存；旧归档无这些信息时返回“未记录”，不能从最终统计倒推。多段计算每段拥有自己的 first，整次调用可汇总各段费用/usage 以免只看到末段。

## 分身交付与限制

`agents.fork` 保持任务、ctx、结果的现有返回入口，正常结果只使用最后一条无工具调用的最终答复，不能再拼接流式 pieces 或把工具前自言自语当最终答复。最终答复为空要明确说明。结束于工具调用、取消或异常时给出相应状态与可读 ctx，不退回更早的旧答复。原始探索历史仍完整归档。

来自受限运行的 fork，材料访问与操作能力不能超出父限制。构造子计算可以继承召回、概览和继续委派的能力，不得通过默认 meta、显式工具选择、显式发言 grant、load/reload 或再次 fork 取得写笔记、执行代码和发言能力。控制接口按自身职责提供：fork 可 reframe，不可代父调用 construct__assemble。这些是现有工具暴露边界，不是宿主机安全沙箱。

普通行动的分身保留既有显式发言授权和工具行为。规则由真实调用者 binding 传递，不能根据提示正文声称自己是构造来判权。工具说明与实际可调用函数保持一致。

## reframe 的行为合同

接口使用现有 meta 工具入口，接受 `focus`、`refs`、`note`、`tools`，主行动再支持 `history`。缺省工具/历史选择继承当前设置，显式空工具集合才表示清空可选模块。模型主动使用，无硬长度或调用次数触发。

- focus 非空；说明下一段正在关注什么。保留原调用目的与来源入口，允许当前问题和方法随发现修订。
- refs 沿用已有日志、ctx、笔记与选区解析，按引用解析时固定内容版本。note 作为本次新产生的接续材料写入 journal。
- 校验失败作为原段中的工具错误返回，旧段继续；不清空材料、不提前结束整次计算。
- reframe 必须独占该次 assistant 工具批次。混用时在任何工具执行和主行动确认回调之前拒绝整批；原输出、逐个协议错误和完整配对仍记入 journal，不能执行其中副作用工具。
- 正常 reframe 在工具结果及批次完成记录落盘后换 ctx。新段带选定材料、当前 focus、原段入口及必要调用信息；不重装整份旧轨迹。
- 旧段保存后继/来源关联，新段保存来源与选择，原始条目不修改、不删除。普通 refs 展开仍能找到前段内容。
- 只有整次计算结束才返回调用者。fork 经多次换段后返回一次最终结果；构造经多次换段后只提交一份 assemble。

执行控制权属于整次调用，ctx 是其当前工作材料。新段重建 session、view 与局部工具状态，但取消信号、已有绝对截止时间、父调用等待和权限限制不能重置。不得递归叠加 Python 调用栈来实现无界换段。已经开始的工具即使后来取消，仍记录真实回执；没有回执保持未知，不自动重试外部操作。

换段的准备在原段仍可继续时完成，提交前再次检查取消/期限。提交后归档或落盘失败按已有失败语义终止，保留可定位的关联；不承诺多文件事务或崩溃后自动续跑。旧 summary 等不使用新能力的调用保持行为，显式传入旧持久 view 的使用者必须有明确支持或可读拒绝，不能悄悄替换它的所有者。

## 构造与主行动接线

构造白名单加入当前概览与 reframe。它的子计算继承准备职责；模型、effort、总 timeout、已收集的 specs 与取消均跨段延续。新段使用选定材料，不能通过每次 prepare 又灌回全量初始材料。原有超时 fallback、失败 fallback 和取消逻辑保留。

主行动仍属于同一个 wake：claims、deferred、associated_windows、interlocutors、取消与控制输出计数延续；不重新 `_adopt` 原召唤，不伪造新唤醒。只有整次行动完成才由原 reader 释放 claims、进入沉淀和处理外层 loop。

主行动每段仍运行现有 `_prepare`：同窗口新消息可插话，另窗召唤按现有规则暂存；新段的 request patches 按实际展示重算，不能复制旧 patches 确认未看材料。有效 reframe 输出沿用“这轮材料已经展示给模型”的确认语义，无效混合批次不确认。已读状态唯一权威不变，重新取草稿和运行提示，不把外部状态从选定 refs 重建。

history 只调整下一段接话范围，不改变负责窗口集合或取消范围。不因为换 ctx 提前触发 settle/loop/finally 或丢失本次输出统计。传给 prepare/on_output/after_round 的 state 始终指向当前 view。

## 空解析修复

`screen.event_for_record` 遇到 `parse_log` 返回空列表时，采用可识别的保守历史事件表达或跳过需要解析的派生属性；保留原记录身份、原文在原有显示路径中的可读性与原来有效消息的行为。不改源数据，不伪造发送者、消息号或唤醒。具体表达应沿用 screen 现有兜底语义，由合成空行/孤立缩进记录验证。

## 验证

每个 Python 切片执行 `uv run --frozen python run.py --check`；整体前后运行隔离 `--smoke`，比较模块数、required core 与可选失败。临时行为脚本放仓库外，不新增永久测试框架，不触碰真实运行数据，不调用真实模型或 QQ 接口。

验收至少覆盖：

- 首轮和后续输入不同，first 仍冻结；usage 正确关联请求；current 在 fork/construct/main 中不串线，旧归档有明确缺口。
- 多轮工具探索只交回最终答复；取消/异常/无最终答复不返回历史自言自语作为成功。
- 构造及嵌套 fork 的实际 schema 与分派均无写入/发言逃逸；普通 fork 原授权仍有效。
- 分身连续两次以上换段、父调用只返回一次；refs 只携带选择内容，旧轨迹可追溯；坏引用、混合工具批次无副作用。
- 换段不重置取消/总时限；取消后迟到回执仍记录，不启动下一段；归档失败不虚报成功。
- 构造换段后一份 assemble；主行动换段期间插话、read patches、claims 与最终 loop/settle 次数正确。
- 空解析记录不越界，正常消息/通知/撤回所需身份保持。

主代理沿固定基线审查每票差异，再核验完整调用路径。单票 done 不等于整个 spec 完成。交付区分已实现、隔离验证和真实使用效果；缓存价格或合成前缀比例不能代替总账，实际评估计入构造、行动、分身的全部费用、延迟、遗漏及补读。

## 不做与开放项

不增加 return_result、任务树、额外原子存储、自动缓存失效图、强制换段阈值、新的全局预算、自动重放副作用、生产笔记整理或全量材料默认折叠。现有 follow/mute/wait/loop 调度语义不变。

效果上的未知：模型何时主动换段更合适，新的材料选择是否遗漏关系线索，总费用是否增加。这些不能由接口测试证明，但不阻塞能力实施。运行中发现共享接口必须变化时先更新相关票的有效性，再修订 spec；不据此扩展成重做调度。
