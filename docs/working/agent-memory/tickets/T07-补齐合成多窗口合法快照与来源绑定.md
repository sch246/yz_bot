## 最小接口与输出

普通函数/字典即可：`open_snapshot(frozen_sources, schedule, cursor)`返回不可变快照描述；`resolve_ref(snapshot, reference)`返回精确原bytes/定位或拒绝；`bind_a0_view(snapshot, target_binding)`提供受限读取的作用域并在finally恢复。名字仅为此草案接口建议，非现有API。

共享输入标识为`source_alias`（fixture窗口/来源别名）、`event_key`（来源文件hash+字节区间+该别名）、`snapshot_id`和`opened_cursor`；message_id不是唯一来源键。内容源只有冻结原bytes，映射是投影。输出描述冻结来源hash/count、开放表hash、身份绑定摘要、可见记录/排除原因、投影映射、虚拟时间和格式能力；不得放真实身份或路径。

## 可观察验收

1. 两个虚构窗口在同日同秒、同message_id、同正文时仍能准确区分来源；同窗口重复ID不能静默任选一条。读取原文与来源字节区间/hash逐条一致。
2. 发生时间早但迟到的记录按开放序号控制；一次工具读取不推进历史。未开放窗口、目录、名字、around/origin/ID入口均看不到未来标记；开放后可读。
3. 原格式语义及原字节保留；不支持格式明确拒绝。相同正文换了原来源不能冒充同一事件；绑定到错误目标/Bot身份必须拒绝。
4. 通过现有A0档案入口真实调用核对范围/邻域/来源，而非只比较新函数自身输出。作用域退出及故障路径恢复全局绑定；禁止网络/QQ/外部写的哨兵在所测范围为0。
5. 路径/symlink/跨分支逃逸和来源/开放表漂移有拒绝证据。至少一个临时故障注入能证明检验会抓到漏窗口命名空间或未来泄漏。
