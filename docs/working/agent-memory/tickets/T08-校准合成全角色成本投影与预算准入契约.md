## 最小接口与输出

普通函数/字典即可：`project_costs(request_rows, lineage, budget_policy)`产出研究实际/保守结算、路径祖先成本、各阶段/角色消费与未知保留；`admit_request(projection, request_envelope)`返回允许/拒绝、所依据的账本切面摘要和各限额算式。它只判定该切面，过期判定不得作为实际发送授权；实际reserve原子化与HTTP接入仍未完成。

共享请求标识为供应商尝试级`request_id`，与`role_id/task_id/run_id/branch_id/parent_checkpoint_id`分开；实际重试是新request，不因同一逻辑任务合并。形成/探问/出题/核验标签各自归属，但全部占共同研究总额。lineage引用祖先请求集合，不能仅靠父segment名推断成本。快照票共享的`snapshot_id`仅作暴露关联，不成为新的计费身份。

## 可观察验收

1. 同一实际request被多个角色/分支引用只计一次研究支出，每条路径仍包含其祖先；兄弟新增分别计入。伪造相同request_id但envelope/usage冲突必须报错，不静默去重或任选低值。
2. prompt已含cache时cache只用于拆价，不再次加token；合法usage精确结算。缺usage保留完整预留，超报记录真实并闭锁，未知/poison/inflight不因换角色、fork或换segment清零。
3. 有限fixture预算证明S+I+R准入，形成与探问各自限额和共同总额同时生效；各分类单独未超但合计超额时拒绝。无价不得记0；测试价不是当前供应商报价。
4. 重复结算、乱序返回、未知祖先、环、缺账本切面和漂移明确拒绝；串行限制明确拒绝不支持的并发路径，不用纯投影声称并发原子性。
5. 准入报告绑定账本切面，状态改变后旧允许结果不得视为新状态许可。通过现有Ledger生成的纯合成真实行复算，不能仅构造与新函数同形的字典作唯一证明；至少一个故障注入检出祖先漏算/探问漏记。
