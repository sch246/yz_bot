## 行为与权威

- `current/{global/main,person/<stable-id>,group/<source-alias>}.md` 是当前内容唯一权威，首行 `<!-- stateless-note {JSON metadata} -->`，随后是精确保留的 UTF-8 Markdown body。所有消费者得到整份当前 Markdown bytes（含可读 metadata），CRLF、尾空格不改写。
- `versions/<content-version-id>.md` 为不可变完整版本；父版本和整文件 hash 构成历史，删除仍保留当前墓碑与删因/来源，普通读取不注入墓碑。恢复和回退基于当前父版本提交新版本，不重置历史或外部副作用。版本 hash 是完整 metadata（不含 version_id）+换行+body 的 hash；材料 sha256 是整份实际 .md bytes 的 hash，两者不同。
- `receipts/` 是不可变 applied 审计证据，用来识别维护者放回整份旧版 Markdown、删除 current 等情况。它不提供当前正文、不选择 fallback。current 缺失/损坏时不会从 versions/receipts 复活。
- `candidates/` 存单文件提案，含原始 body/hash、父版本/hash、scope/branch、T10 来源截止、理由、预期和带类型的 statement 来源。prepare/commit/rebaseline 共用 `_validate`；重算候选 checksum/id 不能绕过操作、范围、来源、complete terminal、generation、未来截止和恢复祖先检查。同文件任何条目竞争均按父版本冲突拒绝，不合并。
- 受控写入短持 `flock`，生成模型不占锁；不同 NoteWriter 争锁会拒绝。一个文件逐次完整临时写、flush/fsync、replace、目录 fsync；新版本证据先落稳，current 后替换，最后 applied receipt。无多文件原子快照保证。
- `register_trigger` 仅基于 T10 已提交 wake 幂等登记；首输出 ack 不等于终态。`admit_trigger` 从 `recover_commits` 取明确 terminal/cutoff/request IDs，再连接实际 HTTP request evidence 与 output context hash、T07 精确原文、已提交笔记版本、generated/execution/result。来源不靠脚本想象或当前目录扫描。
- 无变化/失败/预算未准入有明确 `finish_trigger` 状态和原因、尝试时间；registered_at 可计算年龄。调用方显式完成整个整理任务后调用 finish_trigger；单个候选提交不会自动宣称整份任务完成。没有调度线程或自动模型重试。
- 首片仅处理 complete terminal 候选。failed/cancelled 的实际 generated/not-dispatched/failed/unknown 事实仍可登记/绑定截止，任务明确记 not-admitted 及理由；不自动整理、重试请求或行动。这是已接受首片局限，不添加 allow_partial。

## T13 接线接口

普通函数与字典，不需要接入框架：

```python
writer = NoteWriter.create(fresh_external_root, branch='main')
# 已有 notes 根用 NoteWriter(root)，不会创建模型/请求。
task = writer.register_trigger(loop_root, wake_id, snapshot,
                               allowed_keys=('global/main', 'person/101'))
admitted = writer.admit_trigger(task['id'], loop_root, snapshot)
# 无 terminal 返回 pending，cutoff 尚未开放；complete 才能 prepare。
source_ids = list(admitted['cutoff']['exposures'])  # caller选择实际需要的来源
candidate_id = writer.prepare_candidate(task['id'], 'global/main', markdown_body_bytes,
    sources=source_ids, reason='明确修订原因', expectation='下次怎样不同')
result = writer.commit_candidate(candidate_id)
writer.finish_trigger(task['id'], 'success', '整个整理任务已完成的具体说明')
materials = snapshot_notes(root, next_snapshot, allowed_keys=('global/main',))
# materials 直接交 T10 drive_wake(..., materials=materials)，不重新口述/重读路径。
```

`prepare_candidate` 支持 operation=write/delete/restore/rollback，后两者显式给 restore_version 和相同旧 body bytes，仍需新来源/理由/当前父版本。statements 字段区分 observation/quote/inference/correction/draft/attempt/success/unknown；success 必须连接 completed execution。此结构约束不能证明自然语言语义正确。

六字段材料例（身份为纯合成）：`kind='note', source_id='person/101', version_id='<64hex>', snapshot_id='<T07>', sha256='<整份Markdown hash>', raw=b'<!-- stateless-note ... -->\n# body\r\n...'`。notes source_id 含斜杠，是其 scope/identity key；T11 opaque handle 限制不同，T13 必须显式映射 handle→授权 key，不能假定直接透传。个人 key 不随群/私聊/显示名改变；读取必须显式 allowed_keys，内部取到某人的材料不表示可向当前群公开。T07 只支持 ordinary-group，尚未验证私聊来源摄取或真实私聊效果。

`read_committed(root,key,snapshot,allowed_keys=...)` 和 `snapshot_notes` 共用相同 resolver，仅返回当前有效版本及不可变 bytes。已冻结 A 的材料对象在提交 B 后仍是 A；下一次新读取是 B。候选、墓碑、历史不默认注入。

## 手改与故障恢复边界

先调用 `pause_note(key,reason=...)` 暂停该文件，再让维护者编辑；保存后再次调用 pause_note 记录准确观察，得到 observed_sha256 与 expected_version。然后显式 `rebaseline(key, expected_observation=..., parent_version=expected_version, trigger_id=..., sources=..., reason=..., expectation=...)` 新增基线修订。未经暂停的手改一旦被观察，旧候选会拒绝、保存观察并暂停。重新基线仍要通过同一来源/范围/截止检查。元数据首行被删除时不会猜如何切分正文，需显式修复该首行后重新观察。

非合作编辑器在最后 hash check 与 replace 之间保存，仍可能被覆盖；doctor 已主动复现这条反例，不能声称任意并发安全。生产编辑器集成未实现。

如果 current replace 已成功，而 receipt 写入失败：

1. 本次 commit 返回 failed、writer.poisoned=true，保留 marker/.new/全部失败文件，不报告可靠成功。
2. 普通 read_committed/snapshot_notes 因 persistence-unknown 或残尾拒绝，重新构造 writer 也闭锁。即使 current 是完整 B，也不把它悄悄改回 A。
3. `recover_notes(root)` 是只读诊断：报告 current 的结构/父链/hash、`applied_audit_confirmed` 与 `audit_error`，同时独立报告 marker/residual/rejected。它可以说明 current 是完整 B、applied receipt 仍只确认 A，但不宣称 B 的持久性已经获证。候选/版本/实际请求证据仍可供人工复核。
4. 当前切片没有自动清 marker、补 receipt 或激活失败写者的 API。后续若要恢复可写，必须据 current 原件、immutable 版本、candidate/terminal/exposure 及 missing receipt 的证据设计明确修复；本次只读恢复不猜成功、不回退历史、不发模型或重放行动。物理断电/所有文件系统持久性未证明。

正常写入 current replace 到 receipt 完成之间，普通读取也可能短暂拒绝（当前完整但 applied 审计尚未确认），不会返回旧正文。每文件提交锁的写者串行性不等于多文件快照或任意编辑器 CAS。
