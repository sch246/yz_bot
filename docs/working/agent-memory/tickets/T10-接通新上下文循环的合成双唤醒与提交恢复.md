## 最小接口与状态

拟议入口 `run_synthetic_session(frozen_sources, schedule, wakes, budget_fixture, output, *, scenario="normal") -> report`；内部普通函数可采用 `build_screen`、`drive_wake`、`recover_commits`。名称可调整，语义如下：

- 画面带 snapshot_id、所选 event_key/来源引用、格式化正文、冻结分界和截断/近似新旧说明。发生时间排序、开放序号决定可见性，N 是 fixture 配置，不升级为硬契约。
- 每个 wake 带 ID、原因、窗口、开放游标；提交只确认实际画面覆盖的唤醒集合，不能现查末尾或吞掉冻结后新增激活。

- 限定引用工具仅从本次 snapshot 取完整原文。完整 master、未来 schedule/名字/目录不能进入请求。
- 每个实际 request_id 带 role/task/run/branch/parent/stage/snapshot 归属。两轮共用累计 Ledger 与共同预算，不增加第二份可写余额；归属/请求证据落盘失败在 mock 前闭锁。
- CLI 只接受内建合成 fixture/scenario 和新建外部输出根，拒绝已有根/并发；不接受 key、真实材料、任意 endpoint/transport 或付费模式。

## 提交和恢复边界

采用 D07 的待证候选：第一份完整模型输出成功持久化时，将画面 hash、冻结边界和对应唤醒确认置于同一可恢复提交，再执行工具。构造/请求/提交前失败不推进；输出提交后工具未派发或结果未持久化，恢复标未派发/未知，不自动重跑。恢复只重读已提交事实并重建状态，不自动请求、派发或恢复供应商会话。

边界小文件仅是可重建投影，不能成为第二权威。拒绝旧代次、损坏/残尾或不一致日志；持久性未知如实报告，不以两个缓存文件一致代替崩溃一致证明。每个工具前检查取消/共同失败域，结果落盘失败后阻止下一工具。全程不对外发送、不生成 QQ 回声。

## 验收与实际证据

1. 两唤醒不同 Chat/messages 对象；第二轮第一份实际 HTTP body 不含上一轮隐式 reasoning/native工具轮次，同轮下一请求保留正确配对。
2. 实际 SDK/parser 触发受限引用，工具返回与 T07 原 bytes 对应；下一 wire 含该结果。不能脚本直接拼好答案冒充执行。
3. 两窗口同秒、迟到、截断、同名不同人/重复ID、未来名字/目录/正文标记均有反例；所有可读路径遵守开放边界。近似分界不声称精确逐条已见。
4. 构造/请求/输出提交失败、输出已提交但工具前停止、工具结果提交失败：逐断点检查边界、对应唤醒确认和未派发/未知状态；冻结后新激活保留。
5. 只读恢复从成功提交重建，陈旧代次/损坏拒绝；恢复哨兵证明不请求或重跑工具。
6. 第二轮累计成本不重置；共同限额在 mock 前拒绝。缺/冲突/超报 usage、length、连接失败、取消及 reserve/settle 持久化失败不能释放未执行工具或换角色绕过停止。
7. 外部可丢弃脚本能检出至少一种故意错误：复用旧 messages、提交时现查末尾或跳过共同准入。不是只相信新模块自身报告。
8. 报告保存 manifest/schema/code/source/schedule hashes、实际 wire、请求/预留/结算/工具/提交顺序、停止原因、成本及哨兵覆盖；不保存跨次思考供后续消费。提供 commit SHA、命令/exit/hash、失败记录和限制。
