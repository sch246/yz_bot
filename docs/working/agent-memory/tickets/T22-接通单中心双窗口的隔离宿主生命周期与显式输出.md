复用同一commits链，增加有限宿主记录表达入站/激活、任期、取消命中、终止处置和释放；output/dispatch/result仍为原权威。pending由已提交激活减原output acknowledged及明确处置推导，owner由任期/释放投影；不另写pending文件、动作日志、确认表或账本。

本片是单进程、双合成窗口、有限已冻结材料池。投递方在运行时决定到达与激活时机，未来原文及尚未提交的激活不得进请求。复用合法snapshot开放，不改source identity；普通到达和激活分开，普通到达不自行续醒。未知实时bytes接入、原生产chatlog/oplog迁移和note lineage留后续；本片不接note writer。

同一个root的所有新宿主和既有driver日志读取/追加，共用一个串行化边界。日志提交成功后才可claim；检查pending与继续/释放须在同边界内完成。不得只锁新host记录而让原output并发追加。无需为本片增加跨机器或跨进程分布式锁；明确限制单进程，不宣称断电/重启自动恢复。

owner有不可复用任期身份，claim时固定origin；旧cancel/finally只能影响绑定任期，不能取消/删除后来owner。只有第一份完整output成功提交，才确认该次冻结并实际覆盖的激活。构造画面、claim和请求成功都不是确认；输出后新到达不混入旧ack。

## 具名say与正常结束

drive_wake增加显式可选host接点，具名say(text, final_call=True, target=...)走原execute：output先提交，再dispatch、执行、result。无host时工具与行为兼容。不要提供任意工具注册框架，也不要用world工具名冒充say。

target必须显式且属于两个合成目标，沿生产g<群号>/u<对端号>格式或等价的明确映射，不能回退到最近来源。假输出端区分确认成功、有据失败、未确认；message ID是确认成功的必要条件。无ID/超时不声明final；失败/未确认按实际回执保存，具体传输未知不自动重发。只有确认成功且实际调用final_call为true时，设置Chat原turn_done；不得借cancelled结束。

保持同批执行语义：正常final_call不会跳过同批剩余工具，整批结果先保存；取消/持久化失败可以阻止未执行工具。complete terminal保留旧“最后输出无tool_calls”分支，另支持狭窄final-call证据分支：引用同醒同Chat最后批中的具体say action，校验原参数、显式目标、已提交成功回执和message ID，且整批每个call都有终结结果。缺result、unknown、取消、错误action/目标或结果持久化失败均不能进入该分支。不能仅信done布尔值或伪造最后assistant。

## 取消、退出与收尾

保持取消/异常关闭原会话，不能重开closed Ledger、暗建新client或增加预算。取消命中本任期，明确处置它正在处理且尚未确认的冻结激活，避免同一激活热重启；未被该处置覆盖的新激活仍pending，包括取消附近到达者。正常完成可在同一健康会话继续pending；取消/异常之后本次会话停，新pending等待后续显式恢复，不在本片实现自动续跑。

只证明中心取消。关联窗口来自本任期实际接收/读取和发送尝试，用于取消路由，不能当成功发送统计。生产按用户的waiter与watchdog接口不在本片。旧任期回调无权触及新任期；取消后的pending如实可读即为证据，不能把未立即执行声称已处理。

每个owner真正退出只尝试一次fake结束通知，目标是它固定origin，不是最后say目标。收尾失败单独记录，不覆盖原异常、不触发模型或工具重放。usage取绑定owner的实际Mock请求结算；发送数/目的地取假端点确认效果并与action result核对。可报告清楚命名的实际曝光来源记录数，不把它冒名旧正式流event_count。旧hint表达式、正式流统计适配和供应商closing_hint不在本片，后者不决定宿主结束。

## 有区分力的验收

用确定性barrier/事件控制交错，不依靠随机sleep。复用原Chat、实际SDK Mock与共同客户端/预算契约，验证脚本放仓库外。一次只跑一个有限命令，专属venv，timeout60、RLIMIT_AS512MiB、记录当前VmHWM；保留失败原件，不重复无关历史矩阵。

1. 两窗口竞争claim，最大并发模型生成1；普通到达不启动模型。
2. 新激活在退出检查前、检查/释放交界、释放后分别到达，最终处理或明确pending；旧finally不删新任期。
3. output前失败不ack；output提交之后的新激活不被旧ack吞掉。
4. 取消在output前、首工具结果后分别发生：当前工作终止，后续工具停止，新激活仍pending；过期任期cancel不伤新owner。
5. origin A、say B确认成功并final：不额外请求空白final，同批结果齐全，结束通知只到A。
6. 无ID/超时/失败没有final-call证据；伪造action、错误target、遗漏批结果在恢复时拒绝。发送已成功但result落盘失败保持未知并闭锁，不自动重发。
7. 多醒同owner只收尾一次，无say的正文不发送；收尾失败不重放，发送数/曝光数/请求usage各自可核对。

交付commit、fixed diff、实际命令/结果/source hashes、有限案例与反例、保留边界；helper转review，不合主树。check必跑，默认driver/subject模式做一个适当回归；只有新风险才补smoke，若做只能既有temporary fake入口。root两轴审查、集成和资源清理后才done。不能据此宣称主体性、生产路由/统计、取消自动恢复、旧机制退役或D12全部完成。
