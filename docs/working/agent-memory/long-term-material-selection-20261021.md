# 长期选材：短起点、主动查阅与宿主资源边界

2026-10-21。接续 [D17](decisions/D17-重审主体持续性与自主选择的目标和实现方向.md)／[D18](decisions/D18-确定统一事件与文件记忆的首版职责边界.md)，复用 [T23](tickets/T23-完成中心闭环的隔离生产接线与联合验收.md)。这是研究结论及下一切片建议，没有实施。三个只读子代理分别补当前代码、Hindsight、meow／Cortico 的定向证据；主代理亲读相关设计与研究原文、核查关键代码及官方资料，另做一次 SQLite 内存库合成探针。未读生产材料、凭据，未调用实验模型或收费 API；不把本次 Codex 会话费用算作已核验的零费用。

## 当前建议

**先让同一主体从有界起点自行查阅旧经历，不引入独立选材模型或新记忆引擎。** 醒来提供她自己留下的当前短笔记、这次唤醒／重访的原因与身份、有限近期经历，以及可查询历史的入口。她决定继续查什么、修订什么、是否行动或静默；宿主不替她填兴趣、日程或每醒必做的总结。

当前唯一笔记 head 可先承担短起点，历史版本作为“当时的理解”按需查阅；这不是宣称单一短笔记已经解决长期知识组织。第一切片不必先改为多文件／七分类体系。若持续出现多个仍有效的主题互相挤占、频繁整篇覆盖冲突，再扩展可独立修订的条目，沿用同一提交入口与版本来源约束。它是对 D18 文件记忆方向的分步接入建议，不取消该方向。

常驻文本和目录都受实际字节／上下文额度约束；数量少不等于文本短。超出时明确告知范围，不能静默裁掉她的笔记。笔记提交超额应保留旧 head 并返回可理解的拒绝，让她自己调整。起点额度与近史选择是可调工程参数，不是人格规定；当前没有依据宣布某个固定条数最佳。

## 已有代码究竟缺什么

以下定位固定在 `f572071`，不是生产运行观测。

| 事实 | 对下一步的影响 |
|---|---|
| [Center._freeze](../../../mods/chat/center.py#L337)复制整个 journal，然后把全部 eligible arrival、output／results／重访／resume 放进模型；超限直接拒绝 | 当前没有长期发现／选择能力；不能仅在最后截短 messages |
| [record_event](../../../mods/chat/center.py#L222)已记窗口、origin、day、原文字节 hash | 可以先列候选身份，不先解码全文；第一版只覆盖已登记材料，不自行遍历旧聊天库 |
| [read_archive](../../../mods/chat/center.py#L484)只认先前 freeze 的 key | 现有工具主要供重读；缩小默认曝光后，还必须补“不知道 key 时怎样找”的入口 |
| [note_head](../../../mods/chat/center.py#L275)、[read_note](../../../mods/chat/center.py#L464)仅提供当前 head，[provider](../../../mods/chat/center.py#L519)按版本全文注入 | 历史笔记版本可查、当前版本标识、起点容量仍需接线；旧版不能冒充当前立场 |
| [实际请求观察](../../../mods/chat/center.py#L312)及[笔记提交](../../../mods/chat/center.py#L297)已接请求／来源／父版本校验 | 保留此入口，发现候选不能自动获得引用正文的资格 |

最小读路径是：**列出或搜索候选 → 按候选身份核验并读取正文 → 正文实际进入下一次请求 → 允许在此来源范围内提交修订。** 它仍由同一个 Chat 决定下一动作，没有每醒额外选择调用。

接口只需一处候选查询（可空关键词浏览，带过滤／cursor／额度）、一处按候选身份精读，以及现有 `read_note` 的可选历史版本读取；`commit_note` 继续是当前笔记的唯一修订入口。读取旧笔记不改变当前 head 或提交所见 parent，旧版作为历史来源标识，不能借反查绕过当前版本 CAS。

- 候选身份可用 `scope + journal event id`，附类型、窗口、日期／登记顺序、origin、hash；它不必等同正文 archive key。列目录不应为了构造 byte ref 扫描全日。
- 精读时才按 origin 定位原片段、核对登记 hash，并生成／复用固定 byte ref。原档不需换格式。[read_archive_bytes](../../../mods/chatlog.py#L1101)已有范围与 hash 检查；避免精读整日物化仍需小入口。
- 目录及搜索返回分页、受限摘录与覆盖范围。目录看过只证明元数据看过；摘录只证明相应片段曝光。不能把整条原文 source key 提前加入 `request.sources`。超大原件若不能完整放入，先明确返回过大；以后提供分段读取时，须记录真正读到的范围，不能用无标记截断冒充全文。
- 查询可按窗口、事件类型、登记范围、词面以及显式引用找材料；没有关键词也能分页浏览。事件发生时间、到达／提交顺序、笔记修改时间分开；能否在本醒读取以登记截止和实际版本为准，不能用旧日期让迟到材料穿越截止。
- 目录／索引是 journal 与原档的可重建投影，不成为第二个记忆写者。发现范围先限于该隔离根已登记的材料；未登记旧存量需要单独迁移，不用“搜索历史”悄悄扩大授权。
- 结果保留 `complete / partial / not_found / too_large / invalid_source` 的实际区别及续查位置；扫描预算耗尽不是不存在，原件被改不是普通漏召回。损坏来源沿已有闭锁处理，不回落到旧 reader。

第一版可用普通函数与现有工具注册接线。搜索、精读结果进已有工具结果／请求证据路径；不另建 selector session、向量服务、任务系统或权威摘要库。

## 两种容量必须分开解决

**有界上下文不等于有界宿主内存。** [Center 初始化](../../../mods/chat/center.py#L100)一次读完整 journal、splitlines 后解码常驻；历史 request 还保存当时完整 payload。[每醒](../../../mods/chat/center.py#L342)又深拷贝全部事件。[日档冻结](../../../mods/chatlog.py#L1008)整日读入，随后解码、建行／offset／记录列表。只选择最后几条送模型，上述开销仍然存在。这是源码可确定的增长路径；没有据此断言它就是此前 OOM 的现场原因。

下一资源切片应取消这两项隐含工作：每醒复制整个 journal；为少量原文精读构造整日列表。随后流式校验／恢复 journal，仅保留有限热状态，历史 payload 按位置读取；逐记录解码也必须限制单条大小，否则一条巨型 request 仍能制造峰值。

历史定位、当前 heads、未决重访／行动等查询可用磁盘派生索引承载，避免全量 Python 列表；它只由 journal 派生。可以先启动时流式校验并重建，不预先设计 checkpoint 协议。这样常驻内存可控，启动 I/O 仍随历史线性增长，**不宣称启动耗时也已恒定**。索引水位／完整性不满足时明确重建或拒绝服务，不能把旧索引的“没找到”当事实。未决项也不能为节省内存被静默删除或自动标完成。

完整请求证据先保留，不借优化删除历史；较短的新上下文会减轻未来写入，却不会消除既有 journal。磁盘保留、分段／checkpoint 与生产存量处理仍未裁定和实测，不把它们塞进第一张选材切片。若引入 SQLite，只作可重建定位投影；不是另外安装一套记忆产品。

### 一个会改变实现选择的中文反例

官方 [SQLite FTS5 tokenizer 说明](https://www.sqlite.org/fts5.html#tokenizers)表明，默认 unicode61 按连续 token 字符分词；trigram 使用三字符片段，少于三字符的 MATCH 不命中。它们都不是中文语义召回。

本轮以系统 Python 的 SQLite **3.45.1** 建两个 `:memory:` FTS5 表，分别 `tokenize='unicode61'`／`'trigram'`，仅插入合成文本“她想继续研究纸灯，后来改为研究木船。”，绑定参数查询得到：

| 查询 | unicode61 MATCH | trigram MATCH |
|---|---|---|
| 木船 | 0 | 0 |
| 研究木船 | 0 | 1 |
| 木制小舟 | 0 | 0 |

两表 `body LIKE '%木船%'` 都命中 1。这个小探针只证实该文本／版本的行为，没有测索引速度或中文召回率。结论是：**不要把默认 FTS5／BM25 当作已解决中文检索。** 第一版词面路径必须支持中文短子串和显式引用；受限流式扫描能作为起点，但不承诺全库扫描恒定成本。若以后加 trigram，也需处理短查询；LIKE 命中本身不证明走了索引。转述失败仍是单独缺口，不能靠改一个 tokenizer 宣告解决。

## 下一步只补会改变判断的证据

不恢复旧四臂，不建比较器或永久测试矩阵。后续隔离实施可沿一条实际路径补两段：先“有界起点→目录／搜索→精读→下一实际请求→有来源的修订”，再把同一路径的 journal 恢复和档案精读改为有界内存。对应删掉全历史默认灌入、全量深拷贝、精读时整日物化；不保留新旧自动回退双路径。

最小合成反例只检查三个尚未证明的地方：不知道旧 key 时能否找到并读到必要记录；只看目录时能否被阻止引用未读全文、失效旧版是否明确；无关历史扩大后上下文与宿主峰值分别怎样增长。检索结果及后续真实请求能证明发现／曝光接线，不能证明模型一定会主动查、正确使用或形成长期取舍。后者需另有行为和独立结果，当前仍未知。

若必要材料根本未保存或不可发现，先修取得；若已进入候选却被挤掉，修选择／预算；若已实际读到却未用，查消费与推理。只有中文转述或跨经历关联反复漏取，且同范围、同展示额度的定向证据支持另一检索器，才考虑 Hindsight／embedding 等。无需等规模很大，也不预先规定失败次数或新增长期审批门槛，复用 [D15](decisions/D15-界定预测与便宜选择研究的独立验证入口.md)的诊断区分即可。

本轮没有新的维护者价值选择。路线保持 D18；剩下的是可由隔离实施取得的机制／资源证据，不要求维护者代选她应在意什么，也不把本研究变成未来每次行为更新的通用前置。
