## 本轮研究答案：旧职责接管表与位置边界（2026-10-19）

D01/D03 已盘清当前消费者和方向效力，本轮复用；只对画面、取消/失败、工具状态与日志接口定向补证。没有启动或改动生产代码、读取运行数据、调用模型。下表是目标责任和后续证明要求，不是已实现或可删除证明。

### 1. 本轮新增维护者裁定

主代理提交了这个具体问题：最近 N 条之外未见消息、迟到旧消息与前置非连续引用，不能由每窗口一个位置精确表示。维护者实际选择：**“接受画面分界；不保证逐条准确标新旧（推荐）”。**

因此位置只表示上次画面的分界，允许漏标新旧；不增加逐条已见集合，不恢复旧 unread/正式阅读系统。构造画面、模型收到请求、产生输出、工具成功和理解内容仍是不同事实，不能用这个位置证明其中任何一个。未见但被截断的原文仍在档案，可按路径反查；画面说明截断/迟到/缺口的已知限制，不宣称“边界之前全看过”。这收窄了语义，没有推翻 N 默认、发生时间排序或前置跨窗口选择的已定方向。

具体反例保留作校准：

- 位置为 12:00，后来归档一条发生于 11:59 的消息，按发生时间会落到边界前。
- 两次唤醒间新增 N+1 条，最近 N 没装下最早那条，边界仍可能越过它。
- 前置只引用旧档 A、C，未引用中间 B；单位置不表示精确集合 `{A,C}`。
- 快照冻结后又入站一条消息；提交时若重新取当前末尾，将越过从未入画面的消息。这里的错误不能由“允许近似新旧”替写入越界开脱。

### 2. 画面与位置的最小候选协议

画面由普通读取/选择/格式函数生成，来源是已持久化 chatlog 普通日档和已支持的补回 sidecar。使用默认 N（80 只是现有参照值，不升格为本票硬契约）；跨窗口增补由前置引用。保留原记录头、正文、日期、窗口、来源位置及 CQ 原串；QQ 侧名字来自当时原档。v0 推导/猜测/缺失字段保持标记，不重写旧档。

发生时间决定展示排序，时区和同秒稳定次序显式冻结；同秒 tie-break 不能声称真实跨窗口因果。位置可用“最后画面记录的发生时间+稳定来源坐标”表达一个边界；它不是时间单值，也不是另一套消息身份。前置零散反查留引用轨迹，不据其最晚时间推进窗口主画面边界。

**候选提交点**：第一份完整模型输出成功持久化时，将本次实际画面快照引用/hash、每窗口冻结的边界与已递交唤醒确认关联在同一日志提交中。构造画面不提交；请求失败/取消在此前发生则不推进。输出可能没有工具或没有对外回复，也可提交；该点只表示产生了基于这份画面的输出，不能解释为理解成功。工具在这之后逐项派发，不等整轮工具全部成功才确认画面。

位置从该类持久事实恢复；若另有可读小文件/内存缓存，它只能是可重建投影，不再独立写一次形成第二权威。提交仅使用请求实际取出的快照边界，绝不现查末尾。候选首先依靠单中心约束排除两个可提交画面代次交错，恢复时也校验该约束；若以后允许交错，提交/投影必须核对画面代次或父状态并拒绝过期提交。日志先后只作审计，不能单靠“最后提交”防止旧快照倒退覆盖。

| 中断点 | 候选处理与明确限制 |
|---|---|
| 画面组装/请求发送前失败，或供应商失败而无完整输出 | 不推进位置，不确认对应唤醒；保留失败/未完成线索，不在进程里无界热重试。后续新唤醒/恢复可重看同一材料 |
| 输出提交前取消 | 可记录明确取消终止，停止本次；取消不应让相同唤醒无限重启。新到的唤醒不能被旧取消吞掉；终止与输出确认是不同记录 |
| 完整输出落盘后、工具前崩溃 | 边界/对应唤醒已确认，输出为计划，不自动重放工具；日志恢复时能指出未派发/未知状态 |
| 工具产生副作用后、结果落盘前崩溃 | 外部结果未知，不猜成功或失败、不自动重跑；日志闭锁和人工/明确恢复入口接管 |
| 回声晚到或迟到旧时间消息 | 仍由 chatlog 正常记录；可以落在分界前，标新旧不精确已被接受；不由位置阻止归档或把它判成已执行 |
| 快照后并发新激活 | 只确认输出实际覆盖的唤醒快照，新激活留下；结束检查与释放执行线须避免竞态 |

这里选择的是待实现验证的最小协议，不新增 exactly-once，也不承诺跨 chatlog/行动日志的分布式原子事务。D10 要逐断点验证；若不能用一条可恢复提交表达边界/确认，须先报告不足，不能靠两个文件各自成功假装崩溃一致。

### 4. 行动日志的最小信息与恢复边界

日档可读且可按文件定位，记录粒度至少区分：唤醒/快照来源、完整模型输出、调用顺序与原始参数、派发/完成事实、完整结果/异常、结果未知、取消/停止、当时可用工具版本、发生/接收/提交时间与关联身份。一个输出多工具不能被压成一行“成功”。子任务有父行动/角色；图片等大结果可引用已持久化的受限产物，但必须保留可定位的实际返回，而非只留美化标题。思考不跨唤醒保留。

模型输出持久成功后才允许副作用；每个工具前检查共享持久化失败与取消。外部副作用和本地记录之间不具原子性，未知状态必须诚实留下。恢复不自动执行已登记计划，也不以“没有结果”等同“没执行”。普通读文件可替代旧反查接口的查阅用途，但不会自动替代这些写前与失败保护。

旧日志查阅、旧结果桥、NapCat锚点与动态消费者均有本轮无法从源码证明的存量条件。保留这些欠缺不要求生产长期双套权威；后续切换须明确谁接管、何时满足删除条件。assign_tasks能否直接say的现有WHY?未由本票裁定，不借离线能力封闭修改生产权限选择。
