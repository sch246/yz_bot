### 2. 最小接口：普通函数与字典

以下是实验域内的职责接口，不要求新增类、统一事件框架或生产manager；可从现有脚本抽出小函数，仍使用原有lock/hash/checkpoint。模块/文件数应在实现时按实际耦合选择，本文不预设目录层级。

| 拟议接口 | 输入 → 输出与不变量 |
|---|---|
| `prepare_inputs(source_specs, parsing, schedule)` | 未来显式获准的输入清单/格式/时区/开放表 → 冻结原字节、解析事件、稳定来源定位和缺失统计。只读原输入；旧单窗口包可以显式标注v1能力，不能冒充新包 |
| `open_snapshot(branch, wake_id)` | 固定唤醒表 → 只含已开放完整记录的不可变快照、当前虚拟时刻、名字快照、唤醒原因。工具次数不推进历史；迟到旧时间按可用边界入内 |
| `resolve_ref(snapshot, reference)` | 当前合法快照+chatlog/行动/笔记/Skill引用 → 原文或事件副本、canonical来源/版本/hash，或显式拒绝。所有角色共用，同一请求拿固定bytes，不按路径再次读取新版本 |
| `drive_arm(arm, wake_snapshot, bindings)` | 臂声明+快照+隔离工具/模型/账本/日志普通函数 → 本次暴露、输出/工具轨迹、停止原因和新状态。A0调用原run_offline；A1–A3只在该边界内增量组合 |
| `reserve/settle(request_id, role, parent, request_or_usage)` | 单个供应商请求开始/结束 → token/费用/调用数的预留和实际或保守结算。每个子请求有唯一ID；父子/多角色共享预算，不能仅靠外层on_chunk累计 |
| `record_action / dispatch_guard` | 输出/参数/结果/唤醒确认与快照边界 → durable记录或持久化失败。每个副作用前查共享失败/取消；位置和确认沿D07候选提交点，不自动重跑未知工具 |
| `stage_revision / commit_revision` | 精确bytes/父版本/合法来源/修改理由 → 候选；再经父版本检查、旧版保留、逐文件提交后成为当前版本。冲突/失败留下候选，不改hint写入者，不自动激活Skill |
| `seal_checkpoint / probe_fork / submit_answer` | 已到达且已结算的状态 → 可复验checkpoint/独立探问；提交即终止，题目/gold/探问行动不写回形成轨迹。未到达时点不补造fork |

**合法视图的具体选择**：冻结master仅供控制器使用；臂可触达的archive/目录/读取函数只呈现已开放部分与本分支合法产物。A1–A3用受限文件引用接口，A0保留正式阅读流程，在离线作用域绑定其`chatlog.read_range/read_around/read_origin`等实际档案入口到同一视图；只改read_range(until)不足。时间截止依据开放快照，不是事件发生时间。不得将完整未来档案复制到可读root后靠模型自律。

来源身份沿冻结原档/sidecar记录位置保留；分支回声有独立来源命名空间。若可见文件拼接/追加使物理行号变化，必须有可重建的canonical来源↔可见位置映射，不能把副本新行号冒充原来源。读取必须既能返回准确原文，也能让A0原有origin/消息选择正常提交；D10用“候选回声插入后再读历史原文”验证此接缝。映射只是投影，不增加第二个原文写入权威。

**A0外层驱动**：隔离绑定只建立一次，按开放表将当前批次`arrive`到对应窗口、仅对规定外部信号activate，再调用run_offline；一次drive内部可有多次API请求。跨drive保留该臂storage/oplog/工具激活，不能每唤醒清零。离线`context.current`保持明确空值，唤醒来源走显式参数/事实；不能为了模拟来源事件意外使finally执行生产`_run_hint`的代码求值/发送（agent.py:114、133–138；chat/__init__.py:444–480）。窗口收尾需求以无执行能力的替身另校准，真实hook可用性仍是D07/D13的迁移证据。

**两个时钟**：模型可见“现在”及TTL/oplog日号/目录提示都由虚拟钟产生；真实请求起止/价格时段取计量钟。已发现接缝：oplog.py:397–399、759–764，tools/__init__.py:586、807、879、1009，chat/__init__.py:406，view.py:58。离线绑定要替换各模块使用的时钟引用并finally恢复，不能全局篡改共享time模块使真实计费时间也变成历史日期。普通事件时间格式化仍按冻结时区。D10检查实际provider报文与工具结果，而不只检查末尾时间文字。

### 3. 多角色、子任务和笔记的最小执行边界

所有角色（前置/聊天/图书管理员/assign_tasks子任务/独立judge）由实验调用入口显式接收冻结模型、受限registry、当前合法快照和按请求ID的回调。价目、参数、工具集按角色冻结；模型更换/预算停止/持久化失败向外传播，不能变成普通`ERROR`字符串后继续无限下一任务。普通任务失败可以保留原返回形状，二者区分。

不能直接开放生产`assign_tasks`：`mods/tools/agents.py:49`仍拿隔离后的全局client，所以请求**会经过**request_policy，并非完全绕过预算；但是`:50–52`没有传registry，默认回到生产default_registry，`:55–63`只收正文/写storage费用，没有实验on_chunk对账；`:76–77`线程也没有安装离线ContextVar。仅将max_workers设为1仍不修复这些问题。

最小候选为实验专用受限适配，显式传client/model/registry/允许模块/快照/parent与task ID/受限sink，逐子请求reserve/settle；保持任务去空行、独立任务、结果原顺序及普通失败项形状。首版可串行子任务，不声称时延等价；若需要并发，预留检查和写账必须有原子锁及每请求关联，再独立校准。原生产子代理能否直接say的WHY?不在这里代裁；离线若提供候选say，同样受目标范围/合成回声规则约束。

前置返回引用，harness兑现原文；图书管理员只读本轮暴露和结果，笔记写入有受限文件范围。D06内容对照使用`chat_i → librarian_i提交/失败 → 下一唤醒`；另一套合成调度表能强制晚提交/未完成/积压，下一聊天读当时旧版。不是先搭生产异步队列。Skill写入默认在D12练习分支开启，A0–A3形成主轨迹保持共同声明的Skill能力；不能在A3里顺便加一套自动策略更新。

受控笔记提交先保证上一版/候选/提交状态可恢复，再宣告当前版本；逐文件原子替换不等于全局事务。父版本冲突是可诊断拒绝，笔记写失败可留下旧版；行动证据落盘失败则闭锁所有后续副作用。新日志可复用现有PersistenceError类型及普通guard回调，但必须覆盖主调用/子任务/笔记提交，不假设llm里原oplog检查会自动感知另一个写者的失败。人工编辑仍沿D08协作条件，普通hash+replace不承诺保护不协作保存。

一次checkpoint有效需要：无在途供应商请求/未结算预留；已产生输出的工具批次符合完整或明确中止/未知状态；原文/日志/版本与引用可恢复；A0通过原有oplog settled规则，A1–A3通过新增行动与笔记恢复规则。未兑现阅读不伪造input；未提交笔记可作为明确待处理任务保存，不能记为活版本。未知外部结果可保留以查阅，但checkpoint恢复不得自动派发它；不能恢复的边界拒绝续跑并保留失败记录。

### 7. 费用估算：可复算上限，不编当前报价

本轮代码/文档研究的实验API调用为0，未取得新usage或当前价目。以下是D05取舍所需算式；具体模型指纹、最新价目、样本数、B1/B2、Q、重复次数、重试与总费用上限仍待真实选择，不在此虚填。

一次请求j在prompt已含cache的供应商口径下：

`C_j = ((P_j − H_j) × p_input,j + H_j × p_cached,j + O_j × p_output,j) / U`

P是总输入、H是其中缓存、O包括供应商计费的全部输出（含其口径内思考），U取价目单位；角色价/请求真实计量时段分别适用。额外缓存创建费等按实际供应商字段另计，不能盲套三项。复用`mods/llm/pricing.py:22–74`的拆缓存算术，但实验先验证价格存在/币种/单位，不沿缺值默认0；不执行来自生产配置的price_fn，用显式冻结的数字表/时段表即可。模型可见虚拟历史日期不决定真实服务计费时段。

设s个独立样本包、每包r次预注册重复、2个形成预算点、每条形成轨迹q道探问、各题新增token限额Q：

- 形成运行数 `N_form = 4 × 2 × s × r`；仅一包一次重复也有8条形成轨迹，不是4次API调用。
- 四臂全部角色合计形成token上限 `T_form ≤ 4sr(B1+B2)`；B已含前置/聊天/图书管理员/子任务，不能再漏记或给A3额外免费额度。
- 探问新增token上限 `T_probe ≤ 8srqQ`，按每题/Q口径；未到达题无fork但仍留分母，实际支出不预设所有题都成功。
- 若共盲判n份回答，每份judge/核验上限J，则另预留 `nJ`，自动出题、候选形成、D12控制/候选及未见复验、获准重试也分别预留。它们不藏在B内，更不在主轨迹预算耗尽后免费运行。

各角色先用“输入最大预留×相关输入类别/有效时段最高价 + 最大输出×相关输出类别/有效时段最高价”，再加缓存创建、固定请求费等所有额外计费项的可预留上界。只有冻结价表确认缓存输入价不高于普通输入价时，才能直接用无缓存输入价作上界；不能据高缓存旧记录直接折扣。若只知道合计token，统一币种/计价单位后，取所有冻结角色、输入/缓存/输出类别及有效时段的最高单价乘token总额/U，再加额外项目上界，得到更松的保守界。缺价或额外项目没有可预留上界时，不声称总费用有界；收费运行应拒绝，或另有经选择的独立硬费用守卫。

研究总账按唯一请求ID计实际/保守结算；路径成本另含祖先形成，不将复制来的既有笔记当免费，也不把同一祖先重复当真实支出。请求前的保守预留不保证供应商绝不超报；实际超报如实入账并停止后续请求，限制沿D06报告。

调用数按每唤醒的聊天请求数m_i、前置f_i、图书管理员l_i及子任务a_i拆算：A1为Σm，A2为Σ(m+f)，A3为Σ(m+f+l)，所有臂再加其a；“一次前置角色”可因受限工具读取产生多次供应商请求，故不能固定f=l=1。A0的实际m与读取/cover循环由校准测得，不能用提案“两三次”估计当实测。由请求上限和B共同限住，重试不重置。

历史依据仅用于解释保守性：旧6-call校准已有无usage预留/length，旧171-call样本已有高输入与缓存，linked检索改善仍增加形成/判分成本（回放记录对应运行段，D02已整理）。它们模型/reader/任务不同，不能外推新四臂每唤醒费率；文件MB不换算调用预算。完成无模型切片后，D05先选小预算真实A0校准的授权范围/上限，再以新usage填入算式决定是否扩大；本轮没有做这一步。

人工工作量亦分列：不要求通读档案或逐条标注；优先机械题/自动候选与独立核验，维护者只处理歧义和最终取舍。具体题量/人工投入仍由D05实际交流选择，不假定“人工免费”或将自动核验等同零费用。
