## 本轮研究答案：笔记读写、提交、消费与回退边界（2026-10-19）

本票复用 D04 的五类目标/行为证据和 D03 的效力整理，结合现有 hint/Skill 源码给出最小协议候选。它可供 D09 确定受限写入与校准范围；没有实施或实测，没有读取运行数据、调用模型。以下文件字段/并发机制是研究建议，不冒充维护者已裁定格式。

### 1. 已裁定、候选与当前事实

- 已裁定：每次唤醒结束触发图书管理员、可删改旧笔记、全局/个人（含私聊）/群三个范围，自定义名进入个人笔记。来源：[无状态目标](../../proposals/stateless-agent-loop.md) §6–7。
- Markdown、日期/来源、上一版/墓碑、异步不等待和逐文件原子替换是 §3.5 机制建议，仍需证明边界。研究协议采用它们作为最小候选，不把具体frontmatter或目录名定为永久契约。
- `edit_hint(text)`只允许中心reader整体替换待办；空串清空，不发QQ（meta.py:538–549）。全局hint通过`set_agent_hint`保存（chat/__init__.py:356–372）。
- Skill磁盘版本不等于当前运行版本：`SessionBinding.load`只激活last-good（tools/__init__.py:634–650）；reload从磁盘准备候选，成功才提交、失败留旧版（:658–685）。Markdown首行目录描述与正文分开，候选保存`source: bytes`（:221–239）；`state_snapshot.active`只hash正文（:939–953），不能冒充整文件hash。
- 当前离线safe registry只允许已有隔离Markdown的load/reload，未开放写入或Python/宿主能力（experiments/memory_replay.py:351–387）。其`is_file`前置也会挡住文件删除后的reload；不能直接声称删除/卸载闭环现成可用。

### 2. 责任与写入权威

| 载体 | 放什么/由谁受控写入 | 不由它承担 |
|---|---|---|
| 笔记 | 长期事实、人物/关系、可修订解释与经验；图书管理员提交，维护者可直接编辑 | 不复制可查询游标/计数，不作为原聊天和工具结果权威 |
| hint | 尚未兑现的决定、下一步与阻碍；聊天主体经edit_hint独写 | 不放长期事实/全量历史；图书管理员发现待办问题时只回有来源的建议，不成为第二写者 |
| Markdown Skill | 跨任务做法及适用/失效条件；首轮在独立实践分支形成受限候选，再精确加载复验 | 一次具体结论不自动升级Skill，不因此开放生产Python/任意文件修改 |
| chatlog/行动日志 | 原话、调用/结果及实际发生事实；沿D07各自的日志通道写 | 笔记删改/回退不删除或改写原文，不撤销世界已发生的事 |

笔记区分观察、原话、玩笑/推测、自我解释、未完成承诺和后来纠正。来源冲突先保留其条件与不同出处，不用“更流畅”的总结覆盖证据。低使用频率不是删除依据；删改理由应指向过时/更正/重复/无行为作用等可审阅事实，收益仍要后续验证。

全局/个人/群是归档和选取范围，不因跨窗口引用而自动获得读取授权。与人有关的私聊笔记不会仅因提到同一人自动成为对群可公开的事实；取得材料、用于内部推断和向目标窗口输出分开记证据，跨窗口错配/外泄列为行为失败。具体资料合法范围由后续授权冻结包决定，本轮无资料访问。

### 3. 读取与引用边界

前置只给情景说明和引用，harness从合法源取原文（无状态目标:87–94）；不能将前置总结包装成原文。最小引用必须足以确定：来源类型/窗口/日期/文件或行动位置、完整记录范围、允许的时间截止、冻结快照或可修改文件版本，以及实际取出文本的hash。字段名/旁置记录方式后续实现选择，不先立统一schema。

- 只读manifest内冻结输入及本分支已合法产生的文件；拒绝绝对路径/`..`/symlink逃逸、其它分支与未来材料。目录标题、备份、Skill和子任务读取也受同一边界。
- chatlog按完整记录返回头/正文/日期/窗口。消息号不单独当全局唯一身份；多人物/主题入口应定向找到同一原文，而非只有一个不可追的链接。`chatlog._file_records`和`search_current`保留这种分组/来源（chatlog.py:63–89），`_append`返回文件/头行定位（:146–167）。
- 追加日档可用冻结快照或记录范围hash验证旧引用，不因尾部加新行让旧来源全部失效。笔记/Skill是可修改文件，必须锁定版本/hash，不用同路径新内容冒充当时版本。
- 缺失/歧义/越界/坏hash/失效引用显式失败，不自动换最新版本、放宽截止或让前置补写正文。请求使用已取出的不可变bytes/text，渲染后不再按路径重读一次。
- 普通目录/自动注入只列当前有效版本；历史、墓碑、回退候选不默认重新注入。查旧证据是显式读取，不等于旧主张重新有效。

图书管理员接收这次实际暴露材料与完整行动/结果的引用，以及合法现有笔记；不因为文件在同一目录就读完整未来档案。生成时读到哪个版本、来源截至何时须可追。正常后来纠正开放后允许修订，probe gold与未见评测结果不回流；诊断使用过的案例标成已见。

### 4. 提交：一个受控写者与父版本检查

| 小机制 | 能解决 | 不能单独保证 |
|---|---|---|
| 原子替换 | 读者不见半写文件 | 旧候选不会覆盖新内容 |
| 一个受控提交写者 | 受控提交按序，减少重叠 | 人工改动、生成时读旧版本 |
| 父版本/hash检查 | 识别陈旧候选/错分支/已观察到的外部改动 | 任意编辑器并发下的文件系统CAS |

最小候选组合：一个受控提交写者、保存生成时基线、提交核对父版本/hash、逐文件原子替换。生成可与聊天并行，不持有文件锁等待模型。队列是普通待处理记录，不预建事务manager或多文件事务；本票没有不可分拆跨文件成功的已证需求。

候选先在隔离位置保存实际内容、父版本、产生原因、来源、预期变化与否定条件。提交时重读当前文件并在受控提交锁下核对父版本；不匹配则留候选、拒绝覆盖，重读后重新提出修订。同文件不同条目首版也视作冲突，不无证据自动三方合并。

通过校验后保留上一版，在同目录临时文件完整写入、flush/fsync、replace；实现须给出失败和重启后的恢复顺序。现有实验`_write_json`（:65–71）是可复用小机制实例，本身不提供多文件事务或断电目录持久性保证。若备份/审计记录未落稳，不能报告新版本已可靠提交；目录持久化与崩溃恢复在D10校准。每文件可见性明确，不承诺多文件同一瞬间的全局快照；首版避免“删旧文件+建新文件必须同时成功”的操作。

**人工编辑的保证有协作条件。** 任意编辑器不遵守锁时，hash检查与replace之间仍存在TOCTOU。直接文件编辑能力保留；若要承诺不覆盖手改，编辑期间须暂停该文件自动提交，或保存过程共用协作锁/入口。普通hash+replace不能声称保护不协作的任意保存。一旦观察到外部改动，保留候选并停止该文件自动提交、重读，不盲覆盖；若以后要求任意并发编辑且绝不丢改，须另研究，不暗加锁协议假装维护者已同意。

每唤醒产生可追踪触发，不要求无限并发调用。候选方案由单个图书管理员消费队列，记录来源范围、年龄、成功/失败/未处理，不静默丢触发、不自动扩大费用、不盲重试旧全文。重试上限/费用由D05裁定，D09定义受限实现范围。队列落后时下次聊天读已提交旧版，不等待未完成候选；未提交文本不进普通注入。已组装请求保持其版本，提交完成后下一次读取才看新版。D06参考串行回放仅测内容/成本，不能据它证明生产队列及时性。

### 5. 删除与回退

删除保存旧文和墓碑/删因/来源/父版本/取代关系，常规读取不再选它。后来确实又需要时，显式反查原证据，基于新需要提出恢复修订；不扫描备份无条件复活。需分别记录“删除后再次需要”“是否找回”“恢复是否正确”，不是以访问数自动判删对错。

回退是一次新的受控提交：从当前版本指向选定旧内容，保留被撤回版本、原因和证据，不抹指针历史。旧内容可能已被后来事实否定，不能将回退等同重新确认其真实性；仍须看适用范围/新证据。回退笔记不回退已发送消息、工具副作用、chatlog或其它后来事项。

Skill回退另有运行态步骤：恢复准确bytes → reload成功并核对last-good的source hash → 激活正确模块并核对下一请求实际正文。磁盘改回但registry仍是坏版，或reload失败继续旧last-good，均不是“回退已消费”。删除Skill时须同时说明目录、last-good、已激活会话与后续请求的语义；现有离线白名单的文件存在检查需要补受限路径，不能靠删除磁盘假装卸载。笔记/Skill回退候选不会自动进入生产或追加调用预算。

### 6. 精确消费与最小证据链

沿[回放实践反馈主线](../../proposals/memory-replay-evaluation.md)“实践反馈循环”和“方向订正”：真实失败形成候选 → 同初态控制/候选fork → 后续加载实际产物 → 行为变化 → 独立结果 → 保留/修订/回退 → 未见复验。禁止由脚本把候选重新口述成另一份prompt。

至少保留以下不同事实，不将它们合成“已学会”：

1. 实际产物bytes/hash/父版本及形成时合法输入、失败轨迹、预期/否定条件。
2. 是否只在目录中出现、被前置选中，harness读入哪个版本/哪些原文，实际进入哪次请求。
3. Skill磁盘source hash、registry last-good source hash、激活正文hash和请求中的实际投影；首行描述另记，正文hash不能代替整文件hash。
4. 是否正确引用/使用，行为是否改变，独立结果是否支持改善，以及实际形成+消费总成本。
5. 版本后来为何修订/撤回，未见案例是否再次消费；用错/没用/删后需要也保留。

正确引用仍可能扩写无依据细节；旧linked实验已有反例（memory-replay-evaluation.md:213–218）。调用减少不自动证明忠实性，任务改善不证明元层学会学习。无候选、错配候选、移除新候选、直接给合法来源等诊断，只在相应失败出现时按需增加，不变成每轮固定成本；一次随机消融不是确定因果。

### 7. 最小校准案例与未证边界

以下是后续D09/D10/D12的验收输入，本轮未执行：

| 案例 | 应观察到的区别 |
|---|---|
| v1=A，后来合法更正为v2=B，旧候选晚到 | 父版本不匹配拒绝；下次实际注入/回答使用B，不能只查磁盘 |
| 人工编辑与候选提交竞争 | 在暂停/协作锁条件下不覆盖手改；另保留不协作TOCTOU反例，不扩大保证 |
| 临时写/备份/fsync/replace前后失败、多个唤醒积压 | 旧版或完整新版、失败不冒充成功、触发来源不丢；重启可说明当前权威与待处理；不同文件部分成功显式 |
| 生成Skill v2只load，再reload+load | 仅load仍是v1；reload成功核对source后下一请求才是v2；坏v2留v1且记失败 |
| 删除低频条目后再次需要，及回退 | 默认不注入墓碑/备份；显式恢复有新修订；不逆转后来事实，Skill运行态也验证 |
| 两窗口同主题/错人、未来范围、坏hash、短原话扩写 | 错配/越界拒绝；合法来源多入口可定位；证据外具体化记失败 |
| 未选到/未注入/未用对、已见练习与未见复验 | 精确载体消费和行为/独立结果分开，题目和评分不回写，保留未见口径 |
