## 推荐实施范围：一条完整中心闭环，先不上线

候选范围是替换中心的数据与生命周期接线，在独立 worktree、临时 runtime、假 OneBot／假模型下证明：入档 → 唯一 arrival/activation → 冻结画面与前置选材 → 新上下文的同一中心 → 已提交输出 → 显式行动与结果 → 主动笔记或重访 → 下一醒准确消费。没有必须常驻的图书管理员，也不把每次 QQ 入站都当任务。

实现应复用已验证的小机制和当前 Chat、工具、权限、LLM/client 生命周期；实验脚手架不是待整体搬入的框架。生产接线不照搬 SyntheticHost 固定双群、未来材料池或只进程内假通知例外。目录、类和最终函数名由实际接点决定；此处先定责任和可观察行为。

这一轮代码交付只在隔离运行根生效。不得在当前工作树启动、切换 live 开关、接生产配置、读取旧运行存量、发送 QQ、重启或部署。旧代码与档案保留到逐项切换验收；单个运行根每项事实只启用一个权威写者，不以长期新旧双写作迁移策略。若不能做到，停止接线并交回差异。

## 维护者会看到的行为差异

新上下文不沿用整段旧 Chat 的偶然缓存；她通过冻结画面、前置选择和按需原文取用接续，笔记是可修订的理解。单窗口位置只表示上次画面分界，已接受它可能漏标新旧，不能宣传精确逐条已读。

主循环无需等轮末整理才记住；提交成功不等于已经消费新版，下一次实际读取／请求曝光另有证据。自身输出证明“当时这样想”，不证明外部世界真实。重访是她的选择，harness／时钟机会与实际兑现分开，不能把任何定时轮都写成她自发决定。

普通消息、控制消息、撤回、poke、回声和激活继续按各自判据处理。私聊展示对象与作者分开。`.py`、link、自重启、维护命令、tool last-good/TTL 和最终 #hint 都有具体旧责任，不由“新循环更简单”推定删除。

个人资料有业务键和展示称呼；tracked 源码只有 `identity.setname`／动态导出，未找到 `.setname` 命令注册。实际入口可能动态提供，本轮未读。建议原资料继续服务其已有消费者，转入 note 时只作为有来源的候选，不把整份 users dict 变成她认可的观点。`#limit/#reset_start` 及实际 `.setname` 兼容形式留到明确调用路径后决定，当前不给生产承诺。详见[资料、later、reboot 补证](/root/work/agent-memory-active-continuation-20261020/production-memory-resume-facts.md)。

## 迁移顺序：将来获精确授权后才执行

1. **冻结切换点。** 先在 fake 中证明 ingress 暂停、在途请求／工具状态可识别，未知动作不重放，维护路径仍可用。真实停止、队列暂存及 NapCat 补回界限另行批准；不能假定暂停期间没有消息。
2. **封存原件和运行依据。** 到时限定窗口／时间／状态文件，记录部署 commit、schema、旧 pending/source/page、TTL、hint、later/reboot 接续状态及 hash。备份原件只读留存；备份不自动授权复制凭据或其他聊天。
3. **严格只读预检。** 优先在获准的隔离副本上操作，生产原件只用无副作用方法；不得直接调用会建索引／修原档的现 reader。核对格式、边界、原件可反查、动态 API 消费者与旧未完成状态。无法证明冻结一致性或遇未支持格式／残尾，停止并报告，不顺手修复。
4. **离线转换并审阅。** 原 chatlog 不改写。生成新 journal/note 只使用明示迁移规则，逐项映射旧未完成责任。没有已见证据就不制造“她读过／做过”的经历；对不上来源、旧工具未知、旧 pending 是否激活不清、故障门不一致则拒绝，不猜成 complete。
5. **一个版本接管。** 审阅转换结果后才有未来启动候选，按既有完整进程重启边界切换，不热换中心代码。每项中心事实只有一条可写权威；旧 oplog 留档可读。补回锚、冻结边界、孤儿 page/pending、gap 和重试责任有接手者后，才能停旧发布；不可半迁移双确认。
6. **先观察再扩大。** 观察选材／版本曝光、激活确认、显式目标、回声、usage/unknown、持久重访和维护出口。失配停止新模型与行动派发，保留状态，进入下面的回退决策；不靠后台自动修坏日志。真实观察、费用上限和结束条件在上线候选中另给。

普通 `_append` 当前只有 flush，sidecar 补回则 fsync 文件和目录；“入档先于发布”不是跨档原子事务，也不是两路一致的断电保证。实施必须显式保留或补足这项承诺，不能靠修改文档抬高现有保证。

## 回退边界

| 发生时点 | 允许恢复的部分 | 必须留下的事实与限制 |
|---|---|---|
| 尚未启动新中心，没有新写入／请求／效果 | 放弃未激活的新生成物，继续原单版本 | 保留预检、拒绝原因、转换 manifest；不删原档或覆盖旧状态 |
| 新中心已有接收、笔记、请求或结算，尚无外界效果 | 停止新派发并封存新 journal/note/预算，再按可证明的旧基线重建候选 | 新入档、新理解、usage 和未知不能丢掉；旧中心回到旧水位可能重读，必须标明，不能称无损回滚 |
| QQ／命令／文件等已生效，或效果未知 | 先停止进一步行动；保留 dispatch、原始结果和 actual/unknown，逐项人工对账后才定恢复范围 | 还原备份不撤回外界效果。结果落盘失败也不能重试；旧中心若无法理解新状态，不直接恢复自动运行 |
| journal／原件损坏或来源不匹配 | agent mail 闭锁，保留 `.py/.reboot` 等维护入口的既有可用策略 | 新预检／中心失败处理不自动截断修复、不重算为成功、不抹未知；另行审阅修复步骤。现有 sidecar 的明确残尾隔离机制另有职责，不能借本表悄悄删除，也不因此取得预检时修生产档的许可 |

笔记回退应产生可追新版本并保留历史，不是覆盖原文件；首版原生回退／删除／祖先读取工具尚未接通，不能将它们列为已经可用。上线前至少需离线证明如何保全切换后新事实及重建一个可审阅状态；不能以“git revert”充当数据与外界效果回退。

## 实施划分与有限验收

若维护者批准上述生产模块隔离改动，先形成明确验收的实施 spec／T票；当前不创建 ready 票或绕过 D14 前置。生产切换与删除的否定结论仍有效。初步按三个所有权切片安排，最终以接口和完整源码阅读后定：

- 来源适配：原件 bytes/稳定引用/可见截止、archive 前置与启动补回接点；只使用合成公开格式，不读取真实库存。
- 中心闭环：owner/pending/冻结/Chat/显式 output-result、note gateway 与下一醒读取，联合取消及故障门；保留工具、权限和动态名字。该切片依赖来源接口，不能并造第二条中心循环。
- 重访与恢复：同 journal 下持久请求、scheduler 投影和 reboot/维护兼容；只对 fake supervisor/OneBot 验证，先与中心接口对齐。

可先并行核对来源与重访接口，中心所有权由一个 worker 持有；主代理整合并统一验证，不多代理同时改 Chat/loop。证据脚本放仓库外，不新增默认永久测试套件。先有改动前 check/smoke 基线，改动后按仓库要求 check 和隔离 smoke，对实际改变的责任写有限故障／差异探针；不重跑全部研究。每项结果绑定 commit、实际命令、资源、退出码和原件，失败原样保留。所有 WHY 约束逐项保留；包括子代理直接 say 在内的 WHY? 不由本包代答，确需改变才交维护者裁定。

首版联合验收至少覆盖：两个窗口竞争与取消／退出交界，真实过滤判据与回声归档，一次输出确认的准确冻结范围，say 目标与整批 final，主动 note 的父版本和来源 cutoff／同醒及后醒 wire，持久重访的一次实际投递，旧自重启／人工重启差异，TTL/hint/维护动态入口，以及归档／journal／结果失败的闭锁与未知。生产 formats 若无法全支持，必须把拒绝范围写进切换前置，不能让未验证格式默默经过。

工程验收不能代替她是否愿意记、怎样修正理解的行为答案。验收通过仅说明这个实现范围可审阅；不会自动获得实际材料、上线、100M 生产使用或旧数据删除权限。
