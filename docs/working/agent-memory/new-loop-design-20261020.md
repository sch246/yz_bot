问题是：怎样以最少的新机制把近期连续感、相关经验、纠正与回退连成可运行的新循环。下面是建议的实现起点，尚无新循环语义效果或“最佳方案”实测。

## 建议起点

沿用[已定方向](../proposals/stateless-agent-loop.md)和 D01–D04、D07–D09：一个聊天主体，每次唤醒重新组装上下文；前置用便宜模型找额外引用；聊天结束触发图书管理员修订文件。三个角色的跨次状态由普通文件承载，同次工具轮次仍保留供应商要求的原生配对，不跨次保存思考。

```text
冻结本次可见材料与已提交版本
  → 当前窗口最近画面直接进入上下文
  → 前置读取短目录，给情景说明和额外引用
  → harness取出引用的准确原文/笔记版本
  → 新建聊天上下文，执行本轮工具
  → 先持久化完整输出，再逐项行动和记录结果
  → 图书管理员提出修订候选，受控提交后供后续唤醒选取
```

### 上下文先解决“刚才发生了什么”

- 被唤醒窗口最近 N 条是默认材料，不交给前置决定是否保留。包含自己的实际发言、日期、窗口、原作者与稳定来源；N 可配置，80 只是参照值。
- 每窗口一个位置只表示上次画面的分界；接受截断、迟到和不连续引用导致的新旧漏标。原文仍能反查，不恢复精确 unread/正式阅读系统。来源：[D07](decisions/D07-确定画面-位置与行动日志如何接管旧职责.md)。
- 相关个人、当前群、全局的短笔记和待办分别选入；前置负责“除此之外还需看什么”。返回引用由 harness 取原文，避免为选材料再生成同量摘要。
- 最近画面、笔记概要、额外引用分别限制注入量，另有最终请求整体上界。缩减注入或推迟整理不删除原聊天；稳定指令在前，易变材料和当前时间在后。
- 先用人物/窗口/时间/已有目录定向查找。只有失败案例表明这些入口不足，再研究更复杂的检索；不预建向量库、图数据库或记忆 manager。

### 笔记解决“下次应该怎样不同”

- 个人笔记跟随稳定身份，覆盖私聊；群笔记保留群情境，全局笔记只放跨场景内容。显示名不当身份，多人批次的事实分别归原作者，不能归给最后一个发言者。
- 笔记放有来源、可修订的事实与经验；未完成事项仍由聊天主体写 hint，可复用做法才成为受限 Skill 候选。图书管理员没有第二份 hint 写权限。
- 优先处理明确纠正、失败与返工，再看值得保留的一般信息。精确重复可以幂等去重；语义冲突须保留来源/条件并提出修订，不能用 FIFO 或字符串不相等自动裁定真伪。
- 图书管理员读本次实际暴露和发生的材料，生成候选；提交由 harness 核对范围、父版本和来源，保留上一版、删除原因及墓碑。新版本只影响之后的读取；已经发出的请求继续使用取出的旧 bytes。
- 已定为每唤醒触发；候选机制采用单受控提交写者。下一轮不等未完成整理，只读已提交旧版，记录积压；旧父版本候选拒绝覆盖新版。人工不协作保存的 TOCTOU 限制沿 D08 保留。
- 回退是新的受控修订，不能复活已被后来证据否定的主张，也不撤销消息或工具副作用。来源与精确消费要求沿 [D08](decisions/D08-确定笔记修订与经验消费的最小边界.md)。

### 行动事实与笔记各守一份权威

生成文本、派发尝试、实际结果/回声分开记录。草稿、干跑或发送失败不能被后续整理写成“已经说过”。完整输出持久化时，将本次冻结画面 hash、边界和对应唤醒确认关联提交；不现查末尾。提交前失败不推进，提交后缺结果标未派发/未知，不自动重放工具。恢复依据成功提交事实，边界小文件只能是可重建投影；具体断点沿 D07 校准。

## 下一步按完整行为切片

第一片是纯合成双唤醒：两个窗口、固定开放表、每次新建 Chat、近期画面与受限原文引用、实际 SDK/parser/假 HTTP、共同预算、完整输出提交和只读恢复。第二次请求实际 wire 中必须没有上次隐式 messages/reasoning；同次工具配对仍正确。恢复不自动发请求或重跑未知动作。前置与图书管理员的真实模型输出留后续切片，不能把 fixture 充当角色收益。

复用 T07 的 freeze/open/resolve 与 T08 的共同准入；不扩展 T07 的 A0 只读绑定，不再补 A0 arrive/activate/take/正式阅读公平性接线。原 Ledger 仍是持久预留/结算权威；所有新角色最终请求都须受同一守卫。T08 的 `allowed` 不是 HTTP 许可，发送方须在串行边界取新鲜完整切面并持久预留。

主干接口稳定后可并行交整票：一条负责前置短目录/精确引用及请求消费，另一条负责图书管理员候选/版本/更正和下一次消费；不让两 worker 同改主循环或共管提交状态。worker 负责票内实现和孙代理核验，主代理审查跨票接口、集成和地图。

### 用具体案例检验新方案

| 合成案例 | 必须观察的行为 |
|---|---|
| 当前窗口刚纠正事实，其它群有相似话题 | 当前画面确实进入请求；额外引用不挤掉关键纠正 |
| 同人在私聊/两群出现，另有同名不同人；多人批次 | 个人身份一致、来源作者不混，输出遵守目标窗口范围 |
| 生成回复后干跑或发送失败 | 记录生成/尝试/结果差别，笔记不写成已发成功 |
| A被更正为B，旧候选晚到 | 拒绝旧父版本；下一次实际请求加载并使用B |
| 低频重要事实被省略，后来再次需要 | 原文可反查；遗漏注入不等于原文已删；恢复有新修订和原因 |
| 预算不足、缺usage、取消和提交/结果写失败 | 后续请求/工具闭锁，累计成本不重置；恢复不重放未知副作用 |

继续区分“没选到 / 没注入 / 用错 / 事实本来未知”。只有具体失败需要时，再对新候选做小范围机制诊断，例如直接给同一合法证据或移除错配笔记；不恢复旧新四臂和固定两预算点作为推进门槛。

新候选的实际行为验收由 [D12](decisions/D12-经验能否在后续实际消费并可逆修订.md) 接管，范围同时包括未经笔记修订的近期连续感/前置选材，以及形成经验后的消费与纠正。至少核查近期纠正能否正确接续、额外引用是否相关且没有无据扩写、人物/来源/目标窗口是否一致，并计入实际形成与消费总成本。T10 的假传输断言不能代替这些实际模型证据。小范围诊断用具体运行单冻结输入、预期、失败与子预算；不再等待旧四臂非劣容差或B1/B2/Q。D05保留正式规模及维护者最终成本/人工接受取舍。

尚无证据确定最佳 N、笔记注入份额、前置选择质量、图书管理员及时性或完整费用。先从合成主干与真实请求消费证据收敛；实际模型小试按既有授权和可信预留逐阶段准入，不把100M总额度当运行参数。未发现本次设计研究必须由维护者再选的事项。
