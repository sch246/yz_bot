## 3. 5元如何预留和结算

建议采用“目标模型上下文容量粗预留”，放弃用JSON字节数冒充真token上界。它仍有条件：未来须核实目标模型适用容量、当时价格和失败计费范围，并将来源、时点及适用性写入清单；当前公开`/models`示例不是已查询的真实模型元数据。

按2026-10-19[官方容量文档](https://api-docs.deepseek.com/api/list-models/)的1048576示例、[人民币高峰价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)输入未命中2元/百万、输出8元/百万，条件预留为：

`R = (1048576 × 2 + 4096 × 8) / 1000000 = 2.12992元 = 2,129,920微元/请求`

容量本含输入加输出，二者分别取最大是有意多预留；不靠缓存命中或空闲折扣凑出额度。若目标适用容量/价目改变，重新出具清单和算式，不能在运行中静默换政策。18万输入、12次合计4.713216元的旧候选因缺完整输入上界证明，不作为本次真实守卫。

1. 最终序列化HTTP body核对model、参数和能力后，先把请求ID、完整请求hash及预留持久落账，再允许一次HTTP尝试；持久化失败不得发送。
2. 只有`已结算费用 + 未结算预留 + 新预留 <= 5,000,000微元`且其他限额允许才发出。余额不够就停，不临时缩输出或提高费用。
3. 原始usage须先于既有parser异常被保存。合法usage按冻结规则结算并释放差额：prompt已含cache，缓存别名只算一次，reasoning属于completion，不重复加总。逐请求向上取整，以整数微元记账；计费时点取真实请求时间，不能套用2023年虚拟钟。若仍统一按高峰价折算，则明确标为保守费用，与供应商实付账单分列。
4. 正常且结算落盘成功后，才释放工具批次。错误、length、断流或取消即停止：有合法usage则据其结算，缺失/非法/矛盾usage保留全额预留并记录原因。usage超报记实际并闭锁；账本持久化失败保留未知在途及失败标记，不能重置后继续。
5. 两份满额预留为4.25984元，第三份需6.38976元，会被余额拒绝；成功结算释放差额后仍可能继续至12次，**不是固定只能请求两次**。

[错误码文档](https://api-docs.deepseek.com/quick_start/error_codes/)尚未给出超context等失败请求全部免费的承诺。这套应用预留只能在声明的供应商契约条件下约束发出请求，不能保证供应商账单绝不超报。一般失败请求的计费证据不足要继续核实，并在未来具体运行清单中披露；不能据此新增“必须有供应商绝对费用硬顶”的前置选择。已知额外收费项目若缺价或没有可预留上界，则拒绝启动；不把未知项目默认记零。
