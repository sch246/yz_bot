## 当前图的形状

主入口是列表第一个节点。大多数节点通过单个 `fail` 后继连成一条长优先链：条件未命中时继续下一个，命中时执行动作并停止沿主失败链前进。少数节点使用 `succ` 分支或额外 `while` 反向连接。

默认节点按倒序优先插入：新增无 `while` 节点会成为新入口，并把原入口接到自己的 `fail`。这使刚添加的反应立刻覆盖旧模式，符合在线调试和现场修改的需要。分支机制当前几乎不用，实际理解和维护重点应放在线性失败链上。

这解释了系统“灵活但容易被切断”的特征：一个过宽条件只要返回真，排在它后面的反应就不会再检查。普通文件命令在进入 link 前执行，是重要的恢复保障；`.link catch` 则用于查看一条模拟文本会通过哪些节点、终结在哪里。catch 仍会真实执行 cond，尤其 `py cond` 可能产生副作用，所以它不是纯 dry-run。

当前存在两个名称不同的“好耶”反应、一个测试成功分支，以及经纬节点的多失败分支；维护时不能假设图永远是纯单链。
